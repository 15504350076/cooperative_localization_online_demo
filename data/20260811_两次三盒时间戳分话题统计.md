# 两次三盒复测时间戳：按话题分开统计

统计对象：`three_boxes_20260811_054640`、`three_boxes_20260811_060745`。本表整理自已完成的SQLite写入顺序逐帧复核，并与各盒`联合时间详细统计.csv`交叉核对。54个数据流计数、消息回退数、记录回退数一致。原始包和算法均未修改。

## 1. 统计口径

- **车载IMU**是`/imu/raw`，**Livox内置IMU**是`/livox/imu`，**Livox点云**是`/livox/lidar`；三者分别统计，不能把车载IMU问题算到Livox，也不能把雷达内置IMU的问题算到点云头时间上。
- **消息时间**是消息内的`header.stamp`；**记录时间**是rosbag保存的接收/记录时间。两类回退分别列出，不混用。
- 相邻间隔按原始数据库写入顺序计算，不先按时间排序；UWB按`src_id→target_id`的六条有向流分别差分，不对六方向交织的整个话题直接差分。
- 下表时间单位均为**毫秒**；负的最小间隔表示回退。最大正间隔表示时间轴上的间断，不能仅凭它判断物理停采或丢包根因。
- 两轮全部54个数据流的消息零时间戳、消息重复时间戳、记录重复时间戳均为0。UWB跨方向允许相同时间，不能算成同方向重复。
- 车载IMU正常标称间隔约1毫秒；`/livox/imu`约5毫秒；`/livox/lidar`及单方向UWB约100毫秒。不能把所有传感器的“超过100毫秒”一律称为大跳，例如点云100.32毫秒只是常见帧间隔。

## 6. 如何复核、打开哪些文件

在工程根目录加载ROS环境后执行；编号只出现在循环首行，后续自动复用：

```bash
source /opt/ros/humble/setup.bash
source install/ros2-uwb-online/setup.bash
for RUN in data/three_boxes_20260811_{054640,060745}; do
  bash tools/analyze_box_sensors.sh "$RUN"/uwb_imu_livox_v20[123]_*/ || break
done
python3 -B data/复核三盒复测_20260811.py
```

- [分话题全量统计CSV](20260811_两次三盒时间戳分话题统计.csv)：筛选“轮次”“录包盒号”“数据流”，查看消息/记录两组回退、重复、间隔极值；包含54行独立数据流。
- 每轮根目录`时间连续性复核.csv`：`/imu/raw`、`/livox/imu`、`/livox/lidar`和UWB六方向分别一行，提供间隔极值。
- 每盒`联合时间详细统计.csv`：同样三个传感器分开列出，用于核对零时间戳、重复、回退及原始首末时间。
- 每盒`雷达分析.txt`：明确分成`[/livox/lidar]`和`[/livox/imu]`两段，各自看“消息时间”和“记录时间”；“逐点timestamp”只属于点云。
- 每轮`三盒IMU异常明细.csv`：只针对车载`/imu/raw`，查看前后帧号、原始消息时间和记录时间；不包含Livox内置IMU的姿态突变统计。
- 每轮`点云帧内时间跨度异常.csv`：只针对`/livox/lidar`的逐点字段，按盒号、帧号查长跨度点云。
- 主分析及原始证据图见[两次三盒复测对比](20260811_两次三盒复测对比.md)。

本表是对已完成逐帧统计的重新分话题整理；复核命令可重建基础统计文件。没有先校时、重排时间、删异常帧或把录包时间覆盖进消息头。
