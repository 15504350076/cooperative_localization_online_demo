# 报告编制与对外表述要求（持续记录）

本文档记录报告编写、数据说明、图表组织和对外表述的长期要求。后续编写阶段报告、测试报告、方案说明和甲方汇报材料时，先阅读本文档；新增意见按日期追加，不覆盖已有记录。

## 一、总原则

1. 对外正文只写已经完成并有证据支撑的工作。未验证的功能不写成已有能力，也不为了显得完整而主动罗列未完成项、失败项或可能暴露短板的内容。
2. 每一句结论都应让没有参与项目的读者能够独立理解。涉及数据、算法、传感器或测试时，正文应同时交代对象、场景、数量、结果和证据位置。
3. 报告主体使用中立的第三人称和项目主体口吻，使用“本项目”“本系统”“本次试验”等表述，不以命令或要求甲方的语气写作。优先使用“需要”“采用”“形成”“完成”，少用“必须”“不能”“不代表”“尚未”等反面句式。
4. 文字要直接、朴实、专业，避免人工智能生成感、口号式总结、过度包装、反复免责声明和形式化的“工程边界”。已经完成的工作应通过数据、图、表和结果呈现出来。

## 二、术语和首次出现规则

1. 第一次出现专业缩写时，先写中文名称，再写英文全称和缩写。例如：

   `相对变换估计（Relative Transformation Estimation，RTE）`

   后文可直接使用“RTE”。

2. `Header` 第一次出现时写成“消息头时间戳（Header timestamp）”或“消息头（Header）”，说明它是传感器消息自身携带的测量时间，不是录包接收时间。
3. 其他缩写、话题名、坐标系名和状态码也遵循同样规则：先给中文含义，再给原文或代码名称。
4. “接口契约”“使用门槛”等直译、生硬的词语不作为章节标题。根据实际内容使用“接口约定”“消息字段与状态说明”“状态更新与时效说明”“数据接入说明”等专业、自然的中文名称。

## 三、实测、仿真和数据证据

1. 实测和仿真必须分开写、分开列图、分开列表。标题和表头直接标明“实测”或“仿真”，不能用“合成试验”等含义不清的说法代替。
2. 实测数据要写清采集对象、场次、盒号、传感器、静止或运动状态、数据量和可用于的后续试验。仿真数据要写清仿真模型、是否带真值、噪声设置、随机种子和评价指标。
3. 例如“完成6组实测审查”后，至少列出场次、数据包、各传感器帧数、时间范围、统计结果和对应表格或文件路径，不能只给一句总数。
4. 对算法结果，正文应明确数据性质。例如“2厘米测距噪声、仿真无噪声局部运动输入、重复试验5的带真值仿真结果应同时写明具体数值和配置”，不能写成“另1次约6.98米”。实测误差和仿真误差不得混在同一段中比较。
5. 录包接收时间不能当作传感器同步时间。涉及同步时，统计消息头时间戳、传感器时间源、共同事件和时间区间；明确区分测量时间与接收时间。
6. 已采集的雷达点云和图像可以作为工作成果展示；若尚未进入定位融合，应说明其后续需要特征提取、标定和甲方实车条件下的调试，不把原始采集写成已经完成多模态融合。

## 四、图表和仿真展示

1. 图、表和数据是工作量的主要证据。报告不能只放算法框图和少量结果图，应按实测、仿真、算法、传感器和系统链路分别组织。
2. 每组重要实测至少给出一张统计表或汇总表；表中包含数据包名称、设备、传感器、帧数、时间范围、质量统计和可用于的实验。算法仿真至少给出参数表、逐组结果表、误差图和状态/可用率图。
3. 图题、横轴、纵轴、图例和表头优先使用中文。英文只保留话题名、代码符号、算法缩写和确有必要的原文。
4. 仿真界面、Gazebo场景、回放界面或网页演示只要能够展示真实完成的工作，就应纳入报告。不能因为界面不够美观而隐去；应在图题中说明它展示的是场景、消息流、真值、算法输出还是回放过程。
5. 仿真结果和实测结果不得使用同一张图混排，除非图题、颜色和数据来源已经明确区分。
6. 正式Word和PDF排版中，中文正文使用宋体，中文标题使用黑体；英文、数字及拉丁字符统一使用Times New Roman。

## 五、能力、结果和验收表述

1. 只陈述已经实现和验证的能力，例如“已完成三盒数据采集、消息回放、UWB相对三角形输出和RTE独立仿真评估”。
2. 不写空泛的过程性句子，例如“只有通过相应门槛的能力，才逐步进入整体闭环”；甲方和项目成员都理解这类常识，正文应直接给出已完成内容和证据。
3. 不自行设置未约定的“G1～G4”等验收体系。确需提出阶段指标时，应明确写成“建议指标”或“拟定指标”，同时说明提出依据；已经由甲方或合同确定的指标才可写成验收指标。
4. 不把“具备接口”“功能自检通过”“输出有数据”“精度通过”混为一谈。每一种结论都要对应具体数据和评价方法。
5. 说明坐标系、地图变换或消息使用方式时，直接说清本系统采用的坐标、输入、输出和计算方法。例如使用“规划模块需要地图坐标时，系统提供参考车局部坐标到地图坐标的变换”，不使用命令式的“必须提供”。
6. 章节标题和段落应自然、专业，避免“使用门槛”“工程边界”“交付方式”等僵硬表述；改用“消息字段与状态”“坐标和时间说明”“数据与复现步骤”等具体名称。

## 六、写作前后的检查清单

- 是否在第一次出现时解释了算法、缩写、消息头和坐标系？
- 每个数字是否注明了实测或仿真、数据来源、单位和统计口径？
- 是否有对应的表格、图片、日志、数据文件或命令可以复核？
- 是否把已经完成的采集、统计、回放和验证工作写足？
- 是否把实测和仿真分开编排？
- 是否出现没有定义的分级编号、验收门槛或目标指标？
- 是否使用了命令甲方、过度防御、反面提醒或自我暴露不足的句子？
- 图题、横纵轴、表头是否尽量使用中文？
- 读者不看项目历史，能否理解本段的对象、场景和结论？
- 手工修改正式报告后，是否使用只排版的渲染脚本，而没有运行会重建 Markdown 的脚本？
- 本次改动是否已经在[报告改动前后对照记录.md](报告改动前后对照记录.md)中写明文件位置、改动前内容、改动后内容、原因和验证结果？

## 2026-10-26　局部里程计、IMU和大运动参数要求

1. 报告直接说明系统具备局部里程计输入能力。车载IMU经惯性航位推算可以形成局部位姿和速度，雷达里程计、视觉里程计也可以作为上游输入；不要用“本次没有使用某前端”作为正文重点。
2. RTE精度仿真优先采用已经形成局部位姿输出的里程计输入，与论文的视觉惯性里程计实验输入保持同一层级。原始IMU积分属于上游航位推算链路，单独说明其作用和统计口径，不把长时间未经校正的惯性漂移与RTE定位精度混成同一指标。
3. 大运动仿真参数给出空间范围、持续时间、最大速度、最大加速度、航向角速度、测距噪声和重复次数，并说明这些参数对应的实际运动场景。参数用于覆盖大范围运动即可，不人为加入未经任务设定的中断、丢包或极端噪声。
4. 如果大误差来自静止阶段过早初始化或局部解分支，应通过运动激励条件和算法状态处理，不能把初始化问题写成传感器误差。RTE初次建系可配置最小运动范围，默认UWB相对三角形程序保持不变。
5. 论文引用明确精度、实验类型和里程计来源。本项目引用的RTE论文采用100次蒙特卡洛仿真和Intel RealSense T265视觉惯性里程计实测，UWB约37 Hz、VIO约200 Hz，VICON提供真值；论文五组实测的QCQP位置RMSE依次为0.296、0.201、0.124、0.108和0.178 m，不能直接写成三车实测结论。

## 2026-10-27　开发阶段低速编队仿真要求

1. 开发阶段的无人车仿真按安全、可靠的低速工况设置，最大车速不超过3米/秒；给出实际最大速度、起步过程和运动范围。
2. 大运动范围指编队整体覆盖较大区域，车间距可保持在20～30米以内；同时检查最小车间距，避免出现明显不合理的接近。
3. 对比里程计精度时固定轨迹和测距噪声样本，写明无误差输入、小漂移模型和具体参数。合成局部里程计输出可以用于分析上游里程计精度的影响；雷达点云、视觉图像或具体前端仿真需有对应实际处理链路才能如此命名。

## 2026-11-01　初始化门槛与室外退化输入修订

本轮意见指出两点：图13中的10米不能写成规划或控制需要安排的运动距离，也不能把较晚出线解释成优化器计算耗时；VIO/LIO仿真还应在输入参数中直接考虑滩涂、沙地和训练场的特征退化，而不是只在文字中提醒实车可能变差。

执行规则：

1. 10米只按当前RTE实现的初次建系运动变化判据说明，交代它用于避免静止或小范围近直线运动产生多解；同时说明低机动起步不应持续等待固定距离，后续采用可变时间窗口和收敛、测距几何、位置不确定度联合判定。
2. 连续定位阶段的相对机动对照与初始建系判据分开，机动实验不再承担初始化距离条件的解释。
3. VIO/LIO三档输入直接采用室外退化条件：VIO随机位移100/60/30厘米、尺度2.0%/1.0%/0.4%、方向变化0.00020/0.00010/0.00004弧度/秒；LIO随机位移60/30/16厘米、尺度1.0%/0.4%/0.2%、方向变化0.00010/0.00004/0.00002弧度/秒。相关84条件、1680次重复、布点、峰值和机动结果全部重算。

意图：对甲方说明算法的输入条件和当前处理方式，避免把规划运动假设写成定位模块的要求，也避免用过于理想的运动输入支撑室外精度表述。

## 异常曲线说明（2026-11-01）

曲线前段与后段出现明显不同的上升、下降或突变时，紧挨结果图说明发生了什么、关键时间及量级，并结合输入和输出查找原因；区分错误初始解、后续位置跳变与稳定后的波动，明确试验条件、曲线对象及坐标刻度。测距残差较小不能单独说明相对位置一定正确，无法由现有证据确定的触发机制不作定论。

## 2026-11-02：机动方式的范围

用户所说的机动包括相对加减速、转弯、平行及非平行行驶，并不只指相对运动幅度。设计仿真和解释曲线时应区分具体运动过程，同时分析对最终定位误差的影响；多种运动因素同时变化时，不把相关性直接写成因果关系。比较时交代共同起步、误差输入、时间段及评价口径，使用实际运行结果绘图。

## 2026-11-02：直线运动基线与结论章
