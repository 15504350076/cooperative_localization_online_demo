# Omni-swarm 时间同步与本工程录包参数

## Omni-swarm 的做法

Omni-swarm主要依赖ROS消息时间戳和各机通信链路进行协同，不是用UWB测距消息替代统一时钟。它的时间对齐前提是各节点使用同一ROS时间基准；工程落地时仍应由系统时钟同步（如NTP/PTP）或硬件触发保证。仅比较不同机器各自的录包接收时间，不能证明同步。

## 录包时长

`record_joint_time.py` 默认每路录制180秒。可命令行调整，例如：

```powershell
python tools\record_joint_time.py --duration 600
```

订阅就绪后脚本会明确提示已经开始录制。现场人员可在整个录制时段内任选时刻只移动一个约定盒子，完成后保持静止，并在`实验备注.txt`记录盒号和大致动作时间。需要更长沟通时间时增大`--duration`，例如15分钟使用`--duration 900`。

默认180秒无需输入 `y` 或等待回车；不再按固定秒点依次移动三盒。全静止实验保持静止并填写备注即可。代码仍保留最低时长限制 `max(150, 90+20×盒子数)` 秒，这是参数校验规则。

时长从各路远端录包命令启动时计算；压缩、下载和解压需要额外时间，因此电脑脚本的总运行时间会超过指定录包时长。更新本地工程后，需将最新的 `tools/record_joint_time.py` 重新复制到上交Windows电脑，已有副本不会自动更新。
