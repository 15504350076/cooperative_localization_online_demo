# 41 201盒UWB最小在线相对定位部署步骤（精简执行版，已合并）

现场命令已合并到 `docs/21_上交盒端传感器节点启动与可用性检查_精简执行版.md` 第7节。本文件仅用于追溯。

本页只用于已经完成编译安装后的现场运行。首次编译、源码上传和排障看[详细讲解版](41_201盒UWB最小在线相对定位部署步骤.md)。本流程只启动201上的浙大UWB-only融合节点，不改动上交程序。

当前运行关系：三盒`gnss_uwb`发布`/uwb/range`，只在201运行浙大融合节点，输出`/cooperative_localization/poses_2d`。

终端按用途命名：三盒已有的`gnss_uwb`所在终端称为“UWB启动终端”；下面在201另开的终端称为“融合终端”“观察终端”和“录包终端”。如果`gnss_uwb`已经在后台正常运行，不必另开UWB启动终端。

## 1. 启动前检查

三盒的上交`gnss_uwb`应已经运行。只在201执行：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash

export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

ros2 topic type --no-daemon /uwb/range
ros2 topic info --no-daemon --verbose /uwb/range
ros2 interface show cooperative_interfaces/msg/UwbRange
timeout --signal=INT 5s ros2 topic echo --no-daemon --once \
  --qos-profile sensor_data \
  /uwb/range cooperative_interfaces/msg/UwbRange
```

应满足：

- Topic类型为`cooperative_interfaces/msg/UwbRange`；
- 能看到1、2、3之间的测距消息；
- `distance`大于0；
- 当前接口包含`header、src_id、target_id、rolling、distance`。

如果看不到Topic，先检查三盒的ROS域、RMW和`ROS_LOCALHOST_ONLY`，不要启动融合节点排查。

## 2. 启动201融合节点

先确认没有旧的浙大融合进程：

```bash
pgrep -af '/zju_cooperative_fusion_node( |$)' || echo '融合节点当前未运行'
```

在201融合终端执行：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
source /home/firefly/zju_coop_ws/install/ros2-box/setup.bash

export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

ros2 launch zju_coop_bringup uwb_only.launch.py \
  reference_node_id:=1 \
  uwb_topic:=/uwb/range \
  poses_topic:=/cooperative_localization/poses_2d
```

看到`cooperative output ready`后保持融合终端运行。不要再启动第二份融合节点，也不要停止三盒的`gnss_uwb`。

## 3. 检查三车在线相对位置

在201观察终端加载同样环境：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
source /home/firefly/zju_coop_ws/install/ros2-box/setup.bash

export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

ros2 node list | grep zju
ros2 topic info --no-daemon --verbose /cooperative_localization/poses_2d
timeout --signal=INT 15s ros2 topic hz /cooperative_localization/poses_2d
timeout --signal=INT 15s ros2 topic echo --no-daemon --once \
  /cooperative_localization/poses_2d \
  cooperative_localization_msgs/msg/CooperativePose2DArray
```

正常输出应包含：

```text
reference_node_id: 1
vehicles: 1、2、3
position_valid: true
yaw_valid: false
frame_id: coop_ref_1_relative
```

车1应为`(0,0)`，车2位于相对`+X`方向，车3位于另一侧镜像分支。纯UWB不能得到车辆自身航向，因此`yaw_valid=false`是正常结果。

如果15秒没有输出，先看融合终端是否提示`missing edge`、`measurement_consistency=failed`或三角不等式失败。它表示这段时间没有有效三角形，不表示盒子死机。

## 4. 录制60秒在线输入和输出

保持融合终端运行，在201录包终端执行：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
source /home/firefly/zju_coop_ws/install/ros2-box/setup.bash

export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

ONLINE_TIME=$(TZ=Asia/Shanghai date +%Y%m%d_%H%M%S)
ONLINE_BAG=/home/firefly/uwb_test/zju_online_v1_${ONLINE_TIME}
mkdir -p /home/firefly/uwb_test

timeout --foreground --signal=INT --kill-after=5s 60s \
  ros2 bag record -o "$ONLINE_BAG" \
  /uwb/range /cooperative_localization/poses_2d

if [ -f "$ONLINE_BAG/metadata.yaml" ]; then
  ros2 bag info "$ONLINE_BAG"
  ONLINE_ARCHIVE="${ONLINE_BAG}.tar.gz"
  tar -C "$(dirname "$ONLINE_BAG")" -czf "$ONLINE_ARCHIVE" \
    "$(basename "$ONLINE_BAG")"
  ls -lh "$ONLINE_ARCHIVE"
  sha256sum "$ONLINE_ARCHIVE"
  printf '下载文件：%s\n' "$ONLINE_ARCHIVE"
else
  printf '录包失败：未生成 metadata.yaml\n' >&2
fi
```

包里必须同时有输入`/uwb/range`和输出`/cooperative_localization/poses_2d`。原始录包目录会保留，并在同一目录自动生成`zju_online_v1_<北京时间>.tar.gz`；下载该压缩包即可。记录包路径和消息数量，后续用于统计有效输出比例和异常拒绝情况。

下载到开发电脑后的自动分析命令见[41号详细部署版的第17节](41_201盒UWB最小在线相对定位部署步骤.md#在线结果包的离线分析)。

## 5. 后续测试顺序

在线静态输出连续稳定后，再按顺序做：

1. 与上交确认GCS需要的Topic、消息类型、QoS、节点号、坐标系和时间戳；
2. 只移动一个盒子约0.5～1米，另外两个保持静止，录制输入输出并检查相对坐标变化；
3. 动态UWB通过后，再考虑接入IMU；
4. GNSS先用于真值或绝对坐标对齐；雷达和相机分别完成自己的Topic、时间戳和外参验收后再接入。

当前没有动态数据时，只能确认静态在线输出，不能评价运动定位精度。

## 6. 停止

测试结束后，只在运行浙大融合节点的融合终端按一次`Ctrl+C`：

```bash
pgrep -af 'zju_cooperative_fusion_node|zju_local_inertial_node' || \
  echo '浙大在线节点已停止'
```

上交`gnss_uwb`应继续运行。不要使用`pkill ros2`或`killall`。
