# 当前功能与上交联调清单

## 1. 当前已经实现

| 层级 | 已实现功能 | 主要入口 |
|---|---|---|
| 输入标准化 | UWB测距；标准ROS 2 Imu字段对应的普通C/C++结构体；节点号、序号、采样/接收时间 | `types.hpp`、`c_api.h` |
| 单节点预测 | 15维误差状态 `[δp,δv,δθ,δbg,δba]`，名义状态为位置、速度、四元数、陀螺零偏、加计零偏 | `InertialEskf15` |
| IMU机理 | ENU导航系、FLU车体系、瞬时量中值积分、重力补偿、零偏补偿、过程噪声和可选消息协方差 | `inertial_eskf15.cpp` |
| 多车融合 | 三车为45维；支持稀疏节点编号；保留节点间交叉协方差；单节点异步IMU传播 | `CooperativeInertialEkf` |
| UWB更新 | 三维欧氏距离雅可比、完整15N卡尔曼增益、NIS拒绝、Joseph更新、NLOS协方差放大 | `update_range` |
| 相对输出 | 主参考节点下的二维相对位置/速度和相对位置协方差 | `estimate/estimates` |
| 质量与拓扑 | 动态边、NLOS/有效率/频率/残差窗口、降权/暂缓/剔除/恢复、连通性和二维刚性判断 | `Engine`、`DegradationMonitor` |
| 对外库接口 | `.dll/.so`稳定C ABI，版本/大小/stride校验，调用方拥有内存；默认IMU＋测距，保留仅测距回退模式 | `include/zju_coop/c_api.h` |
| 在线演示 | UDP接收IMU和UWB，定位/网络/观测/状态/告警输出 | `zju_coop_online` |
| 日志回放 | 输入输出事件日志；回放IMU与UWB输入并重新计算输出 | `zju_coop_replay` |
| 仿真验证 | 三车静止IMU、3-4-5 UWB、UWB-only和IMU＋UWB真实进程烟雾测试 | `tools/*smoke_test.py` |

标准 `sensor_msgs/msg/Imu` 没有温度，因此当前算法输入不含温度。模组私有温度可以由上交驱动记录，后续若要做在线温度补偿，应单独版本化扩展，不能改变现有结构布局。

## 2. 当前部署形态

当前初版是一个参考盒上的集中式联合求解：参考盒接收三个节点的IMU和车间UWB测距，维护15N联合协方差。它不是最终“每车各自运行本地EKF、交换NodeState、主车多跳汇总”的分布式版本。

Windows 和 RK3588 使用同一份 C/C++ 源码与 C ABI，但分别构建为 x64 DLL 和 ARM64 `.so`；二进制不能跨平台混用。上交 ROS 2 wrapper 可以复用源代码和字段映射，仍需在目标平台重新编译。工程默认 `config/demo.ini` 已启用 IMU＋测距融合，`config/range_only_demo.ini` 只用于回退和回归。

主参考节点由配置 `reference_node_id` 明确指定，示例为节点1。更换参考节点需要重新初始化实例，当前不支持任务中无缝切主。

## 3. 是否可以与上交联调

可以开始两级联调：

1. **现在即可进行C ABI联调。** 上交可在Windows或Ubuntu x86_64先写最小ROS 2 wrapper，把标准Imu和UWB消息映射到 `c_api.h`，验证创建、配置、输入、step和错误码。
2. **现在即可进行临时UDP联调。** 若上交暂时不能链接库，可按ZJCL发送类型1的UWB和类型2的IMU，接收定位/网络/观测/状态/告警。
3. **AIBrainBox真机联调仍有前置条件。** 需要上交提供RK3588/Ubuntu 22.04编译环境或在盒端执行构建，冻结真实UWB消息、IMU frame/外参、时间域、ROS 2 topic/QoS，并提供至少一段可回放数据。

没有实际ARM64构建与实物数据前，只能表述为“具备联调接口和在线仿真闭环”，不能表述为“已在AIBrainBox部署通过”。

## 4. 上交需要提供或确认

- 盒子系统镜像、编译器版本、ROS 2发行版、CPU架构和部署目录权限；
- 每车稳定且唯一的 `node_id`，以及当前主参考节点；
- `sensor_msgs/msg/Imu` topic、实际频率、QoS、`frame_id`、轴向、单位、安装外参和标定结果；
- UWB topic/消息：from/to、sequence、统一时间戳、距离、标准差、NLOS标志/概率、valid/status；
- 上交统一时间轴的epoch和精度，回调接收时刻的获取方式，失同步的处理规则；
- 三车初始相对位置/姿态来源；没有绝对约束时整体平移、旋转和镜像不能仅靠车间距离消除；
- ROS 2输出topic、交大GCS网关方式以及三方确认的QoS；
- 实测bag或日志，至少包含静止、直线、转弯、NLOS、断边、乱序和重连场景。

## 5. 当前未完成

- 实际RK3588/AArch64构建、CPU/内存/延迟/长稳测试；
- 上交正式ROS 2包和消息定义；
- NodeTimeSync、LinkState、NodeState显式输入及分布式多跳汇总；
- IMU温漂模型、在线初始对准、车辆运动约束和真实标定参数整定；
- 激光点云配准、多目视觉识别/相对位姿、传感器外参和对应退化检测；
- GCS三维姿态/高度输出，目前仍明确标为无效；
- 有真值基准的精度指标验证。

## 6. 推荐首次联调顺序

1. 上交先用三条合成Imu和UWB消息调用C ABI，确认结构体、单位、frame和时间；
2. 接真实静止IMU，检查重力轴向和静止速度漂移；
3. 接真实UWB，静态验证三边和NLOS字段；
4. 三车低速运动，比较算法输出、UWB残差和独立真值；
5. 注入失同步、乱序、断边和NLOS，检查降权/告警/恢复；
6. 通过后再做systemd自启动、长稳、资源和交大GCS正式网关联调。
