标准 `sensor_msgs/msg/Imu` 没有温度，因此当前算法输入不含温度。模组私有温度可以由上交驱动记录，后续若要做在线温度补偿，应单独版本化扩展，不能改变现有结构布局。

当前独立自检包含新增 `[PASS] pose2d_snapshot`，成功摘要为 `SELF_CHECK PASS (passed=14, failed=0)`；旧 C ABI v1 有效位检查仍保留。ROS 2/Gazebo同机测试已另行通过，但这些结果仍不代表 RK3588、跨盒网络或实车验证。

## 2. 当前部署形态

当前仓库并存两条模式：旧集中式路径由参考盒接收三车IMU并维护15N联合协方差，继续作为回归基线；新首版由每车运行本地15维惯导并发布NodeState，参考车只汇聚紧凑状态和UWB，维护二维协同修正并发布GCS结果。新模式仍依赖一个参考节点汇聚，不是无中心或显式多跳算法。

Windows 和 RK3588 使用同一份 C/C++ 算法源码与 C ABI，但分别构建为 x64 DLL 和 ARM64 `.so`；二进制不能跨平台混用。ROS 2消息、local/fusion节点、bringup、topic和QoS首版已在Ubuntu 22.04 x86-64实现并测试，仍需在目标ROS 2/ARM64环境重新编译，并用上交正式UWB包替换当前测试消息依赖。

主参考节点由配置 `reference_node_id` 明确指定，示例为节点1。更换参考节点需要重新初始化实例，当前不支持任务中无缝切主。

## 3. 是否可以与上交联调

当前可以开始以下联调：

1. **纯 C ABI 联调。** 现有调用示例、C API测试和独立自检共同验证创建、惯性配置、IMU/UWB输入、`step`、只读 `zju_coop_get_pose2d_v2`、错误码和销毁；其中 Pose2D v2 的直接证据位于 `tests/test_c_api.cpp` 和自检项 `pose2d_snapshot`。该层不依赖 ROS 2。
2. **临时 UDP/GCS 联调。** 可按 ZJCL 发送类型1的UWB和类型2的IMU，接收旧定位/网络/观测/状态/告警以及类型105 Pose2D；该链路用于当前在线演示。
3. **ROS 2同机软件联调。** 当前消息包、local/fusion节点、解析仿真和Gazebo闭环可以直接运行；进入AIBrainBox联调前，上交仍需提供RK3588环境、正式UWB消息、topic/QoS、IMU frame/外参、统一时间域和DDS条件。

没有实际ARM64构建与实物数据前，只能表述为“具备联调接口和在线仿真闭环”，不能表述为“已在AIBrainBox部署通过”。

## 4. 上交需要提供或确认

- 盒子系统镜像、编译器版本、ROS 2发行版、CPU架构和部署目录权限；
- 每车稳定且唯一的 `node_id`，以及当前主参考节点；
- `sensor_msgs/msg/Imu` topic、实际频率、QoS、`frame_id`、轴向、单位、安装外参和标定结果；
- UWB topic/消息：from/to、sequence、统一时间戳、距离、标准差、NLOS标志/概率、valid/status；
- 上交统一时间轴的epoch和精度，回调接收时刻的获取方式，失同步的处理规则；
- 三车初始相对位置和公共 ENU 初始航向来源、精度与注入时刻；UWB 测距不直接观测航向；
- 允许浙大适配节点使用的 ROS 2 namespace、DDS domain/网络、部署方式，以及交大GCS订阅结果的约定；
- 实测bag或日志，至少包含静止、直线、转弯、NLOS、断边、乱序和重连场景。

## 5. 当前未完成

- 实际RK3588/AArch64构建、CPU/内存/延迟/长稳测试；
- 上交正式输入消息包与生产topic/QoS冻结，以及现有浙大ROS 2节点的RK3588和跨盒部署；
- NodeTimeSync、LinkState、NodeHealth及无中心/显式多跳协同；NodeState首版已实现；
- IMU温漂模型、在线初始对准、车辆运动约束和真实标定参数整定；
- 激光点云配准、多目视觉识别/相对位姿、传感器外参和对应退化检测；
- GCS高度和完整三维姿态输出；当前ROS 2与临时UDP Pose2D链路提供二维x/y与各车ENU航向，C ABI v1旧yaw仍无效；
- 有真值基准的精度指标验证。

## 6. 推荐首次联调顺序

1. 双方先冻结输入消息、统一时间、坐标系、公共 ENU 初始航向、结果消息和 QoS；
2. 浙大用合成 Imu/UWB 数据验证 C ABI、NodeState、ROS 2 local/fusion和GCS输出链；
3. 在上交 ROS 2 环境接真实静止IMU，检查重力轴向、初始航向和静止速度漂移；
4. 接真实UWB，静态验证三边、时间戳和NLOS字段；
5. 三车低速运动，比较算法输出、UWB残差和独立真值；
6. 注入失同步、乱序、断边和NLOS，检查降权/告警/恢复；
7. 通过后再做DDS跨盒GCS、systemd自启动、长稳和资源联调。
