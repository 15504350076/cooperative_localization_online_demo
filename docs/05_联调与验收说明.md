# 联调与验收说明

## 0. 验证边界

当前可以在 Windows 上验证 C++17 工程、C ABI、临时 UDP/GCS、日志和回放；在 Ubuntu 22.04 x86-64 上还已验证每车本地惯导、NodeState、参考车二维 UWB 修正、ROS 2/Fast DDS 同机链路和 Gazebo 闭环。

以下项目仍需后续现场证据：

- Ubuntu 22.04 ROS 2 节点的 RK3588/AArch64 构建、DDS 跨盒通信与长稳；
- RK3588/AArch64 原生编译、`.so` 加载、CPU/内存和长时间稳定性；
- 上海交大真实 IMU/UWB 的字段、QoS、时间同步和序列语义；
- 实车公共 ENU 初始对准、外参、轨迹真值和定位精度；
- 点云相对观测处理。当前点云只有 C ABI 预留校验入口，不进入算法。

本机 x86-64 测试通过只能证明当前软件链路与冻结语义，不能代替 RK3588、跨盒、真机和精度验收。

## 1. Windows Release 构建与 CTest

环境最低要求：Visual Studio 2022 C++ 工具链、CMake 3.16+、Python 3。以下命令在工程根目录的 PowerShell 或 Visual Studio Developer PowerShell 中执行：

```powershell
cmake -S . -B build-vscode -DBUILD_TESTING=ON
cmake --build build-vscode --config Release --parallel
ctest --test-dir build-vscode -C Release --output-on-failure
```

若普通 PowerShell 找不到 `cmake`，可在 VS Code CMake Tools 中使用 `.vscode/settings.json` 指定的 CMake，或从 Visual Studio Developer PowerShell 执行。不得把“VS Code 没有红线”当作构建通过。

CTest 当前登记七个测试目标：

1. `zju_coop_tests`：C ABI、核心滤波、Pose2D、协议、在线适配层等 C++ 测试；
2. `c_header_smoke`：纯 C 头文件、v1/v2 初始化器和符号可用性；
3. `zju_coop_sdk_consumer`：外部调用者示例；
4. `zju_coop_self_check`：独立 C ABI 自检；
5. `zju_coop_python_tests`：Python 协议、模拟器和 GCS 测试；
6. `zju_coop_range_only_online_smoke`：仅测距兼容链路；
7. `zju_coop_default_online_smoke`：默认 IMU＋测距、Pose2D、日志和回放链路。

验收记录必须保留命令、完整输出、退出码和测试日期；测试数量会随工程新增用例变化，不能硬编码成永久指标。

## 2. 独立动态库自检

```powershell
.\build-vscode\Release\zju_coop_self_check.exe
```

该进程通过公开 C ABI 构造三车静止 IMU 和 3-4-5 测距，验证传播、更新、参考输出、拓扑、重复包、超时和恢复；`pose2d_snapshot` 还验证三车 0°/+90°/-135° 初始 ENU 航向、3-4-5 位置、共同时间和 `frame_id`。当前预期末行为：

```text
SELF_CHECK PASS (passed=14, failed=0)
```

它不打开网络端口、不读取 INI、不写日志，也不影响后续 online 或 ROS 2 实机进程。自检覆盖范围有限，不能证明 105 UDP、GCS、真机时间同步或定位精度。

## 3. Windows 手动在线闭环

从工程根目录打开三个 PowerShell 终端。

终端 1，启动本机 GCS 看板：

```powershell
py -3 -B tools\gcs_dashboard.py --udp-port 39002 --http-port 8080
```

终端 2，启动默认 IMU＋测距在线进程：

```powershell
.\build-vscode\Release\zju_coop_online.exe --config config\demo.ini
```

终端 3，发送三车 100 Hz 瞬时 IMU 和 20 Hz 三边测距：

```powershell
py -3 -B tools\imu_uwb_simulator.py --host 127.0.0.1 --port 39001 --duration 10
```

浏览器访问 `http://127.0.0.1:8080`。默认配置应显示节点 1 为 `(0,0)`，节点 2/3 为相对位置，并在有效时显示三车各自的 ENU 航向箭头。online 结束摘要中应看到 `imu>0`、`propagated_imu>0`、`accepted_ranges>0`、`published_pose2d>0`。

模拟器采用固定初值和理想误差假设，仅服务软件验证。它不构成真实 IMU 噪声、安装误差、UWB NLOS、时钟漂移和车辆动力学的有效模型。

## 4. 默认在线 smoke

可单独运行：

```powershell
py -3 -B tools\imu_online_smoke_test.py `
  --online-exe build-vscode\Release\zju_coop_online.exe `
  --replay-exe build-vscode\Release\zju_coop_replay.exe `
  --config build-vscode\config\demo.ini
```

该进程级测试应验证：

- 三个节点均收到并传播 IMU；
- 测距进入处理链；
- AlgorithmStatus 报告模式 2；
- 收到节点 1/2/3 的 Localization；
- 收到节点 1/2/3 的有效 105 Pose2D；
- 至少一个相同 `timestamp_ns` 的批次覆盖三车，且 `target_node` 为参考节点 1；
- GCS 只在该三车批次收齐后原子更新，残缺或跨参考节点批次不能部分覆盖页面；
- 三车 x/y 与配置的 `(0,0)`、`(3,0)`、`(0,4)` 在测试容差内一致；
- 三车 yaw 与配置初值在测试容差内一致；
- online 摘要包含 `published_pose2d>0`；
- ZJLG 日志非空，replay 能重新消费 IMU 和测距输入。

CTest 会自动调用该脚本；手动运行便于定位端口、进程或输出字段问题。

## 5. C ABI 最小闭环验收

一次输出周期必须按以下顺序审计：

1. `zju_coop_step(NULL/0/0)` 查询 v1 输出容量，返回 `BUFFER_TOO_SMALL`，不推进；
2. 初始化数组并再次 `zju_coop_step()`，算法只在此处实际推进一次；
3. `zju_coop_get_pose2d_v2(NULL/0/0)` 查询车辆数，只读；
4. 初始化车辆数组并再次查询 Pose2D，只读；
5. 同一批三车的 `timestamp_ns/reference_node_id/frame_id` 一致；
6. v1 `zju_coop_localization_t.yaw_valid` 仍为 false；
7. v2 单车 `yaw_valid` 在共同 IMU 历元和合法姿态下为 true；
8. 错 ABI、错结构长度、错 stride、非零 reserved 或容量不足时不部分覆盖输出。

对应测试重点位于 `tests/test_c_api.cpp`、`tests/test_cooperative_inertial_ekf.cpp` 和 `tests/test_quaternion.cpp`。

## 6. 三车坐标与快照验收

当前冻结口径：

- 参考车编号来自 `reference_node_id`，默认是 1；
- 每车位置为 `p_node^ENU-p_reference^ENU`；
- 参考车 x/y 必须为 0；
- 原点随参考车移动，坐标轴保持公共 ENU 东/北方向；
- 每车 yaw 为本车 FLU 前向 +X 相对公共 ENU 东向 +X 的逆时针角，范围 `[-π,π)`；
- 参考车 yaw 保留，不归零；其他车 yaw 不减参考车 yaw；
- `frame_id` 为 `coop_ref_<reference_node_id>_enu`；
- 三车不同 IMU 历元时，快照时间置 0，位置和航向有效位均为 false。

105 UDP 按车发送三帧。GCS 必须用共同 `timestamp_ns+target_node` 聚合，并防止乱序旧帧回退当前显示。

## 7. 实车联调前置清单

| 项目 | 责任方 | 进入联调的最低条件 |
|---|---|---|
| 车辆与 `node_id` | 双方 | 唯一，且 ROS、UWB、GCS 映射一致 |
| 单车/跨车时间同步 | 上海交大 | 所有消息携带同一 epoch 的测量时间；接收时间可比较；同步状态可诊断 |
| 公共 ENU 与初始 yaw | 上海交大为主、双方确认 | 三车初始姿态处于同一 ENU；FLU/ENU、四元数方向和单位书面冻结 |
| UWB 自定义消息 | 上海交大 | 至少有 header、src、target、distance；质量、序列和接收时间映射方案补齐 |
| IMU 消息 | 上海交大 | 标准 `sensor_msgs/Imu`，frame、单位、重力/比力语义与协方差口径确认 |
| ROS 2 适配节点 | 浙大 | 订阅、C ABI 映射、串行调用、错误日志和结果发布全部完成 |
| Pose2D ROS 2 消息 | 双方 | header、reference、三车 node/x/y/yaw/valid 字段与 QoS 冻结 |
| DDS/GCS | 上海交大 | GCS 盒能订阅结果，处理有效位、快照时间和参考车切换 |
| RTK 真值 | 双方 | 坐标转换、同步、样本匹配和误差统计方法冻结，只用于评估 |

## 8. 功能场景

### 理想正常场景

- 三车形成同历元 Pose2D；
- 参考车位于 `(0,0)`，三车 `position_valid/yaw_valid=true`；
- 105 的三帧具有相同快照时间与参考节点；
- 网络连通、几何可观；
- v1 Localization 继续保持 `yaw_valid=false`。

### IMU 节点不同步

- 任一节点姿态时间落后时，Pose2D `timestamp_ns=0`；
- 本批位置和航向有效位为 false；
- GCS 保留上一合法快照或明确显示无效，不把零值当新定位。

### 单边断开/几何退化

- 超过 `edge_timeout_ns` 后活动边减少；
- 欠约束时出现 `GRAPH_GEOMETRY_DEGENERATE` 或不可达原因；
- 告警进入 ACTIVE；恢复并完成状态机恢复后发送一次 CLEARED。

### 时间与协议异常

- 零接收时间、过度未来、过度延迟、乱序或重复输入按接口规则拒绝；
- 错 magic、版本、长度、CRC、布尔、reserved、NaN/Inf 和错误能力位被拒绝；
- 非法帧不得覆盖上一合法 GCS 快照。

## 9. 性能与精度声明

当前测试证明理想软件闭环和接口行为。真实 UWB 定位精度、航向漂移、实时性和资源占用仍需：独立真值、明确样本单位、同步误差统计、场景/时长说明及 CPU/内存/磁盘记录。不得根据模拟器结果宣称满足实车指标。

## 10. 交付证据

每次交付至少保存：

- 源码版本、配置、编译器、CMake、Python 和平台信息；
- configure/build/CTest 完整输出与退出码；
- 独立 self-check 输出；
- 默认 IMU＋测距 smoke 输出和 online `SUMMARY`；
- 105 三车共同时间戳、参考节点、x/y/yaw/有效位样例；
- ZJLG 日志及 replay 摘要；
- 未验证项、外部阻塞和复测计划。

不得用口头“能跑”替代命令输出，也不得把 Windows 仿真结果写成 ROS 2、RK3588 或实车结果。
