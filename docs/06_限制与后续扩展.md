# 已知限制与后续扩展

## 1. 当前已知限制

### 平台验证

- 已在 Windows x64 构建，并在 Ubuntu 22.04 x86-64 完成算法、ROS 2 Humble/Fast DDS 和 Gazebo 同机闭环；
- 未在 RK3588/AArch64、跨盒 ROS 2/DDS 或真实 UWB 上运行；
- 未测 CPU、内存、日志吞吐、实时性和长期稳定性。

### 算法范围

- 保留参考盒集中式的每节点15维IMU预测和15N联合UWB距离更新，作为回归基线；
- 已实现“每车本地15维惯导→紧凑NodeState→参考车二维UWB修正→GCS”的首版分布式软件链；当前仍由一个参考节点汇聚状态和测距，不是无中心或显式多跳协同算法；
- 首版协同修正不反馈本地惯导，不携带跨车协方差，不支持单车热重启，只适用于短时演示；
- 三车需要完整非共线三角形才能瞬时二维可观；
- 外部位置初值固定整体坐标方向和镜像分支；理想初始对准还要求每辆车提供公共 ENU 初始航向；
- 后续姿态由瞬时 IMU 递推；UWB 标量测距不直接观测航向，静止或缺少运动激励时不能靠测距校正初始航向误差；
- 内部维护三维位置/速度/姿态/零偏。Pose2D C ABI v2、临时 UDP 和 GCS 已输出二维相对 x/y 与各车 ENU 航向；C ABI v1 旧 `Localization` 仍固定 `yaw_valid=false`，z、高度、完整三维姿态和绝对地理坐标均未输出。

### 接口范围

- ZJCL/UDP 是临时演示协议，没有可靠传输、认证、加密和重传；
- ZJLG 未冻结轮转、保留周期、元数据校验和记录时钟 epoch；
- 首版 ROS 2 适配节点、NodeState、GCS结果消息、topic和QoS已实现；上交正式 UWB 包、生产 QoS、NodeTimeSync、LinkState 和 NodeHealth 尚未实现或冻结；
- ROS 2 Pose2D frame 已采用 `coop_ref_<reference_node_id>_enu`，x/y 轴与公共 ENU 平行；生产时间 epoch 仍需冻结。

### 传感器范围

- 当前只融合IMU与UWB，尚未融合激光雷达或多目视觉；
- 当前没有点云配准、视觉目标/特征识别、相机标定或跨传感器外参资料；
- 原始 PointCloud2 和图像不能直接替代相对位姿观测。

## 2. 推荐的近期扩展顺序

1. 在 UGV V3 真机完成 ARM64 构建、ABI、在线和长时资源验证；
2. 冻结上交 UWB TLV、统一时钟域和 ROS 2 Range 消息；
3. 用上交正式 UWB 包替换当前测试消息依赖，并在三盒 DDS/盒端环境验证现有 ROS 2 节点和 GCS 跨盒接入；
4. 用真实 UWB 和独立真值完成三车精度测试；
5. 增加第 4 辆车和冗余边，验证断边容错；
6. 用真实IMU完成轴向、噪声、零偏、温漂、时间和外参验证；
7. 再开发激光/视觉相对观测前端；
8. 根据带宽和实测漂移决定是否增加协同修正反馈、分层汇聚或无中心约束传播。

## 3. 激光雷达扩展需要什么

若上交只提供 `sensor_msgs/msg/PointCloud2`，浙大还需要：

- 雷达型号、点字段、频率和时间戳语义；
- 点云去畸变所需运动/IMU 信息；
- 雷达到车体外参；
- 车辆间关联或扫描匹配策略；
- 相对位姿、6×6 协方差、残差 RMSE 和退化标志的输出定义；
- 可复现 bag、场景说明和真值/标注。

原始点云应在各盒本地处理，跨车与 GCS 只传相对观测摘要。

## 4. 多目视觉扩展需要什么

若上交只提供多路 `sensor_msgs/msg/Image`，浙大还需要：

- 每个相机 CameraInfo、畸变模型和内参；
- 相机间、相机到车体的外参；
- 硬件同步和曝光时间语义；
- 车辆目标标识、特征/目标识别训练数据或可用检测器；
- 跨车数据关联方案；
- 相对位姿、协方差、inlier_count、inlier_ratio 和 reprojection_rmse_px；
- 标定数据、bag、遮挡/弱纹理/光照场景和真值。

视觉目标识别与相对位姿前端不应放在 GCS。GCS只显示算法输出的相对观测质量、退化原因和定位结果。

## 5. 退化环境识别接口位置

退化识别应在算法/传感器前端接口协议中定义，不应由 GCS重新实现：

- UWB：距离、标准差、NLOS 标志/概率、valid/status、采样/接收时间；
- 激光：相对位姿、协方差、residual_rmse、degeneracy_flag；
- 视觉：相对位姿、协方差、inlier_count、inlier_ratio、reprojection_rmse_px；
- 平台：NodeTimeSync、LinkState、NodeHealth，由上交提供；
- 算法：Pose2D 已由浙大 ROS 2 适配节点发布；ObservationState、FusionAction、reason_mask 和 Alert 的正式 ROS 2 映射仍待接口评审。

GCS只负责分区展示、历史记录和传输状态提示，不能修改算法门限或把平台健康映射为定位状态。

## 6. 变更原则

后续新增字段必须版本化并同步修改：C ABI 或正式 ROS 2 schema、线协议参考实现、C++/Python golden bytes、日志、GCS、测试和交接文档。不得在保留原版本号的情况下改变字段偏移、枚举或单位。
