# GNSS初始化与RTK相对真值设计

## 1. 目标与边界

使用ROS 2 Humble标准`sensor_msgs/msg/NavSatFix`完成两项独立功能：

1. GNSS拒止前，利用各节点同步定位结果自动生成现有二维滤波初值和每节点15维惯性初值；
2. GNSS/RTK仍可用时，生成主参考节点坐标系下的相对位置真值，供日志、GCS和精度评估使用。

RTK真值不得进入`Engine`、EKF量测更新、退化状态机或动态拓扑。标准
`NavSatFix`不区分RTK Fixed/Float，因此“真值topic只发布可作为真值的数据”是上海交大
GNSS驱动与wrapper的接口承诺；浙大仍校验定位状态、协方差、时间和数值范围。

## 2. ROS 2与C ABI映射

`zju_coop_gnss_fix_packet_t`逐字段映射：

- `header.stamp` → `timestamp_ns`；
- `header.frame_id` → `frame_id`；
- `status.status/service` → 同名数值；
- `latitude/longitude/altitude` → WGS84经纬度和椭球高；
- `position_covariance[9]`和`position_covariance_type` → 同名字段；
- wrapper补充`node_id`、`sequence`、同时间域`receive_timestamp_ns`和`valid`。

不把ROS对象内存强制转换为C结构，不向标准ROS消息添加项目字段。

## 3. 独立上下文

新增不透明句柄`zju_coop_gnss_context_t`，与`zju_coop_handle_t`没有指针关系：

```text
NavSatFix → GNSS context → 初值数组 → create/configure主算法
                      └→ RTK相对真值 → 日志/GCS评估
```

每个节点只保存最近两个有效定位样本。上下文固定节点集合、参考节点、时间门限、速度估计
间隔、协方差门限和天线杆臂。真值查询只读取GNSS缓存，类型层面不能调用主滤波器。

## 4. 坐标与初值

- 按WGS84将经纬高转换到ECEF；
- 首次成功生成初值时，以参考节点最新有效fix为固定ENU原点；
- 所有后续初值和真值均投影到该固定ENU坐标系；
- 利用每节点最近两个fix的ENU位置差除以时间差估计三轴速度；
- 各节点最新fix时间必须落在`max_epoch_skew_ns`内；
- 天线杆臂按“IMU原点指向GNSS天线”的FLU向量配置，通过初始姿态旋转到ENU后从
  天线位置中扣除；默认杆臂为零、姿态为单位四元数；
- 位置协方差从fix局部ENU旋转到固定ENU；
- 速度协方差近似为两帧位置协方差之和除以`dt²`；
- 输出同时填充`zju_coop_node_initialization_t`和
  `zju_coop_inertial_node_initialization_t`，姿态、零偏及其标准差沿用既有安全默认值。

初值生成只允许成功一次，避免运行期间改变坐标原点。

## 5. RTK相对真值

对节点`i`和参考节点`r`：

```text
p_truth_rel = p_i_enu - p_r_enu
Cov_truth_rel = Cov_i_enu + Cov_r_enu
```

假设不同接收机定位误差独立。真值输出携带节点/参考节点时间戳、三维相对位置、3×3协方差、
有效标志和过期标志。任一节点fix过期或与参考节点时间差超限时，该节点真值无效，但查询
仍返回完整节点数组，便于GCS显示具体缺失节点。

## 6. 错误与质量规则

- 拒绝NaN/Inf、非法经纬度、非法协方差、未知节点、重复/倒序样本；
- `NavSatStatus.status < 0`或`valid=false`不得成为初值/真值；
- 配置可要求协方差类型至少为`DIAGONAL_KNOWN`；
- 水平/垂直标准差超过门限的数据不得进入有效缓存；
- 测量时间和接收时间超出未来偏差/延迟门限时拒绝；
- 所有C ABI输出先写局部临时值，完整成功后再覆盖调用方缓冲。

## 7. 测试

- WGS84经纬高到ECEF/ENU的已知点测试；
- 三节点两历元生成相对ENU位置和速度；
- 时间不同步、协方差过大、未知节点、倒序数据拒绝；
- 真值相对参考节点为零、协方差相加、过期后valid=false；
- C ABI纯C头文件、数组stride、容量查询和原子写回；
- 完整现有CTest与独立自检回归。

## 8. 明确不做

- 不把GNSS/RTK作为在线EKF位置更新；
- 不从`NavSatFix.status`猜测RTK Fixed；
- 不改变ZJCL/UDP小包协议传输原始GNSS；
- 不实现PPP/RTK解算或上海交大时间同步；
- 不声称RTK真值误差为零。
