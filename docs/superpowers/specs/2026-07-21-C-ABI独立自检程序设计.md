# C ABI独立自检程序设计

## 目标

新增独立可执行程序 `zju_coop_self_check`，使用程序内部确定性数据，通过公开 `c_api.h` 自动验证当前协同定位最小闭环。它只在用户显式启动时运行，不读取真实传感器、不占用UDP端口、不写配置或日志、不改变算法ABI和在线程序行为。

## 隔离边界

- 自检代码位于独立 `src/self_check` 目录，生产算法核心不依赖它。
- 主函数位于 `src/apps/self_check_main.cpp`，不修改 `online_main.cpp` 和 `replay_main.cpp`。
- 自检只链接 `zju_coop` 动态库并调用公开C ABI，等价于一个上交侧最小消费者。
- 不使用ROS 2、网络、文件、系统时钟、随机数和硬件驱动，Windows、Ubuntu x86-64与RK3588 ARM64使用同一源码。
- 自检失败只返回非零进程退出码，不修改其他进程或设备状态。

## 自动验证项

1. ABI版本和软件版本字符串可查询。
2. 三节点基础实例和15维惯性配置可创建。
3. 三节点首帧IMU建立时间基准，第二帧IMU完成传播。
4. 3 m、4 m、5 m三条平台间测距被处理并更新滤波器。
5. `step`的两阶段缓冲区查询和正式输出成功。
6. 输出包含三个节点、三条观测边，主参考节点为1；参考节点位于原点，另外两节点保持3-4-5几何。
7. 网络连通、二维可观，`yaw_valid=false`、`z_valid=false`。
8. 完全重复的测距包被识别为重复，不污染状态。
9. 超过边超时后活动边清零、网络断开并包含`LINK_TIMEOUT`原因位。
10. 输入新测距后网络恢复为三边连通可观。
11. handle能够正常销毁。

## 代码结构

- `src/self_check/self_check.hpp`：定义可测试的 `SelfCheckResult` 和 `run_self_check()`。
- `src/self_check/self_check.cpp`：构造C结构体、调用C ABI、收集逐项结果；不直接退出进程。
- `src/apps/self_check_main.cpp`：打印报告并把结果转换为0/非0退出码。
- `tests/test_self_check.cpp`：直接验证自检函数返回成功、检查数量和关键报告项。
- `CMakeLists.txt`：新增可执行目标、CTest和安装规则。

## 输出和退出码

每项输出固定的 `[PASS]` 或 `[FAIL]` 行，结尾为 `SELF_CHECK PASS` 或 `SELF_CHECK FAIL`。全部通过返回0；出现任何C ABI错误、状态不符或数值越界返回1。异常会转换成失败报告，不从自检模块向外抛出。

## 验收标准

- Windows Release重新构建成功；原有6项CTest不回归。
- 新增自检单元测试和独立进程CTest通过。
- 直接运行 `zju_coop_self_check`打印全部检查并返回0。
- 安装树包含自检程序，但不改变默认在线启动命令。
- Ubuntu/RK3588只能在对应环境实际编译运行后记录为通过。
