# 理想 IMU-UWB 二维位姿 GCS 闭环设计

## 1. 本轮目标

在暂不引入 ROS 2 的条件下，使现有 C++ 工程形成可演示的最小闭环：

```text
三车初始对准结果 + 三车瞬时 IMU + 车间 UWB 测距
    -> 15 维误差状态惯导递推与测距更新
    -> 参考车坐标原点下的三车二维位置和各车 ENU 航向
    -> 临时 UDP 遥测
    -> GCS 看板显示位置、数值航向和方向箭头
```

本轮保留旧接口、旧协议和回放能力。标准点云、图像、GNSS 预留接口继续存在，但不进入本轮定位计算。

## 2. 明确假设

这是理想环境下的功能闭环，以下条件由模拟器或上交侧在正式联调时满足：

1. 三车传感器时间戳已统一，时间同步由上交完成。
2. 每车启动前已经完成惯导对准，并向算法配置初始位置、速度、姿态和零偏。
3. 初始姿态四元数表示车体 FLU 坐标系到所有车辆共同 ENU 坐标系的旋转，包含有效初始航向。
4. 后续 IMU 输入为瞬时角速度和比力，算法完成姿态、速度和位置递推。
5. UWB 为视距、误差较小的车间测距，节点编号与车辆编号一致。
6. 参考节点固定为 1；后续仍保留动态参考节点和更多观测源的扩展位置。

这些假设用于证明数据链和软件接口可运行，不能作为实车精度、长时间稳定性或复杂 NLOS 环境性能的证据。

## 3. 坐标和航向定义

- 输出原点：当前参考车的位置。
- 输出坐标轴：始终与公共 ENU 平行，x 指东，y 指北。
- 车辆 i 的位置：`x_i = E_i - E_ref`，`y_i = N_i - N_ref`。
- 车辆 i 的航向：该车车体 FLU 前向轴在公共 ENU 水平面内的方向。
- `yaw_rad = 0` 表示朝东，逆时针为正，范围归一化到 `[-pi, pi)`。
- 参考车输出 `x=0, y=0`，其 `yaw_rad` 保留自身真实 ENU 航向。

航向从内部四元数得到：先把车体前向单位向量 `(1,0,0)` 旋转到 ENU，再计算 `atan2(N,E)`。车体前向轴水平投影退化时，`yaw_valid=false`。

## 4. 最小输出模型

### 4.1 单车二维位姿

```text
VehiclePose2D
  node_id
  x_m
  y_m
  yaw_rad
  position_valid
  yaw_valid
```

位置和航向分别给出有效标志，GCS 可以保留有效位置，同时隐藏无效方向箭头。

### 4.2 同历元多车快照

```text
CooperativePose2DSnapshot
  timestamp_ns
  reference_node_id
  frame_id = coop_ref_<reference_node_id>_enu
  vehicles[]
```

同一快照内各车结果属于同一个算法输出历元。理想模拟数据保证三车 IMU 递推到同一时间，再处理该时间的测距并输出。

## 5. C ABI 兼容策略

现有 ABI v1 的定位结构没有数值航向字段。直接修改其布局会导致旧调用程序的 `struct_size`、字段偏移和数组步长失配。

本轮采取兼容扩展：

1. 保留现有 ABI v1 结构、函数和版本号。
2. 新增 `zju_coop_vehicle_pose2d_v2_t`、`zju_coop_pose2d_snapshot_v2_t` 和只读查询函数 `zju_coop_get_pose2d_v2`。
3. 在线程序仍调用原有 `step` 推进一次算法，再调用 Pose2D 查询读取同一状态；查询函数不得再次推进滤波器。
4. 旧 SDK 调用方继续工作；后续 ROS 2 wrapper 可选择 Pose2D v2 输出。

## 6. 临时 UDP 协议扩展

保留所有旧消息类型，新增单车 Pose2D 消息类型 `105`。每个多车快照编码为三帧，每帧头部携带：

- `source_node`：当前车辆编号；
- `target_node`：参考车辆编号；
- `timestamp_ns`：该组快照时间。

32 字节载荷布局：

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | float64 | x_m |
| 8 | float64 | y_m |
| 16 | float64 | yaw_rad |
| 24 | uint8 | position_valid |
| 25 | uint8 | yaw_valid |
| 26 | uint16 | reserved |
| 28 | uint32 | capability_mask |

该 UDP 协议只服务当前 Windows/Ubuntu 无 ROS 演示。正式 AIBrainBox 与 GCS 联调仍按已商定的 ROS 2 消息包和 DDS 链路交付。

## 7. GCS 显示规则

1. `position_valid=true` 时绘制车辆位置和轨迹。
2. `yaw_valid=true` 时显示航向数值并绘制方向箭头。
3. 航向无效时隐藏箭头，避免把占位数值误当成真实结果。
4. 看板显示参考节点编号、快照时间和坐标系语义。

## 8. 验收条件

1. ABI v1 现有测试全部继续通过。
2. 四元数可正确提取 `0`、`pi/2`、接近 `-pi` 的 ENU 航向。
3. 三车可配置不同初始航向，参考车位置严格为零且保留自身航向。
4. 恒定 z 轴角速度输入后，航向按时间连续变化。
5. 在线程序每个周期只推进一次滤波，随后输出同一状态的 Pose2D。
6. 新 UDP 帧可被 Python 解码器和 GCS 看板识别；旧消息仍可解码。
7. 旧 range-only 演示不产生伪造的有效航向。
8. 点云预留接口仍可通过原有格式校验测试，并且未接入定位算法。

## 9. 本轮不宣称的能力

- UWB-only 可独立观测车辆航向；
- 无外部约束时长期抑制惯导航向漂移；
- NLOS、异步、多路径和链路异常下的实车精度；
- 雷达点云特征提取、配准或深度学习感知；
- ROS 2 Humble、DDS 和 RK3588 已完成实机验证。
