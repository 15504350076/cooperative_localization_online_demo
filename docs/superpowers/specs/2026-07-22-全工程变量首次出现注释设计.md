# 全工程变量首次出现注释设计

## 1. 目标

对当前工程的全部手写程序补充中文变量说明，使读者在变量第一次声明时即可理解其业务作用，并在必要时知道单位、坐标系、数据来源、生命周期、所有权和有效条件。

本轮只调整注释与为保持排版所需的空白，不修改算法、协议、C ABI、默认参数、程序行为或测试逻辑。

## 2. 文件范围

纳入范围：

- `include/` 下的公开 C ABI、公共 C++ 类型和导出声明；
- `src/` 下的算法核心、配置、协议、网络、应用和自检代码；
- `examples/` 下的 SDK 调用示例；
- `tools/` 下的 Python 协议、模拟器、GCS和冒烟工具；
- `tests/` 下的 C、C++和Python测试代码；
- `CMakeLists.txt` 与 `cmake/` 下人工维护的构建变量。

不纳入范围：

- `build-*`、IDE缓存及其他生成文件；
- 编译器、系统库、ROS 2或第三方项目代码；
- 文档示例代码中不参与工程构建的占位名称。

## 3. “第一次出现”的定义

“第一次出现”指变量在其有效作用域内的声明位置，而不是第一次读取或赋值的位置：

- 结构体字段和类成员：在字段或成员声明处说明；
- 函数参数：优先在头文件公开声明或类内首次声明处说明；仅存在实现定义时，在定义处说明；
- 局部变量：在首次声明前或同一声明行的行尾说明；
- 循环变量：在循环语句前说明其遍历对象；
- Lambda捕获和参数：在Lambda声明前说明捕获对象和参数含义；
- CMake变量：在首次`set`、`function`参数或`foreach`声明前说明；
- Python模块变量、实例成员、函数参数和局部变量：分别在首次赋值、类/函数文档字符串或首次声明语句前说明。

同名变量在不同作用域是不同变量，必须在各自首次声明点具备可独立理解的说明。

## 4. 注释形式

采用“接口注释＋声明点注释＋同语义分组注释”的混合方式：

1. 公开结构体字段和函数参数使用 Doxygen 或紧邻声明的中文注释，说明契约而不复述类型名。
2. 局部变量在声明前使用中文注释；短字段可使用对齐的行尾注释。
3. 连续且属于同一语义组的变量允许共用一段注释，但注释必须逐一指出变量名与作用。
4. 循环下标也必须说明，例如“`row`为当前协方差矩阵行号”，不得只写“循环变量”。
5. 测试变量说明其构造的场景或要证明的边界，不能只写“测试数据”。
6. Python参数优先在函数文档字符串中集中说明；函数体局部变量仍在首次赋值处说明。

## 5. 信息质量要求

合格注释至少提供变量名本身无法直接表达的一项信息：

- 业务角色或算法角色；
- 单位或量纲；
- 坐标系、旋转方向或矩阵布局；
- 数据来源和目标消费者；
- 生命周期、所有权或线程安全约束；
- 有效条件、哨兵值或与其他字段的联合解释；
- 测试中代表的输入场景和预期风险。

禁止以下低信息量写法：

- “`result`保存结果”；
- “`i`是循环变量”；
- “`config`是配置”；
- 逐字翻译变量名或类型名；
- 对同一参数在声明和实现中重复完全相同的说明；
- 为满足数量而在每次使用变量时重复注释。

## 6. 特殊规则

- 数学矩阵和状态索引必须说明维度、行列含义或对应的15维误差状态分块。
- IMU量必须说明瞬时量属性、单位、ENU/FLU约定及是否包含重力（适用时）。
- 时间变量必须区分传感器统一时间、接收时间、单调调度时间和墙上时间。
- 测距、创新、协方差与门限变量必须说明单位及用于“输入检查、质量评价或滤波更新”的哪一阶段。
- 网络缓冲、句柄和指针必须说明所有权、有效期和失败时是否保持原值。
- 协议字段必须说明线序、长度或CRC覆盖范围（适用时），且不得改变既有协议口径。
- 简单布尔变量必须说明`true`具体代表的业务状态。

## 7. 并行实施边界

允许最多三个后台子代理与主代理并行审查。文件按目录或模块唯一分配，同一文件在同一轮只由一个代理修改，避免共享工作区覆盖。

主代理负责：

- 固化注释标准；
- 分配互不重叠的文件；
- 审查所有差异是否仅涉及注释和空白；
- 纠正重复、错误或低信息量注释；
- 执行完整构建与测试；
- 使用中文提交且不推送。

## 8. 验收标准

- 范围内每个手写程序文件具有模块职责说明；
- 参数、成员、局部变量和循环变量在各自作用域首次声明处有中文用途说明；
- 抽查数学、IMU、协议、时间、网络和测试变量时，注释与真实代码语义一致；
- 差异审查未发现算法、协议、ABI、默认值或测试逻辑变化；
- Windows Release重新配置和编译成功；
- 独立自检全部通过；
- CTest全部通过，包含在线与回放冒烟；
- Python单元测试全部通过；
- Ubuntu 22.04/RK3588仅记录可执行命令，不在没有对应环境时声称已经验证。
