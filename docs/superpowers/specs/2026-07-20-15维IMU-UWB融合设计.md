## 1. 目标与交付边界

在不破坏现有 UWB-only 在线闭环、C ABI v1、ZJCL Range 消息和日志回放的前提下，增加三车 IMU 瞬时量预测与 UWB 距离联合更新。每个节点采用 15 维误差状态，在线程序同时接收标准 ROS 2 `sensor_msgs/Imu` 可映射的数据和现有 UWB Range 数据，继续向 GCS 输出主参考节点下的相对二维位置、网络状态、观测质量和告警。

本阶段采用集中式联合协方差实现三车 Demo，但状态以每个平台的 15 维本地惯性状态为基本单元。接口预留后续 `NodeStatePacket` 和分布式本地滤波升级位置，不在本阶段实现跨盒 NodeState 交换。

## 2. 既有系统兼容原则

1. `imu_enabled=false` 时，仍使用现有 `RangeEkf` 恒速预测和 UWB 更新，输出语义不变。
2. 不修改已经发布的 `zju_coop_config_t`、`zju_coop_range_packet_t`、既有函数签名、枚举值和字段偏移。
3. IMU 使用新的版本化结构和函数，不把 IMU 字段追加到 Range 结构中。
4. 旧 UWB 模拟器、GCS 面板、Range 协议黄金字节和历史日志继续可读。
5. 新版在线程序可以同时记录和回放 IMU 与 UWB；旧程序不能识别的新 IMU 消息不被描述为向后兼容能力。

## 4. 坐标系与单位

### 4.1 导航坐标系

局部 ENU：

- `x`：东；
- `y`：北；
- `z`：上；
- 重力向量：`g_n = [0, 0, -g]`，默认 `g=9.80665 m/s²`，可配置。

### 4.2 车体和 IMU 坐标系

车体使用 ROS 常用 FLU：

- `x`：前；
- `y`：左；
- `z`：上。

上交 ROS 2 wrapper 负责依据 `header.frame_id` 和配置的 IMU—车体外参，把厂商原始坐标转换为 FLU 后再调用浙大库。算法库仍检查 `frame_id` 是否与配置一致，不在运行时查询 ROS TF。

### 4.3 单位

- 时间戳：ns；
- 角速度：rad/s；
- 线加速度/比力：m/s²；
- 位置：m；
- 速度：m/s；
- 零偏：陀螺 rad/s、加速度计 m/s²；
- 四元数输入顺序：`x,y,z,w`；内部存储顺序由实现自行决定，但边界转换必须测试。

## 5. 15维状态定义

每个节点的名义状态为：

```text
x_nominal = [p_n, v_n, q_b_to_n, b_g, b_a]
```

其中 `p_n`、`v_n`、`b_g`、`b_a` 均为三维向量，`q_b_to_n` 是从车体 FLU 到导航 ENU 的单位四元数。

误差状态固定排序为：

```text
δx = [δp(0:2), δv(3:5), δθ(6:8), δbg(9:11), δba(12:14)]
```

本阶段不估计陀螺和加速度计比例因子。以后升级 21 维时使用新的状态版本，不改变 15 维公开布局。

多节点联合协方差按节点配置顺序排列：

```text
P = cov([δx_node_1, δx_node_2, ..., δx_node_N])
```

UWB 更新必须保留节点间交叉协方差，不能把两车位置协方差简单当作相互独立。

## 6. ROS 2 IMU 到算法结构的映射

上交提供的标准消息字段为：

```text
Header header
geometry_msgs/Quaternion orientation
float64[9] orientation_covariance
geometry_msgs/Vector3 angular_velocity
float64[9] angular_velocity_covariance
geometry_msgs/Vector3 linear_acceleration
float64[9] linear_acceleration_covariance
```

算法 C ABI 新增 `zju_coop_imu_packet_v1_t`，至少包含：

```c
uint32_t struct_size;
uint32_t abi_version;
uint32_t node_id;
uint32_t reserved0;
uint64_t sequence;
uint64_t timestamp_ns;
uint64_t receive_timestamp_ns;
double orientation_xyzw[4];
double orientation_covariance[9];
double angular_velocity_rad_s[3];
double angular_velocity_covariance[9];
double linear_acceleration_m_s2[3];
double linear_acceleration_covariance[9];
char frame_id[32];
zju_coop_bool_t orientation_valid;
zju_coop_bool_t valid;
uint8_t status;
uint8_t reserved1;
```

约束如下：

1. `timestamp_ns` 来自上交统一时间轴上的 `header.stamp`。
2. ROS 2 Header 没有递增序号；`sequence` 由上交 wrapper 按节点单调递增生成。
3. `receive_timestamp_ns` 是同一时间基准下 wrapper 收到消息的时刻。
4. `node_id` 由话题命名或 wrapper 配置确定，不从标准 IMU 消息猜测。
5. `frame_id` 必须是以 `\0` 结尾的 UTF-8 字节串；超过 31 B 时 wrapper 拒绝而不是静默截断。
6. 首版没有温度字段。以后若需要温漂补偿，使用独立的版本化温度输入，不修改 IMU v1。

## 7. 姿态和协方差使用规则

### 7.1 orientation

`orientation` 默认不参与运行期间的连续更新，避免模组内部融合姿态与本项目使用同一陀螺/加速度计数据造成重复计权。

当 `use_orientation_for_initialization=true` 时，仅首个可用 IMU 样本可覆盖节点配置的初始姿态，条件为：

- `orientation_valid=true`；
- 四元数全部有限且范数在配置容差内，归一化后使用；
- `orientation_covariance[0] != -1`；
- 协方差有限、近似对称且非负半定；
- 尚未进行第二帧 IMU 传播。

上述初始化完成或第一次传播开始后，后续 orientation 一律不参与状态更新。

### 7.2 三组协方差

- 对应协方差首元素为 `-1` 时，认为该类测量不可用。
- 九个元素全零时，认为协方差未知，不把零解释为无噪声。
- 非零协方差必须有限、近似对称且非负半定。
- 默认 `use_message_covariance=false`，预测使用配置的陀螺/加速度计噪声密度和零偏随机游走。
- 开启 `use_message_covariance=true` 且消息协方差有效时，角速度和线加速度白噪声项使用消息协方差离散化；零偏随机游走仍使用配置值。
- 姿态协方差只用于可选初始化质量判断，不作为 IMU 过程噪声。

## 8. IMU名义状态预测

IMU 消息是瞬时角速度和瞬时线加速度，不是角增量和速度增量。

### 8.1 时间处理

- 每个节点的第一帧有效 IMU 只保存时间、角速度和比力，建立积分基准。
- 从第二帧开始计算 `dt=(t_k-t_{k-1})×1e-9`。
- 重复时间戳、倒序时间戳、非有限测量和未知节点被拒绝，不改变状态。
- `dt < min_imu_dt_s` 或 `dt > max_imu_dt_s` 时拒绝该积分区间并重新建立基准，禁止跨长时间空洞盲目积分。
- 当有效 `dt` 大于数值传播子步上限时，以相同中值测量分子步传播，但不把分子步解释为补回缺失传感器信息。

### 8.2 中值积分

使用相邻两帧零偏补偿后的瞬时量：

```text
ω_mid = 0.5[(ω_{k-1}-bg) + (ω_k-bg)]
f_mid = 0.5[(f_{k-1}-ba) + (f_k-ba)]
Δθ = ω_mid·dt
q_mid = q_k ⊗ Exp(0.5·Δθ)
a_n = R(q_mid)·f_mid + g_n
p_{k+1} = p_k + v_k·dt + 0.5·a_n·dt²
v_{k+1} = v_k + a_n·dt
q_{k+1} = normalize(q_k ⊗ Exp(Δθ))
```

本阶段名义零偏在预测中保持常值，其不确定度通过随机游走进入协方差。

静止 FLU IMU 在水平安装且符号正确时通常测得 `f_z≈+g`，经 `R·f+g_n` 后导航加速度应接近零。该符号必须在真实盒端静止数据验收中确认。

## 9. 误差状态与协方差传播

连续误差模型采用固定顺序 `[δp,δv,δθ,δbg,δba]`，核心非零块为：

```text
F_pv    = I
F_vθ    = -R·skew(f_mid)
F_vba   = -R
F_θθ    = -skew(ω_mid)
F_θbg   = -I
```

过程噪声包含陀螺白噪声、加速度计白噪声、陀螺零偏随机游走和加速度计零偏随机游走。初版离散化使用受子步上限约束的一阶状态转移和对称化过程噪声。

联合协方差传播利用每节点 15×15 状态转移块：

```text
P_ij ← Φ_i P_ij Φ_j^T
P_ii ← P_ii + Q_i
```

不得构造并执行通用 `15N × 15N` 三次方复杂度的稠密矩阵乘法。每次传播后检查全部数值有限、矩阵对称和对角线不小于配置下限；失败时回滚该节点本次名义状态、联合协方差和时间基准。

## 10. UWB联合更新

惯性模式下 UWB 距离模型为：

```text
h(x) = ||p_from - p_to||
u = (p_from-p_to)/||p_from-p_to||
H_from_position = u^T
H_to_position = -u^T
```

其余状态块初始为零，但速度、姿态和零偏可以通过已有交叉协方差间接得到修正。

更新顺序为：

1. 复用现有 Range 包结构、时间检查、重复检查、NLOS 评价和退化状态机。
2. 根据退化状态选择正常使用、协方差放大、暂缓、剔除或试探恢复。
3. 计算残差、残差方差和 NIS，复用当前阈值语义。
4. 采用 Joseph 形式或等价稳定形式更新联合协方差。
5. 把误差位置、速度、姿态和零偏反馈到各节点名义状态，姿态反馈后重置对应误差状态。
6. 更新后执行有限性、对称性和正对角检查；失败则回滚本次 UWB 更新。

当两个节点预测位置重合、距离雅可比不可定义时，报告数值失败，不执行校正。

## 11. 主参考输出语义

内部所有节点在初始化局部 ENU 中传播，主参考节点也可以运动。向现有 GCS 输出前进行平移重基准：

```text
p_relative_i = p_i - p_reference
v_relative_i = v_i - v_reference
```

当前不随主参考车实时航向旋转坐标轴，输出轴仍保持初始化 ENU 方向。因此：

- 主参考节点输出 `x=y=vx=vy=0`；
- 非参考节点输出 `p_relative.x/y` 和 `v_relative.x/y`；
- 二维位置协方差必须由联合协方差计算 `Pii+Prr-Pir-Pri`；
- `yaw_valid=false`、`z_valid=false` 保持现有 GCS 语义；
- 三维位置、姿态、零偏和完整协方差保留在内部，并通过后续版本化状态接口输出。

```text

zju_coop_imu_processing_result_v1_t

```

`zju_coop_configure_inertial_v1` 只能在 `zju_coop_create` 成功后、任何 Range/IMU 输入或 `step` 之前调用一次。失败不部分修改引擎；开始处理后再次调用返回明确错误。旧调用方不调用该函数时继续使用 UWB-only 模式。

IMU 处理结果至少区分：已建立基准、已传播、无效包、未知节点、重复、乱序、时间间隔拒绝、frame 不匹配、姿态初始化拒绝和数值失败。

能力查询实现后，成功配置惯性模式的实例应报告 IMU 输入能力。无 handle 的静态能力查询只表示库包含该接口，不表示当前实例已启用。

## 14. 在线协议、日志与回放

- ZJCL 新增独立 IMU 消息类型，不改变 Range payload。
- IMU payload 固定字段顺序、字节序、长度、枚举和保留位，C++ 与 Python 共同维护黄金字节测试。
- ZJLG 继续记录完整 ZJCL 帧、方向和接收时间，因此可以按原始时间轴重放 IMU 与 UWB。
- 回放必须跳过历史输出帧，只把历史 IMU 和 Range 输入重新送入算法。
- 在线程序按时间戳处理每节点 IMU，并异步处理 UWB；不等待所有节点形成同步批次。
- Python 模拟器生成三车相同恒速平移编队：初始 3-4-5 几何、各车水平静止姿态、`angular_velocity=0`、`linear_acceleration=[0,0,+g]`，通过配置初速度产生平移，UWB 距离保持 3/4/5 m。另提供单车恒角速度和恒加速度单元测试数据，不把它们混入基础在线烟雾测试。

## 16. 测试顺序与验收条件

实施必须采用测试先行，每项生产行为先看到相应测试因缺少功能而失败，再写最小实现通过。

### 16.1 数学与单节点

- 四元数单位化、乘法、指数映射和旋转方向。
- 第一帧只建立基准。
- 水平静止输入在容差内保持零速度和零位移。
- 已知恒加速度得到解析位置和速度。
- 已知恒角速度得到预期姿态。
- 陀螺和加速度计零偏被正确补偿。
- 重复、乱序、异常间隔、NaN/Inf 和 frame 不匹配不改变状态。
- orientation 只在允许的首次初始化使用，运行中不重复融合。

### 16.2 联合滤波

- 15N 状态布局与节点顺序稳定。
- 单节点传播正确传播与其他节点的交叉协方差。
- 一条 UWB 更新同时修正两车并建立/改变交叉协方差。
- 合理 UWB 更新使距离残差下降；NIS 超门限只保留预测。
- 主参考输出恒为相对零，非参考输出和相对协方差公式正确。
- 每次预测和更新后协方差有限、对称且对角为正。
- 数值失败能够完整回滚。

### 16.3 接口与在线闭环

- C 头文件可以独立编译、初始化并调用 IMU 新接口。
- 旧 C ABI、UWB-only全部现有 C++/Python/CTest继续通过。
- IMU C++/Python黄金字节一致，错误保留位、错误长度、非法协方差被拒绝。
- IMU+UWB日志能够回放并重新产生Localization、Network和Alert。
- 三车模拟器、在线程序和GCS形成真实进程闭环；停止IMU或UWB后产生对应退化/陈旧状态，恢复后按状态机恢复。
- Windows 11 x64 Release重新构建和运行全部测试。
- Ubuntu 22.04 ARM64只有在真实AIBrainBox完成构建、测试和运行后才标记通过。
