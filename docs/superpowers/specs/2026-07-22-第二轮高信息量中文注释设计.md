# 第二轮高信息量中文注释设计

## 1. 目标与范围

本轮只修改 `cooperative_localization_online_demo` 工程内部的注释和说明文档，不调整算法公式、数据结构布局、协议字节格式、配置默认值或运行行为。目标是让首次接手工程的开发人员能够从注释理解模块职责、数据语义、关键状态变化以及容易误改的约束，而不是逐行翻译源代码。

覆盖范围包括：

- `include/`：公开 C ABI、导出规则和内部公共数据类型；
- `src/core/`：15维惯性传播、联合测距更新、质量监测、拓扑可观性、矩阵和四元数；
- `src/api/`、`src/apps/`：C ABI边界、在线运行、回放和输出适配；
- `src/config/`、`src/protocol/`、`src/net/`：配置、临时协议、日志和UDP封装；
- `src/self_check/`、`examples/`：自检调用链和SDK调用示例；
- `tools/`：模拟器、进程级测试、协议实现和GCS演示工具；
- `tests/`：测试场景、风险点和关键断言的意图；
- `CMakeLists.txt`、`cmake/`、`config/`：构建选项、安装/导出验证和参数分组；
- `docs/12_工程使用学习与编写思路.md`：明确各命令所属终端环境。

## 2. 注释层级

### 2.1 模块级说明

每个程序模块的文件头应回答：该文件负责什么、接收和产生什么、依赖哪个上游、服务哪个下游、明确不负责什么。涉及坐标、时间或协议时，同时注明ENU/FLU、纳秒时间轴、小端等不可隐含的约定。

### 2.2 类型与接口说明

公共结构体、类和非平凡函数应说明：

- 字段或参数的单位、坐标系、编号和时间语义；
- 所有权、生命周期、线程约束和数组容量约定；
- 调用成功后改变哪些状态，失败时是否保持原状态；
- 有效标志、枚举和协方差的解释方式；
- ABI或协议兼容性要求。

简单构造函数、显而易见的访问器和仅转发调用不强制写重复注释。

### 2.3 关键处理阶段

在下列高风险阶段前添加解释“为什么这样做”的注释：

- IMU时间顺序、瞬时量中值积分、重力补偿、名义状态传播、`Phi/Qd`和误差注入；
- 15N联合协方差块传播、距离雅可比、NIS门限、Joseph更新、交叉协方差和事务回滚；
- 观测质量窗口、降权/暂缓/剔除/试探恢复、边超时、可达性和二维刚度；
- C ABI头部、步长、对齐、两阶段输出容量、异常屏蔽和调用方内存所有权；
- 配置白名单、单位换算、组合约束和默认/显式回退模式；
- 协议帧长、字节序、CRC、有限值、保留字段及跨语言黄金字节；
- 在线进程收包、算法推进、输出、日志、关闭和回放时间调度；
- Python模拟数据的物理假设、异常注入、通过判据和资源清理。

数学注释应标明矩阵维度或状态块含义，但不重复每一项普通乘加运算。

### 2.4 测试注释

测试文件按测试组或场景解释它要防止的回归，例如重复包、未来时间、NLOS、容量查询、CRC破坏、链路超时和恢复。普通测试数据赋值、循环和直观断言不添加注释。

## 3. 禁止的低信息量注释

不添加以下类型的注释：

- “包含头文件”“进入循环”“变量加一”“返回结果”；
- 与函数名完全同义的说明；
- 逐个复述简单赋值或容器操作；
- 没有证据的性能、精度和盒端通过结论；
- 将当前临时ZJCL/UDP演示层写成最终ROS 2或无线协议；
- 用注释掩盖命名不清或行为不确定的问题。

## 4. 使用文档环境修订

`docs/12_工程使用学习与编写思路.md` 第3节拆分为：

- Windows 10/11 PowerShell：使用反引号续行、反斜杠路径和 `build-vscode/Release/*.exe`；
- Ubuntu 22.04 Bash：使用反斜杠续行、正斜杠路径和单配置 `build-arm64/*`。

两种环境都给出GCS、在线程序、IMU＋测距模拟器和自动烟雾测试命令。说明这些命令是无真实数据的软件闭环，不替代AIBrainBox、ROS 2、时间同步和实车验收。

## 5. 验证标准

1. 对生产代码逐文件检查模块级、接口级和关键阶段注释；
2. 检查新增内容没有低信息量逐行注释和未经验证的结论；
3. `git diff --check`无空白错误；
4. Windows Release重新构建成功；
5. `zju_coop_self_check`全部检查通过；
6. CTest全部通过；
7. Python工具单元测试全部通过；
8. 差异复核确认功能代码、配置值和协议布局未被本轮注释工作改变。

## 6. Git边界

仅提交本工程目录内的修改，提交说明使用中文，不推送远程仓库。本轮规格提交与后续实施提交分开，以便审查注释标准和实际改动。
