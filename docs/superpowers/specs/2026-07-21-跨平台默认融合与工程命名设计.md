# 跨平台默认融合与工程命名设计

## 目标

在不改变浙大算法 ABI 的前提下，把工程默认运行模式设为“IMU 瞬时量预测 + 平台间测距更新”，并把工程名称从强调单一传感器的名称改成通用协同定位名称。补齐 Windows 与 RK3588/Ubuntu 22.04 下 ROS 2 调用同一算法库的边界说明和中文注释，最后建立独立 Git 仓库并以中文提交信息保存当前版本。

## 跨平台代码边界

- `src/core`、`src/api`、`include/zju_coop`、配置解析和测试使用同一份 C/C++17 源码。
- Windows x64 编译得到 DLL/导入库，RK3588 ARM64 编译得到 ELF `.so`；二进制文件因操作系统、ABI 和处理器架构不同而不能互换。
- 上交 ROS 2 节点是适配层，负责把 `sensor_msgs/Imu` 和测距消息转换为 `zju_coop_imu_packet_t`、`zju_coop_range_packet_t`，调用 C ABI，再发布定位、网络和告警结果。算法库不依赖 ROS 2 消息类型。
- Windows 独立在线 Demo 通过临时 UDP 协议验证算法与 GCS；AIBrainBox 正式部署由上交在其 ROS 2 包中链接 ARM64 `.so`。若 Windows 安装相同 ROS 2 发行版，可复用 wrapper 源码，但需要重新编译。

## 默认配置和兼容模式

- `config/demo.ini` 改为三车 IMU+测距融合默认配置。
- 原仅测距配置改名为 `config/range_only_demo.ini`，保留回退与回归测试。
- 在线程序和回放程序默认参数继续使用 `config/demo.ini`，从而自然进入 IMU+测距模式。
- CMake 测试分别验证默认融合模式和仅测距兼容模式。

## 命名和注释

- 工程目录改为 `cooperative_localization_online_demo`。
- 不删除真实传感器语义：UWB 的 NLOS、测距标准差、模拟器和历史设计记录仍保留 UWB 名称。
- README 和交付说明以“协同定位”作为工程主名称，不把 UWB 写成系统唯一能力。
- C/C++ 文件增加中文文件职责、公开接口、单位、坐标系、状态顺序和关键分支注释；保留英文标识符以确保工具链和第三方调用稳定。

## Git 口径

目标工程当前不是 Git 仓库。本版在重命名后的工程根目录初始化独立仓库，使用 `.gitignore` 排除构建物、日志、缓存和本地安装包；提交信息使用中文。Git 作者沿用机器已有配置，如机器未配置则只在该仓库内设置项目级中文作者名，不修改全局配置。

## 验收

1. 默认配置解析为 `inertial.enabled=true`。
2. 仅测距配置仍解析为 `inertial.enabled=false`。
3. Windows Release 构建成功，C++、C 头文件、SDK、Python、默认融合在线烟雾测试和仅测距回归测试全部通过。
4. 安装树包含两个配置、C ABI 头文件、DLL 和运行说明。
5. Git 状态干净，初始提交信息为中文；不提交构建目录和日志。
