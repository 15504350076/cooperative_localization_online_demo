# ZJCL/ZJLG 临时在线协议说明

> 生产 AIBrainBox 优先采用“ROS 2 节点调用 C ABI，再通过 ROS 2/DDS 发布结果”。本文协议用于脱离 ROS 2 的 Windows/Ubuntu 进程联调，不可直接认定为正式 GCS 协议。

## 1. ZJCL 1.0 公共头

所有多字节整数和 IEEE-754 浮点数均为小端。公共头固定 40 B：

| 偏移 | 类型 | 字段 | 说明 |
|---:|---|---|---|
| 0 | char[4] | magic | `ZJCL` |
| 4 | u8 | major | 1 |
| 5 | u8 | minor | 0 |
| 6 | u16LE | message_type | 1/2/100/101/102/103/104/105 |
| 8 | u16LE | header_size | 40 |
| 10 | u16LE | flags | 当前在线/回放输出为 0 |
| 12 | u32LE | payload_size | 仅 payload 长度 |
| 16 | u64LE | sequence | 输入按数据流递增；算法输出按进程全帧递增 |
| 24 | u64LE | timestamp_ns | 测量时刻或算法快照时刻 |
| 32 | u16LE | source_node | 按消息类型解释 |
| 34 | u16LE | target_node | 按消息类型解释 |
| 36 | u32LE | crc32 | CRC-32/IEEE |

CRC 覆盖公共头字节 `[0,36)` 和完整 payload，不包含 CRC 字段本身。固定 payload 必须严格等长，禁止尾随字节。

通用 payload 硬上限为 1 MiB；UDP 数据报总长上限为 65,507 B，因此 ZJCL/UDP payload 最大为 65,467 B。

## 2. 消息类型

| ID | 名称 | payload | 方向 | 公共头节点映射 |
|---:|---|---:|---|---|
| 1 | Range | 24 B | 模拟器/盒端→online | source=from，target=to |
| 2 | IMU | 332 B | 模拟器/盒端→online | source=node，target=0 |
| 100 | Localization v1 | 64 B | online/replay→GCS | source=node，target=reference |
| 101 | Network | 20 B | online/replay→GCS | source=reference，target=0 |
| 102 | Observation | 80 B | online/replay→GCS | source=from，target=to |
| 103 | Alert | 40 B | online/replay→GCS | source=reference，target=0 |
| 104 | AlgorithmStatus | 48 B | online/replay→GCS | source=reference，target=0 |
| 105 | Pose2D | 32 B | online/replay→GCS | source=node，target=reference |

精确偏移、枚举和跨字段约束以 `src/protocol/wire_protocol.hpp/.cpp` 和 Python 参考实现 `tools/zjcl_protocol.py` 为准；两端均有固定字节测试。

## 3. 105 号 Pose2D 载荷

105 号消息用于当前最小 GCS 目标：显示以某一参考车辆为动态原点的三车二维相对位置和各车航向。payload 固定 32 B：

| 偏移 | 类型 | 字段 | 约束与单位 |
|---:|---|---|---|
| 0 | f64LE | x_m | `source-reference` 的 ENU 东向相对位置，m，必须有限 |
| 8 | f64LE | y_m | `source-reference` 的 ENU 北向相对位置，m，必须有限 |
| 16 | f64LE | yaw_rad | source 车体 FLU 前向 +X 的公共 ENU 航向，rad，`[-π,π)` |
| 24 | u8 | position_valid | 只能为 0/1 |
| 25 | u8 | yaw_valid | 只能为 0/1 |
| 26 | u16LE | reserved | 必须为 0 |
| 28 | u32LE | capability_mask | bit1=平面位置，bit3=航向；当前发送值为 `0x0000000A` |

总 ZJCL UDP 帧长度为 `40+32=72 B`。当 `position_valid=1` 时必须携带平面位置能力位；当 `yaw_valid=1` 时必须携带航向能力位。接收端必须拒绝 NaN/Inf、`yaw=+π`、非法布尔值、非零保留位、能力位与有效位冲突以及错误长度。

### 3.1 三车快照的组包口径

临时 UDP 每辆车发送一帧 105。三车属于同一快照的判据为：

- `timestamp_ns` 相同；
- `target_node` 相同，均为参考车编号；
- `source_node` 分别为三辆车编号；
- 三帧均通过公共头、长度、CRC 和 payload 校验。

UDP 可能乱序。GCS 应按 `(timestamp_ns, target_node)` 聚合，不得用到达顺序推断车辆顺序，也不得让旧时间戳覆盖新位姿。

当前浏览器看板默认 `--expected-pose-nodes 3`：只有同一 `(timestamp_ns,target_node)` 收齐三辆不同 `source_node` 后，才在同一把锁内更新全部车辆。未收齐的候选批次不会部分覆盖页面；旧历元不会回退当前快照；无效位置不会进入画布缩放或绘制。车辆数量变化时，启动看板必须显式调整该参数。

### 3.2 坐标和航向口径

设公共 ENU 下车辆 `i` 和参考车 `r` 的位置分别为 `p_i`、`p_r`：

```text
x_i = p_i.E - p_r.E
y_i = p_i.N - p_r.N
```

参考车位置固定输出 `(0,0)`。原点随参考车位置动态移动，x/y 轴始终与公共 ENU 东/北轴平行，不随参考车自身 yaw 旋转。

`yaw_rad` 是每辆车自身的绝对 ENU 平面航向。参考车也保留自己的 yaw；其他车辆不输出 `yaw_i-yaw_reference`。

如果三车无法形成同一非零 IMU 历元，发送批次的时间为 0，位置和航向有效位为 false。GCS 必须以有效位控制显示，不能把数值零自动解释为有效定位。

## 4. GCS 接收白名单

当前演示 GCS 消费 100–105。ID 1/2 是算法输入，GCS 收到时应忽略并记录接口越界。

- 105 是二维位置/航向显示的权威来源；
- 100 继续提供速度、协方差和定位状态，且 v1 `yaw_valid=false`；
- 101–104 提供拓扑、观测质量、告警和算法运行状态；
- GCS 不从 Observation 重新计算退化，不修改 `reason_mask` 或 `FusionAction`。

正式 ROS 2/DDS 接口可以把同一批三车数据放进一个数组消息；105 的逐车 UDP 形式只服务当前进程联调。

## 5. IMU 输入（message_type=2）

IMU 固定载荷为 332 B、小端：

```text
4d orientation_xyzw
9d orientation_covariance
3d angular_velocity_rad_s
9d angular_velocity_covariance
3d linear_acceleration_m_s2
9d linear_acceleration_covariance
32s frame_id
4B orientation_valid, valid, status, reserved
```

节点号、序列号和采样时间位于 40 B 公共头；接收时间由 online 进程本机记录。IMU 是瞬时角速度与瞬时比力，未做预积分；标准 ROS 2 Imu 不含温度，本协议也不增加温度字段。

当前理想演示由 `config/demo.ini` 的 `initial_yaw_rad` 提供各车相对同一公共 ENU 的初始航向，首帧建立时间基准，后续瞬时陀螺递推。该做法只验证软件最小闭环；真实初始对准、公共 ENU 建立和跨车时间同步由实车接口方案另行冻结。

## 6. Alert 生命周期

当前只定义 `alert_code=1 NETWORK_STATE`：

- 网络非正常且 `reason_mask!=0`：发送 ACTIVE；
- 异常持续：保持同一 first timestamp 并更新 last timestamp；
- 恢复正常：发送一次 CLEARED，`reason_mask` 清零；
- 正常持续：不重复发送 CLEARED。

## 7. AlgorithmStatus

online 按快照频率输出 ABI、软件版本、算法模式、运行状态、接受/拒绝测距累计数、协议错误累计数和 uptime。默认 IMU＋测距 15 维路径为模式 2；仅测距兼容模式为模式 1。

`accepted_ranges` 统计 `PROCESSING_PROCESSED`，其中可含通过协议和质量流程、但被 NIS 拒绝校正的包；`rejected_ranges` 统计其他处理结论；`protocol_errors` 只统计帧/payload 解码错误。计数仅在当前进程或本次回放生命周期内有效。

## 8. ZJLG 1.0

文件头固定 8 B：`ZJLG`、major=1、minor=0、header_size=8。每条记录为：

| 相对偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | u32LE | frame_length |
| 4 | u8 | direction：1 Input；2 Output |
| 5 | u8[3] | reserved，全 0 |
| 8 | u64LE | receive_timestamp_ns，本地记录时刻，非零 |
| 16 | bytes | 完整 ZJCL frame |

ZJCL CRC 不保护 direction 和本地记录时刻。日志轮转、保留周期、签名和记录时钟 epoch 尚未冻结。

## 9. 默认端口与边界

- Range/IMU 输入：`0.0.0.0:39001/UDP`；
- 结果输出：`127.0.0.1:39002/UDP`；
- 本机 GCS HTTP：`127.0.0.1:8080`。

端口可由 INI 或命令行配置。点云不通过当前 ZJCL 在线链路参与定位；C ABI 仅保留 PointCloud2 相容字段校验入口，当前未解析、未融合。

Windows 已具备 C++/Python 协议交叉测试、GCS 接收测试和本机 UDP smoke；Ubuntu 22.04 x86-64 已具备 ROS 2/Fast DDS 同机与 Gazebo 闭环证据。RK3588/AArch64、跨盒 DDS、真实 UWB/IMU 和实车链路尚未验证，正式接口不得用本协议的本机结果替代真机证据。
