# ZJCL/ZJLG 临时在线协议说明

> 生产盒端优先由上交ROS 2 wrapper直接调用C ABI；本协议用于脱离ROS 2的开发联调。

此协议只服务当前独立在线 demo。正式 AIBrainBox 集成以 C ABI 为稳定边界，上交可通过 ROS 2/DDS 或正式网关协议输出 GCS 数据；不得未经评审把临时 UDP 直接视为生产协议。

## 1. ZJCL 1.0 公共头

所有多字节整数和 IEEE-754 浮点数均为小端。公共头固定 40 B：

| 偏移 | 类型 | 字段 | 说明 |
|---:|---|---|---|
| 0 | char[4] | magic | `ZJCL` |
| 4 | u8 | major | 1 |
| 5 | u8 | minor | 0 |
| 6 | u16LE | message_type | 1/2/100/101/102/103/104 |
| 8 | u16LE | header_size | 40 |
| 10 | u16LE | flags | 当前在线/回放输出为 0；v1 尚未定义位语义 |
| 12 | u32LE | payload_size | 仅 payload 长度 |
| 16 | u64LE | sequence | Range 按有向节点对递增；算法输出按进程全帧递增 |
| 24 | u64LE | timestamp_ns | 测量/状态时刻 |
| 32 | u16LE | source_node | 按消息映射 |
| 34 | u16LE | target_node | 按消息映射 |
| 36 | u32LE | crc32 | CRC-32/IEEE |

CRC 覆盖公共头字节 0–35 和 payload，不包含头内 CRC 字段。固定 payload 必须严格等长，禁止尾随字节。

通用 payload 硬上限为 1 MiB；UDP 数据报总长上限为 65,507 B，因此 ZJCL/UDP payload 最大为 65,467 B。

## 2. 消息类型

| ID | 名称 | payload | 方向 | 头节点映射 |
|---:|---|---:|---|---|
| 1 | Range | 24 B | 模拟器/盒端→online | source=from，target=to |
| 100 | Localization | 64 B | online/replay→GCS | source=node，target=reference |
| 101 | Network | 20 B | online/replay→GCS | source=reference，target=0 |
| 102 | Observation | 80 B | online/replay→GCS | source=from，target=to |
| 103 | Alert | 40 B | online/replay→GCS | source=reference，target=0 |
| 104 | AlgorithmStatus | 48 B | online/replay→GCS | source=reference，target=0 |

精确偏移、枚举和跨字段约束以 `src/protocol/wire_protocol.hpp/.cpp` 与 Python 参考实现 `tools/zjcl_protocol.py` 为准；二者有 golden bytes 测试。

## 3. GCS 接收白名单

GCS 只消费 100–104。ID 1 是算法输入，不是 GCS 结果；收到时应忽略并记录接口越界。GCS 不从 Observation 重新计算退化，不修改 reason_mask 或 FusionAction。

## 4. Alert 生命周期

当前只定义 `alert_code=1 NETWORK_STATE`：

- 网络非正常且 reason_mask 非零：发送 ACTIVE；
- 异常持续：ACTIVE 保持同一 first timestamp 并更新 last timestamp；
- 恢复正常：发送一次 CLEARED，reason_mask 清零；
- 正常持续：不重复发送 CLEARED。

## 5. AlgorithmStatus

在线程序按配置的快照频率输出 ABI、软件版本、算法模式、运行状态、接受/拒绝测距累计数、协议错误累计数和 uptime；仅测距兼容模式为模式1，默认IMU＋测距15维路径为模式2。`accepted_ranges` 是 `PROCESSING_PROCESSED` 累计数，可包含 NIS 拒绝（包已处理但未做测量校正）；`rejected_ranges` 是其他处理结论累计数；`protocol_errors` 仅统计帧/payload解码错误。online 的 uptime 是稳态运行时长；回放 `stream` 沿日志时间轴按同一配置输出并以日志经过时间为 uptime，`final` 只发最终快照且是默认模式，`none` 不发送 UDP。所有计数只在当前进程或本次回放生命周期内有效。

## 6. ZJLG 1.0

文件头固定 8 B：`ZJLG`、major=1、minor=0、header_size=8。每条记录为：

| 相对偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | u32LE | frame_length |
| 4 | u8 | direction：1 Input；2 Output |
| 5 | u8[3] | reserved，全 0 |
| 8 | u64LE | receive_timestamp_ns，本地记录时刻，非零 |
| 16 | bytes | 完整 ZJCL frame |

ZJCL CRC 不保护 direction 和本地记录时刻。日志轮转、保留周期、签名和记录时钟 epoch 尚未冻结。

## 7. 默认端口

- Range 输入：`0.0.0.0:39001/UDP`；
- 结果输出：`127.0.0.1:39002/UDP`；
- GCS HTTP 页面：`127.0.0.1:8080`。

以上均可通过 INI 或命令行配置。

## 8. IMU输入（message_type=2）

IMU固定载荷为332字节、小端，格式为：

```text
4d orientation_xyzw
9d orientation_covariance
3d angular_velocity_rad_s
9d angular_velocity_covariance
3d linear_acceleration_m_s2
9d linear_acceleration_covariance
32s frame_id
4B orientation_valid, valid, status, reserved
```

节点号、序列号和采样时间仍在40字节ZJCL帧头中；接收时间由在线进程本机记录，不在网络载荷中传输。`frame_id`必须非空且NUL结尾，`reserved=0`，status为0/1/2。标准ROS 2 Imu不含温度，协议也不增加温度字段。

Python参考格式是 `struct.Struct('<4d9d3d9d3d9d32s4B')`，C++和Python测试共同锁定332字节布局。AlgorithmStatus在惯性配置下输出模式2（IMU_UWB_15_STATE），UWB-only继续输出模式1。
