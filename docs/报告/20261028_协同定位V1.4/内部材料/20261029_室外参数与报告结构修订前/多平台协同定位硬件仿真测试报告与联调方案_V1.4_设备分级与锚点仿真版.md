## 1 项目概况与技术路线

### 1.1 项目概况

本项目已形成三盒传感器采集、协同定位系统主盒（系统中称为201盒）在线相对位置输出、联合录包和离线复现工具链。当前运行基线使用超宽带测距（Ultra-Wideband，UWB）恢复三车相对三角形；惯性测量单元（Inertial Measurement Unit，IMU）数据和相对变换估计（Relative Transformation Estimation，RTE）算法库已形成独立试验入口。

现有消息接口、三盒数据、在线输出和离线回放程序可用于通信、显示和决策模块联调。本轮进一步按设备组合、输入精度和场地布设条件开展仿真，比较增加哪类输入能够带来多大的位置误差改善。

表1 当前能力与联调范围

| 能力层次 | 当前状态及材料 | 现在能开展什么 |
|---|---|---|
| 三盒硬件与数据 | 三盒UWB、车载IMU、Livox点云和三盒三目视觉采集与测试数据已完成采集与归档 | 真实输入、录包回放、通信承载和接口核对 |
| 在线相对位置 | 实测输出约9.24～9.42赫兹，形成三车相对位置与队形显示 | 相对队形显示、编号对应、有效位、断流提示联调 |
| 动态相对位姿 | 本地惯导、独立RTE库及三车节点已实现；保留既有RTE基线，完成84种条件、1680次单锚点与传感器分级仿真 | 比较惯性、视觉/雷达运动输入与唯一UWB锚点，开展动态实车验证 |
| 整体任务闭环 | 消息接口、仿真场景和硬件在环接入方案已经形成 | 开展接口联调和联合试验 |

现有消息接口、硬件采集、在线输出和回放程序可直接用于联调准备；实测统计和带真值仿真结果分别归档，便于后续运动试验继续使用。

### 1.2 技术路线与系统关系

面向卫星导航拒止条件下的空地多平台协同定位任务，通信交换状态信息，定位模块输出车辆相对位置和状态信息，决策、规划与控制模块据此完成任务计算。定位输出包含位置、参考系、时间和有效性字段。

UWB提供车间距离，IMU提供姿态和短时运动连续性，RTE利用运动中的里程计与测距序列对齐各车局部坐标系。本阶段已完成点云和图像采集；这些数据后续需按特征提取、标定和甲方实车调试流程接入。

![图1 协同定位系统组成](figures/01_系统与联调边界.png)

当前UWB基线以参考车为原点、以车1到车2的连线方向建立相对三角形，用于三车几何显示和消息接口联调。需要地图坐标时，系统通过参考车局部坐标到任务坐标的变换输出相应位置。

### 2.2 单锚点与传感器分级仿真

本轮把设备类别、运动输入精度、测距精度和约束增加过程分别比较。传感器包括IMU、视觉惯性里程计（Visual-Inertial Odometry，VIO）和激光惯性里程计（LiDAR-Inertial Odometry，LIO）。VIO由相机与IMU提供局部运动，LIO由雷达与IMU提供局部运动，因此两类方案均包含IMU。

试验在开发电脑实际执行仿真程序。模拟器生成含误差的加速度、角速度、局部位移和UWB距离；初始化及位置估计程序读取这些测量计算结果。VIO/LIO在本轮采用位移输出模型，参数直接作用于局部运动增量；相机图像、雷达点云的特征提取与前端处理在实车接入时开展。

每类运动输入设基础、增强、精细三档；各档分别搭配10、5、2厘米测距噪声，并比较三种后续处理。九种运动输入、三档测距、三种处理共81种条件；另用默认UWB库计算三档纯测距队形，共84种条件。每种条件20次，合计1680次。各方案共享相同编号的测距扰动；同一档位的三种处理使用完全相同的传感器输入与初始化结果。

表3 运动输入精度设定

| 运动输入及档位 | 仿真误差参数 |
|---|---|
| IMU 基础 | 残余加速度零偏0.010米/秒²；角速度零偏0.000150弧度/秒；加速度白噪声0.050米/秒² |
| IMU 增强 | 残余加速度零偏0.003米/秒²；角速度零偏0.000050弧度/秒；加速度白噪声0.020米/秒² |
| IMU 精细 | 残余加速度零偏0.001米/秒²；角速度零偏0.000015弧度/秒；加速度白噪声0.010米/秒² |
| VIO 基础 | 尺度标准差0.5%；航向漂移标准差0.0001弧度/秒；位移随机项0.03米/√米 |
| VIO 增强 | 尺度标准差0.2%；航向漂移标准差3e-05弧度/秒；位移随机项0.015米/√米 |
| VIO 精细 | 尺度标准差0.05%；航向漂移标准差8e-06弧度/秒；位移随机项0.005米/√米 |
| LIO 基础 | 尺度标准差0.2%；航向漂移标准差5e-05弧度/秒；位移随机项0.015米/√米 |
| LIO 增强 | 尺度标准差0.05%；航向漂移标准差8e-06弧度/秒；位移随机项0.005米/√米 |
| LIO 精细 | 尺度标准差0.02%；航向漂移标准差3e-06弧度/秒；位移随机项0.002米/√米 |

IMU参数对应静止初始化后的残余误差，加速度与角速度白噪声按100赫兹采集、10赫兹平均量设置；角速度白噪声标准差统一为0.0005弧度/秒。VIO/LIO的尺度与航向慢漂移在每次运行中独立生成，位移随机项按单步行驶距离的平方根增长。档位用于比较输入质量，不与某一硬件型号直接等同。VIO精细档与LIO增强档采用相同位移输出误差参数，因此对应结果相同；同等输入质量时，可结合视场、算力和成本选择前端。

三车采用300秒轨迹，前30秒静止，随后在约85×115米范围内运动；最高车速约2.39米/秒，最大车间距约24.56米。唯一锚点放在运动区域中部，场景坐标为（55，75）米，最大车锚距离约66.16米。全部UWB链路连续生成，每条10赫兹，共每秒60条测距，测距误差为零均值独立噪声。仿真采用平面视距工况，三车车载参考点与UWB天线在模型中重合，锚点和车载天线按同高平面处理。

初始化使用0～60秒的六条测距及局部运动，不预先给定各车位置与朝向。程序同时求三车起点位置和各自局部坐标转角，用测距残差选择初始解；真值不参与这一过程。60秒之后才计入本轮位置误差。三个对照分支从同一初始状态继续运行，见表4。

表4 逐项增加约束的比较

| 处理方式 | 0～60秒 | 60～300秒 |
|---|---|---|
| 起点结果＋运动传播 | 六条测距与本车运动共同初始化 | 仅使用本车运动输入 |
| 继续使用车间UWB | 使用相同初始化结果 | 本车运动＋三条车间测距 |
| 继续使用车间UWB＋单锚点 | 使用相同初始化结果 | 本车运动＋三条车间测距＋三条到同一锚点的测距 |
| 默认纯UWB队形 | 读取三条车间测距 | 逐时调用现有C++三角形求解库 |

位置均方根误差（Root Mean Square Error，RMSE）按202、203车相对201车的位置向量与同一时刻真值之差合并计算。表中范围为20次运行RMSE的最小值至最大值。单锚点组使用固定局部坐标轴，纯UWB使用原规范队形坐标，分别与各自坐标的真值比较。真值只用于模拟传感器与事后评价，输出没有经过真值轨迹配准或事后平滑。

### 2.3 既有RTE基线仿真

### 3.4 位置显示与更新检查

默认UWB位置显示读取位置有效标志position_valid。现有监视界面在1秒内没有新的有效位置时显示不可用，1秒内没有收到消息时显示断流。消息头时间戳用于判断测量时间是否前进，接收端本机时钟用于计算断流持续时间。

RTE状态话题提供初始化标志（initialized）、计算状态（status）、结果时间（timestamp_ns）、参与计算的测距边数（active_edges）和测距拟合残差（rms_m）。运行时可结合这些字段查看三车状态是否收到、初始化是否完成以及测距是否持续参与计算。

### 3.5 C/C++程序调用

默认UWB库为zju_coop，公开头文件为include/zju_coop/c_api.h；RTE库为zju_coop_rte，公开头文件为include/zju_coop/three_vehicle_rte_api.h。两套库可以分别构建和调用。

RTE程序先调用zju_coop_three_config_init_rte载入默认参数，再调用zju_coop_three_create_rte创建计算对象。运行过程中，用zju_coop_three_push_node_state_rte送入各车局部位姿，用zju_coop_three_push_range_rte送入车间测距；调用zju_coop_three_step_rte进行计算，再用zju_coop_three_get_pose2d_v2_rte读取三车位置。结束时调用zju_coop_three_destroy_rte释放对象。结构体先用头文件中对应的初始化函数赋初值，位置可用状态从返回的快照读取。

### 5.2 RTE跳变与图14的含义

图14固定展示既有300秒场景中“无误差里程计、2厘米测距噪声、重复试验1”的计算过程。上图为202、203车相对位置误差，中图为滑动窗口的测距拟合均方根残差，下图为同一当前里程计位置经过修正前、后坐标变换所得的位置差。三幅图横轴均为仿真时间，纵轴均以米计；竖线对应147.60秒和294.48秒的修正时刻。初始化之前和无有效输出时段留空。

294.48秒时，203车坐标变换修正引起约2.76米的位置变化；位置误差由0.646米变为2.117米，而测距拟合残差由0.0176米变为0.0171米。修正次数同时由697变为698。重建该5秒窗口后，计算得到相同的测距残差，部分平移分量的估计标准差达到约1.66米，说明这一窗口对坐标变换的约束较弱。

程序每次滑窗求解后直接更新相对平移和转角。初次建系之后，输出会随新窗口解变化；当前实现对后续修正没有增加连续位置先验或单次位移约束。因此，某些窗口虽然仍能较好拟合车间距离，更新后的相对位置却会发生突变。跳变来自该次坐标变换更新，不能由测距残差的大小单独判断。

图14下图的修正变化由输入里程计和输出变换重建，不通过滤波平滑曲线。本轮单锚点对照采用运动传播和逐次测距更新，逐时位置误差见图21，位置更新幅度与测距残差见图25。图15仍保留既有RTE轨迹与真值的对照。

## 6 阶段结论与实车试验

### 6.1 三盒联机运行

计算盒接入后，沿用现有连接方式：201盒通过网线连接调试电脑，202、203盒通过自组网连接201盒，地址分别为192.168.2.202和192.168.2.203。先运行默认UWB程序，在调试电脑查看三车位置和测距，再按第4.2节启动独立RTE程序。

RTE运行时，三盒各自处理本地IMU并发送局部位姿；201盒接收三车局部位姿和车间测距，计算相对位置。通信与规划控制程序可订阅201盒的位置输出。联机试验同时记录三盒输入、201盒输出以及消息更新间隔，检查自组网传输后能否连续收到三车结果。

硬件在环试验可沿用现有300秒仿真输入，将各车局部里程计和UWB测距送入对应计算盒，由201盒运行同一套定位库。仿真真值保存在开发电脑，用于比较盒端计算结果与原离线结果；接入规划控制后，再由仿真器根据控制指令更新车辆运动。

### 6.2 实车运动采集

首轮只布置一个已知位置的UWB点，使用固定地标或已落地并保持静止的无人机承载。记录该点坐标及天线高度，三车分别与它测距，同时保留原有三条车间测距。按同一段低速数据比较IMU、VIO、LIO输入和六条测距的融合结果。

实车试验按开发阶段的低速工况展开，车速不超过3米/秒，最大车间距控制在20～30米。采集包含静止、起步、直行、转弯和编队整体移动，并适当改变车间相对位置，使后续RTE试验具有可辨识的相对运动。

安装后测量UWB天线、IMU、雷达和相机相对车体的位置与朝向，填写对应配置。点云和图像结合实车视场、安装位置开展标定与特征提取调试。联合录包继续保存三盒UWB、车载IMU、Livox和视觉数据，并补录定位输出。

运动采集配合独立位置测量设备，例如载波相位差分定位（Real-Time Kinematic，RTK）设备或全站仪，记录其时间、安装位置和测量误差。计算车2、车3相对201盒的位置真值，再与同一时刻的定位输出比较。试验继续围绕亚米级相对定位目标开展，结果分别列出逐车均方根误差、95%误差、最大误差和实际参与统计的样本数。

### 6.3 通信与规划控制接入

通信侧传送车辆编号、局部位姿和测距；规划控制侧读取第3章的位置消息，按车辆编号匹配各车，并读取位置有效标志和结果时间。采用默认UWB输出时，坐标轴沿201盒至202盒连线；采用RTE固定相对坐标输出时，坐标轴沿首次有效定位时201盒至202盒的方向，并在本次局部里程计中保持固定。

使用地图坐标进行规划时，结合实车摆放和方向测量确定坐标变换，将相对位置换算到地图方向，再加上201盒在地图中的位置。联调时用相同一段数据同时显示定位输出、规划轨迹和控制指令，检查车辆编号、坐标方向及更新时间是否对应。随后在低速实车上记录实际运动与定位输出，逐步完成三车联合运行。

### 6.5 阶段结论

现阶段已形成三盒采集、默认UWB队形定位、独立RTE库、消息接口和仿真复现工具。六组静止实测用于采集、回放和输入分析；本轮按一个已知位置UWB点完成84种条件、1680次分级仿真，输入、初始化、完整输出和逐次误差均已保存。

5厘米测距下，IMU增强档配合三条车间测距及单锚点的相对位置RMSE为0.097～2.027米。5厘米测距下，VIO增强档配合三条车间测距及单锚点的相对位置RMSE为0.036～0.135米。5厘米测距下，LIO增强档配合三条车间测距及单锚点的相对位置RMSE为0.019～0.041米。

默认纯UWB在相同评价时段的三档测距结果为0.037～0.039、0.093～0.099、0.187～0.197米，继续用于现有相对队形输出。VIO/LIO输入在本轮对应的参数条件下给出亚米级相对位置结果；完整档位范围见表9。按所需坐标稳定性、运动输入条件和预算选择组合，实际设备复测后再确定实施配置。

单锚点仿真从测距与运动输入共同求起点关系，输出固定局部坐标中的连续位置；原默认UWB坐标及原RTE程序保持不变。后续以同一个UWB点开展低速实车采集，结合安装标定、前端处理和独立位置真值验证，将相对位置、坐标系和测量时间接入通信、规划与控制模块。
