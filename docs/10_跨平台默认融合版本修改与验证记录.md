## 2. Windows 编译和验证

环境：Windows 11、Visual Studio 2022/MSVC 19.41、Windows SDK 10.0.26100、CMake、Python 3.11.9。

```powershell
cmake -S . -B build_cross_platform -DBUILD_TESTING=ON
cmake --build build_cross_platform --config Release --parallel
cmake --build build_cross_platform --config Release --target RUN_TESTS
```

结果：Release 构建成功；CTest 6/6 通过，包含 C++、C 头文件、SDK 消费者、Python、仅测距在线回归和默认 IMU＋测距在线烟雾测试。

```powershell
build_cross_platform\Release\zju_coop_tests.exe
D:\python311\python.exe -B -m unittest discover -s tools -p test_*.py
```

结果：C++ 161 项、失败 0；Python 27 项、失败 0。

不传 `--config` 启动 `zju_coop_online --duration-ms 120` 成功读取默认配置，日志路径为 `logs/cooperative_localization_demo.zjlg`。安装验证生成 DLL、导入库、两个可执行文件、C ABI 头文件、默认融合配置、仅测距回退配置、文档和工具。

## 3. Windows 与 RK3588 调用结论

- 同样：C/C++17 算法源码、`c_api.h`、结构体、单位、坐标系、配置字段、函数调用顺序和 ROS 2 字段映射。
- 不同：Windows 编译为 x86-64 DLL，RK3588 编译为 AArch64 `.so`；二进制不能互换。
- ROS 2 wrapper：业务源码可复用，但必须在各平台匹配的 ROS 2 发行版和消息包环境中重新编译。
- 正式盒端：上交 wrapper 订阅 ROS 2 消息、完成时间同步/坐标变换并调用浙大 C ABI；浙大算法核心不直接依赖 ROS 2。
