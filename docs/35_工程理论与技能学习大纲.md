# 35 工程理论与技能学习大纲（本科基础·工程入门到熟练）

适用工程：浙大—上交多无人平台协同定位工程。整理日期：2026-09-10。

用途：作为学习路线和其他对话的教学上下文。本文规定“需要学什么、学到什么程度、拿什么练习、参考谁”，不是把所有理论一次讲完，也不是当前实测验收报告。

读者假设：**有大学本科基础，数学和物理按本科课程水平衔接；不默认熟悉机器人、惯导、状态估计、ROS 2 或本工程的软件开发工具。** 微积分、线性代数和概率中不熟悉的部分按需复习，不要求从初等算术重学。编程熟练度不预设，可通过小练习判断需要补哪些内容。

覆盖范围：不仅是核心定位公式，也包括本工程的操作工具、数据格式、编程、硬件接口、通信、时间、仿真、显示、测试、部署，以及已有的历史/可选功能。列入大纲不表示都要立即启用，更不表示都已经完成实测验证。

**推荐顺序：用第 0 节检查知识缺口，直接进入第 2 节的工程主线，缺什么补什么。** 已掌握的基础不必重复学习；重点是本科知识如何用于传感器、估计模型与实际程序。本文中的“选学”是学习深度和时间安排，不是遗漏该部分。

## 0. 本科基础衔接与按需补课

Z1～Z8 是复习与工具补课目录，不是必须全部重修的先导课程。数学侧默认具备本科基础，专业侧从原理讲起；若某个概念已经理解且能完成练习，直接跳过。

### 0.1 学习深度怎么区分

- **认识**：能用自己的话说出是什么、在哪里用、不是什么。
- **会用**：能独立执行步骤、解释输入输出、处理常见错误。
- **会算**：能用小例子和公式复现计算，说明前提和单位。
- **会改**：能读对应源码、做最小修改、补测试并验证结果。

目标是主链路达到“会改”，其余工程组件至少“认识”，负责维护时达到“会用/会改”。不要求先成为所有领域专家。

### Z1 操作系统与开发环境：按需补齐工具知识

重点检查：能否区分开发电脑与盒端的运行环境，理解命令执行位置、依赖和文件路径。一般电脑操作不再作为必修。

1. 硬件与软件；CPU、内存、硬盘、网卡；普通电脑与嵌入式计算机。盒子也是运行操作系统的计算机，不只是一个传感器。
2. Windows 与 Ubuntu/Linux；桌面、程序、进程、终端、Shell、命令；VS Code 编辑器不等于 Python 或编译器。
3. 文件/文件夹、扩展名、文本/二进制文件；绝对/相对路径、当前目录、盘符；Windows `\` 与 Linux `/`。
4. 用户、主目录、管理员权限、文件读写/执行权限；为什么不应遇到问题就加 `sudo`。
5. 软件安装、依赖、版本、环境变量；下载源码不等于安装完成，编译成功不等于已经运行。
6. 压缩/解压、复制/移动、备份；原始数据、分析副本和程序文件分别保存。

小练习：说明一个分析脚本在 Windows 电脑和 Ubuntu 开发机上分别需要什么环境、输入在哪里、输出在哪里。路径或权限操作不熟时再补基础练习，不在盒子上试删改命令。

参考：[VS Code 入门](https://code.visualstudio.com/docs/getstarted/getting-started)。先理解编辑器的文件树、编辑区、终端和状态栏。

### Z2 工程单位、角度与数据图像：快速复习

1. SI 单位与量纲检查，尤其是 rad/s、deg/s、deg/h、m/s² 和噪声密度单位。
2. 秒/毫秒/微秒/纳秒、采样频率与采样间隔；科学计数法在配置和程序中的表示。
3. 角度与弧度、`atan2` 的象限和角度回绕；三角函数和余弦定理直接用于姿态与测距几何。
4. 时间序列的斜率、积分面积、对数坐标；区分原始值、差分值、累计误差和统计量。
5. 测量值的有效数字与数值精度；输出很多小数位不等于传感器精度很高。

小练习：算出 1000 Hz 的理想采样间隔，换算 0.01 rad/s 为度/秒；画一条恒定角速度曲线和对应随时间变化的角度曲线。

参考：[Khan Academy 数学课程](https://www.khanacademy.org/math) 仅作遗忘知识的查询入口；本科数学已掌握时，不必重学基础代数与三角函数课程。

### Z3 Python 与科学计算：按编程基础补齐

已有编程经验者直接检查文件处理、NumPy、绘图和环境管理；没有编程经验者再按下面顺序学习语法。

1. 程序、算法、输入、处理、输出；解释器怎样按顺序执行语句。
2. 数字、字符串、布尔值、变量、赋值；等号赋值与数学等式/比较的不同。
3. `if` 判断、`for/while` 循环、列表、字典、索引；零下标和边界。
4. 函数、参数、返回值、局部变量、模块与 `import`；先会调用再看实现。
5. 文件读取、CSV 行与列、路径；打印、断点、错误提示、异常、逐步缩小问题。
6. 包与依赖、`pip`、虚拟环境、Python 版本；调用的是哪个 Python。
7. 再进入数组运算 NumPy、绘图 Matplotlib；不要求先学习复杂面向对象或网络开发。

小练习：读一列手写的角速度数据，求均值，逐项减去均值，打印结果并画图。先用十个数字，理解后再处理几十万条实包消息。

参考：[Harvard CS50P：Python 入门](https://cs50.harvard.edu/python/)、[Python 中文教程](https://docs.python.org/zh-cn/3/tutorial/)、[Matplotlib Tutorials](https://matplotlib.org/stable/tutorials/index.html)。CS50P 适合作为主课，其他资料按需查询。

### Z4 微积分与力学：从连续模型到离散惯导

1. 复习位置、速度、加速度的微分关系；重点从连续运动方程过渡到离散数据处理，不重讲极限与求导入门。
2. 离散采样、差分与求和；时间间隔不均匀时不能假设每帧都是 1 ms。
3. 多变量函数、偏导数、梯度、Jacobian；Taylor 展开为什么可以局部近似非线性函数。
4. 常微分方程、初始条件、Euler 与中点积分；学到能理解惯导状态递推即可。
5. 质点与刚体、平移与旋转、重力、加速度计支撑力/比力的直觉。
6. 质心、机体原点、传感器安装点；旋转时不同安装位置可能有不同线加速度，认识角加速度和向心项。

小练习：同一个恒定角速度，换两种采样间隔积分出相同总转角；再加入固定偏置，观察误差随时间累积。

参考：[MIT 18.01SC 单变量微积分](https://ocw.mit.edu/courses/18-01sc-single-variable-calculus-fall-2010/) 用于按需复习，不要求完整重修；当前也不要求先学完整刚体动力学与控制器设计。

### Z5 线性代数与概率：衔接状态估计

默认接触过向量、矩阵和概率分布，重点检查能否用它们解释坐标变换、误差传播与不可观方向，再进入 M5。

1. 标量、向量、矩阵的形状与运算；行/列、长度、单位向量、基、坐标。
2. 点积与夹角，叉积与垂直方向；旋转矩阵为什么保持长度。
3. 转置、逆、线性方程、秩、零空间；之后才学习特征值、SVD 与正定性。
4. 样本、总体、频率、概率、随机变量；均值、方差、标准差、高斯分布。
5. 两个误差是否一起变化：协方差、相关性、独立性；条件概率与 Bayes 思想。
6. 噪声与固定偏置的区别；精密度/重复性与准确度的区别。

小练习：画出两个均值不同但波动一样的数据集，以及两个均值一样但波动不同的数据集。说明只看标准差会遗漏什么。

参考：M5 的 MIT 线性代数和概率课程。Z5 用于检查本科知识缺口，M5 围绕工程中的数值计算和估计公式深化，不必重复学习相同内容。

### Z6 网络与远程操作：先分清在哪台机器上做事

1. 网络、网卡、局域网、Wi-Fi、有线网络、路由器；能通信需要网络可达，不是必须同一个 Wi-Fi 名称。
2. IP 地址、子网、网关、端口、客户端/服务器；一台盒子为什么有多个 IP。
3. DHCP 自动分配与静态配置；`192.168.1.203` 在现场约定中用来访问盒3，但数字本身不编码“车辆身份”。
4. 远程桌面控制上交电脑、再从上交电脑 SSH 到盒子，是两层连接；MobaXterm 是客户端工具。
5. `firefly@...` 中的用户名、目标地址、登录提示符；SSH、SCP/SFTP、公钥、私钥、主机指纹。
6. 开多个终端不等于启动多个传感器；断开终端、进程退出、硬件断电是不同事件。

小练习：画出“自己的电脑 → 上交电脑 → 三盒”的连接图，分别标明命令在哪台机器执行、数据存在哪台机器。然后只做只读登录检查。

参考：M1 的 Missing Semester 与第 30 文档；TCP/UDP 和本项目数据通信在 M15 深入。

### Z7 C/C++ 从入门到能读工程

1. 源码、编译器、目标文件、链接器、可执行程序；`.h/.hpp`、`.c/.cpp` 是什么。
2. 基本类型、整数范围、有符号/无符号、浮点、布尔值；数组、字符串、条件、循环、函数。
3. 内存地址、指针、引用、对象生命周期；栈/堆的基本区别；先掌握安全使用，不必从复杂内存优化开始。
4. `struct/class`、构造函数、成员、`const`、命名空间；读懂“一个状态对象持有哪些值”。
5. `std::vector/array/string`、枚举、模板的基本用法、智能指针、RAII；读懂 `std::variant` 表达多种消息载荷。
6. 声明/定义、头文件依赖、库、链接错误；C++ 接口与 C ABI 的区别。
7. `CMakeLists.txt`、Debug/Release、编译警告、断点、测试。先进一个小程序，再读正式滤波器。

小练习：把 Z3 的“十个角速度求均值并扣除”改写成 C++，拆成函数和头文件，编译运行，对比 Python 输出。

参考：[LearnCpp](https://www.learncpp.com/)（从 Getting Started 开始）、[CS50x](https://cs50.harvard.edu/x/)（需要更系统计算机基础时选学）、M12 的 CMake 教程。两门入门主课不必同时刷完。

### Z8 文档、代码和实验怎么一起学

1. Markdown 标题、列表、表格、链接、代码块；LaTeX 中上下标、向量、求和、分数等符号的阅读。
2. README 是入口，配置描述本次运行条件，日志记录发生了什么，报告解释结果，源码定义实际行为。
3. 搜索文件、跳转定义、查看引用、读调用链；一次跟踪一个输入，不逐行通读所有文件。
4. 假设、观察、证据、结论与局限；“可能”与“已确认”要区分。
5. 每课记录：新名词、一个手算例子、一段小程序、一道自己能回答的问题。

小练习：写一页 Markdown，记录 Z3 的输入数据、程序、运行命令、输出和你能得出的结论。此后每个实验沿用这个结构。

## 1. 给其他对话的工程背景

把本文单独发给其他对话时，请让对方先读本节，避免脱离现有条件设计另一套系统。

### 1.1 我们要解决什么问题

- 对象是多个无人平台，目前用三个上交盒子进行传感器与接口测试，后续安装到车辆。
- 已有 IMU 和普通 UWB 测距；激光雷达、视觉是可用的后续扩展。当前讨论不依赖已有地图、卫星导航，也不自行新增磁力计、双天线 GNSS、UWB 测角阵列等硬件。
- 每个平台一个普通 UWB 标签。测距给出标签之间的距离，不直接给出方位角或车头朝向。
- 目标包括：三车队形恢复、相对位置估计、连续相对运动估计，以及明确各种“编队角度”究竟相对哪个坐标系。
- 无绝对方向参考时，不能把人为定义的水平轴直接称为真实东向或北向。相对定位可用，不等于绝对航向可观。

### 1.2 软件大致组成

| 层次 | 当前工程的学习对象 | 不能混淆的概念 |
|---|---|---|
| 传感器与驱动 | 上交 IMU/AHRS、UWB、串口、授时、ROS 消息 | 驱动启动 ≠ 数据有效；消息名称正确 ≠ 单位和时间正确 |
| 算法核心 | C++ 惯性传播、静止初始化、UWB 几何、滤波、可观测性检查 | 实现了公式 ≠ 实测精度已达标 |
| 协同架构 | 集中式联合滤波基线、各车本地惯导和参考车协同修正 | 分布式传状态 ≠ 保留了完整联合协方差 |
| 接口与部署 | C ABI、ROS 2 适配、配置、网络、地面站 | 通信域一致 ≠ 时钟同步 |
| 测试与分析 | 合成数据、Gazebo、实测 rosbag、Python、CSV、Foxglove | 单元测试通过 ≠ 实包验证通过 ≠ 实车验收通过 |

上交主要提供和维护盒端传感器、驱动及消息输出；浙大主要负责接入、算法、分析与验证。时间、坐标、单位和身份映射需要双方共同明确。不要用算法端随意改时间、翻轴或减常数来掩盖尚未查明的接口问题。

### 1.3 必须带着学习的事实边界

1. 当前 IMU 不以地球自转寻北作为初始化前提。静止重力能提供横滚/俯仰信息，启动 yaw 为零只是选择初始方向，不等于对准北方。
2. 上交反馈载体系为前右下 FRD、导航习惯为 NED、欧拉角顺序为 Z-Y-X。还必须明确四元数映射方向、分量顺序，以及 ROS 输出是否做过转换；“习惯 NED”不证明 yaw 零对应真实北向。
3. 工程核心使用前左上 FLU 及向上的导航坐标约定。代码中有 ENU 命名，但没有绝对航向初值时，学习和解释结果应称为“重力对齐的局部坐标系”，不能赋予真实东、北意义。
4. 静止均值估陀螺启动零偏与 AHRS 内部在线补偿不是一回事。上交四元数与上交陀螺输出可能共享同一传感器，不是两套独立真值。
5. 三条距离可以定义三角形形状，但不能单独恢复车辆自身朝向、真实北向，或编队相对一个固定世界轴的整体转动。
6. 当前集中式基线和分布式路径要分别理解，不能把其中一种的状态、观测模型或验证结果自动套到另一种。
7. 雷达/视觉相关模块和示例存在，不代表已经完成与主协同滤波链路的正式融合。

项目具体接口和算法状态，以当前源码、配置及对应实验报告为准；其他对话如果没有这些文件，应要求提供片段，而不是猜测当前实现。

## 3. 分模块学习大纲

### M1 Linux、SSH、Python 与版本管理

要回答：一条命令在哪里执行，影响的是电脑还是盒子，为什么不同终端能有不同结果？

参考：[MIT Missing Semester](https://missing.csail.mit.edu/)（Shell、调试与工具）、[Python 中文教程](https://docs.python.org/zh-cn/3/tutorial/)（语言基础）、[Pro Git 中文版](https://git-scm.com/book/zh/v2)（版本管理）。Python 语法和依赖需兼容实际运行机，不直接照搬最新版特性。

### M4 多平台时间同步与异步数据融合

要回答：三盒是否真的在同一时间轴上？同时启动、同时接收为什么都不够？

必须学习：

- 测量时刻、设备计数器、ROS `header.stamp`、主机接收时刻、bag 时间、播放时间。
- UTC、时区、Unix 时间、上电相对时间、模拟 RMC 日期基准；PPS 秒脉冲提供秒边界，日期/秒编号仍需配套信息。
- 时钟偏移、频率偏差、漂移、重置和跳变；最简单的时钟模型：

$$
t_i = a_i t_{\mathrm{ref}} + b_i + \epsilon_i .
$$

- 网络传输延迟不是时钟偏移：在已经统一基准的前提下，接收时间减测量时间仍包含驱动、排队和网络延迟；基准未统一时还包含时钟差。
- 时间单调性、重复、乱序；`+1001 ms` 是相邻时间向前跨了约一秒，负差才是时间回退。
- 时间配对、插值、外推、缓存、观测过期；固定相减只能校正已证实的固定偏移，不能解决跳变与频率误差。
- NTP/chrony、PTP、硬件 PPS 的作用边界。主机时间同步不自动同步独立设备计数器或驱动拼接的时间戳。

练习：分别画三盒 IMU 和各方向 UWB 的消息时间间隔、接收时间间隔、接收减消息时间；明确哪些对比只在同一录包主机内成立。

掌握标准：能把“明显不同步”“未发现明显异常”“已用独立事件验证到某误差范围”分成三个结论。全程静止包可查跳变和基准异常，不能仅靠相似静止陀螺曲线证明毫秒级同步。

参考：[Linux PTP](https://www.linuxptp.org/)、[chrony 文档](https://chrony-project.org/documentation.html)、[LiDAR_IMU_Init](https://github.com/hku-mars/LiDAR_IMU_Init)。后者用于学习运动条件下时空标定，不等同于三盒时钟同步工具；安装授时服务不是本模块练习的必需步骤。

### M5 线性代数、概率统计与数值计算

### M6 坐标系、旋转、欧拉角、四元数与李群

要回答：一个姿态究竟把哪个坐标系的向量变到哪个坐标系？

统一学习记号：用 $C_b^n$ 表示把载体系分量转换成导航系分量：

$$
{}^n\mathbf v=C_b^n\,{}^b\mathbf v,\qquad
C_n^b=(C_b^n)^\mathsf T.
$$

在本节约定下，ZYX 写成：

$$
C_b^n=R_z(\psi)R_y(\theta)R_x(\phi),
$$

其中 $\phi,\theta,\psi$ 为 roll、pitch、yaw。还要学习内禀/外禀旋转、主动/被动解释，不能仅靠“ZYX”三个字认定两个接口完全一致。

必须学习：

- 世界/局部导航系、机体系、传感器系；FLU/FRD、ENU/NED、相机 optical frame。
- 固定相对世界系、每帧由 A→B 定义的三角形系、跟随主车平移旋转的机体系，三者的区别。
- 四元数单位范数、乘法、共轭、分量顺序 `wxyz/xyzw`；$q$ 与 $-q$ 是同一旋转。
- 双侧坐标转换：例如 $C_{\mathrm{FLU}}^{\mathrm{ENU}}=C_{\mathrm{NED}}^{\mathrm{ENU}}C_{\mathrm{FRD}}^{\mathrm{NED}}C_{\mathrm{FLU}}^{\mathrm{FRD}}$，不能把向量翻轴直接当成完整姿态转换。
- 欧拉角奇异性与跨 $\pm180^\circ$；四元数差分、旋转向量、指数映射；右乘/左乘误差定义。
- 姿态差可用归一化四元数的最短旋转角：$\Delta\alpha=2\arccos(\min(1,|q_1^\mathsf Tq_2|))$。

练习：构造绕每根轴正转 $90^\circ$，检查矩阵、四元数和欧拉角；将同一物理向量用 FRD、FLU 分别表示；构造 $q/-q$ 与真正 $180^\circ$ 变化，比较差分结果。

掌握标准：能画轴说明“前”“右”“上”实际指向，能解释换一种右手坐标系后数字变化但物理结果等价；不会只比较四元数某个分量判定姿态突变。

参考：[Modern Robotics 免费书与配套视频](https://modernrobotics.northwestern.edu/nu-gm-book-resource/)（刚体运动章节）、[ROS REP-103](https://www.ros.org/reps/rep-0103.html)、[REP-105](https://www.ros.org/reps/rep-0105.html)、[《视觉 SLAM 十四讲》第二版代码](https://github.com/gaoxiang12/slambook2)（三维刚体运动、李群李代数）。

### M7 IMU 测量模型、误差指标与惯性传播

要回答：静止时加速度为什么不是零？很小的陀螺误差为什么也会造成漂移？

必须学习：

- 陀螺测角速度，加速度计测比力；$\mathrm{rad/s}$ 与 $\mathrm{deg/s}$、$\mathrm{deg/h}$ 的换算。
- 局部低成本惯导模型中：

$$
\boldsymbol\omega_m=\boldsymbol\omega+\mathbf b_g+\mathbf n_g,
\qquad
\mathbf f_m=\mathbf f+\mathbf b_a+\mathbf n_a,
\qquad
{}^n\mathbf a=C_b^n(\mathbf f_m-\mathbf b_a)+{}^n\mathbf g.
$$

- 静止时比力抵消重力；正确扣重力需要姿态和坐标一致。
- 启动零偏、运行中偏置漂移、温度效应、标度因数、轴不正交、量化、饱和、噪声密度、角随机游走。
- “零偏不稳定性 0.3°/h”不等于每次上电零偏只有 0.3°/h，也不单独保证能够寻北。
- 采样、低通、抗混叠、功率谱密度 PSD、Allan 方差/偏差的用途；先理解时间序列和方差，再读噪声指标。短静止包不足以验证所有长时间稳定性指标，Allan 分析也不是所有现有脚本都已实现的功能。
- 姿态、速度、位置的逐步传播；中点积分、真实 $\Delta t$、四元数归一化；持续偏置如何累积成姿态与位置误差。
- AHRS 与完整 INS 的区别；AHRS 可能用重力修正姿态，纯陀螺积分不包含同样的反馈。
- 地球自转/运输角速度是完整惯导模型知识；本项目当前低成本局部模型与高精度地理惯导的适用范围不同。

练习：生成固定陀螺偏置，分别积分 10/60/180 秒；给姿态一个小倾斜误差，观察错误重力补偿引起的位置漂移。

掌握标准：能解释为何角速度几乎恒定，积分角却逐渐变大；能把零偏、噪声、单位错误分别设计成可检查的假设。

参考：[Kalibr IMU Noise Model](https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model)、[OpenVINS 文档](https://docs.openvins.com/)、[KF-GINS](https://github.com/i2Nav-WHU/KF-GINS)。KF-GINS 用来学习惯导机械编排与误差模型，不是当前无卫导条件下的即插即用方案。

### M8 静止初始化、启动零偏与姿态对照实验

要回答：不寻北是否还能初始化？估零偏需要水平摆放吗？

必须学习：

- 静止检测：样本数、时间长度、角速度/比力方差、重力模长、运动与振动污染。
- 重力方向提供两个姿态约束，yaw 仍任意；通常要求静止而非严格水平，且单姿态下加计偏置会影响重力方向估计。
- 启动陀螺均值 $\hat{\mathbf b}_g=N^{-1}\sum_k\boldsymbol\omega_{m,k}$ 是低成本场景的近似，包含无法分离的地球自转等成分。
- 每次实验重新估计启动偏置；不是把某次测得的三个数永久写死。先用前 10～30 秒静止窗口估计、冻结，再在后续独立时段扣除验证。
- 已知静止才能设初速为零；位置和 yaw 初值分别需要约定或外部信息。
- 单次未知姿态静止不能独立辨识完整三轴加计零偏；多姿态标定、运动激励和外部观测是不同方法。
- 相同坐标、相同映射方向、相同时间和初始对齐条件下，比较自身积分四元数与上交 AHRS；报告“差异/一致性”，没有独立真值不称“绝对姿态精度”。

练习：一包划分初始化段与验证段，输出启动偏置、未扣偏置/扣偏置姿态、ZYX 曲线、最短旋转角差和拒绝的异常时间段；不要用整包均值再声称检验了在线启动过程。

掌握标准：能解释偏置冻结实验的意义与温漂局限；能说明为什么两个解算一致仍可能一起偏离真值。

参考：[FAST-LIO](https://github.com/hku-mars/FAST_LIO) 的 [IMU_Processing.hpp](https://github.com/hku-mars/FAST_LIO/blob/main/src/IMU_Processing.hpp)（查看 `IMU_init`、均值和初始 `bg`）、[OpenVINS 初始化模块](https://docs.openvins.com/namespaceov__init.html)。FAST-LIO 初始化思路值得参考，但其雷达反馈不能凭空移植成纯 IMU 的观测能力。

### M9 KF、EKF、ESKF 与数值稳定性

要回答：为什么不仅积分，还要维护误差协方差？观测怎么改正偏置？

必须学习：

- Bayesian 估计；预测、观测、创新、创新协方差、Kalman 增益、更新。
- KF 与 EKF；非线性函数的 Jacobian；过程噪声 $Q$、观测噪声 $R$ 和初始协方差 $P_0$ 的区别。
- 名义状态与误差状态；本工程 15 维误差状态：

$$
\delta\mathbf x=[\delta\mathbf p^\mathsf T,\delta\mathbf v^\mathsf T,
\delta\boldsymbol\theta^\mathsf T,\delta\mathbf b_g^\mathsf T,
\delta\mathbf b_a^\mathsf T]^\mathsf T.
$$

- 误差动力学 $F,G$、离散转移 $\Phi$ 与 $Q_d$；连续噪声密度不可以不经离散化直接当每帧方差。
- 姿态误差注入与 reset Jacobian；三维小角误差不是四元数四个分量相减。
- Joseph 协方差更新、对称/半正定检查；NIS 门限、异常观测拒绝和长期不一致。
- 可观测性：状态向量里放了加计/陀螺偏置，不等于当前观测能把它估准。
- 扩展选学：IMU 预积分、滑动窗口、因子图和边缘化。当前逐帧惯性传播并不要求先实现预积分。

练习：先写一维位置/速度 KF，再推导距离观测 Jacobian；向 IMU 注入已知偏置，比较“没有外部观测”和“存在足够约束”的估计变化。

掌握标准：能逐项解释 $P,Q,R,H,K$ 的维度、单位和物理含义；不会通过无限放大噪声让错误数据看上去“稳定”。

参考：[OpenVINS 理论与实现文档](https://docs.openvins.com/)、[GTSAM：Factor Graphs and GTSAM](https://gtsam.org/tutorials/intro.html)、[十四讲第二版](https://github.com/gaoxiang12/slambook2)（状态估计、非线性优化）。因子图用于拓展比较，不要求重写现有 EKF。

### M10 UWB 测距、三角形恢复与可观测性

要回答：三条距离到底能恢复什么，为什么距离都有了仍然不能知道车头方向？

必须学习：

- TWR 测距的基本概念；标签天线参考点、天线延迟、视距/非视距、多径、近距离与噪声；普通距离接口不等于 AoA 测角接口。
- 双向测距是六条有向数据流，但静态几何只有三条无向边；正反向测量通常不是严格同一时刻，也不能自动视为独立同精度测量。
- 三角不等式、余弦定理、镜像歧义、共线退化；带噪距离可能不构成精确三角形，须讨论统计误差而非直接断言硬件损坏。
- 人为定义 $A=(0,0)$、$B=(d_{AB},0)$、$C=(x_C,y_C)$，则：

$$
x_C=\frac{d_{AB}^2+d_{AC}^2-d_{BC}^2}{2d_{AB}},\qquad
y_C=+\sqrt{d_{AC}^2-x_C^2}.
$$

- 该解取 $d_{AB}>0$ 并选 C 在正 Y 的镜像分支；假设距离对应同一队形。三维标签距离恢复的是三点所在平面的形状，不自动等于水平地面投影；水平定位要说明高度/平面假设。
- 每帧重新把 A→B 放在 +X，会消去编队整体旋转。因此该输出的 X 不是始终固定的初始世界轴。
- 固定系中的连线角 $\operatorname{atan2}(y_j-y_i,x_j-x_i)$ 需要先知道固定系中的点坐标；公式不能创造缺失的方向观测。
- 标签位置和车体原点的杆臂：非零杆臂下，距离可能通过已知姿态模型产生耦合，但不能据此声称静态三个单标签可独立解出三个车头朝向。
- 图连通、刚性和可观测性的区别；更多车辆时，图连通不保证唯一队形；全局平移、旋转及镜像等不确定性如何固定。

练习：用 3–4–5 米三角形手算坐标和内角；将整个三角形平移、旋转、镜像，验证三条距离不变；再加入近距离噪声，观察位置和夹角的不稳定性。

掌握标准：能分别回答“内部夹角”“相对初始固定轴角度”“相对车头角度”“相对东/北角度”需要什么条件，不能只回答一个笼统的“角度”。

参考：[工程理论方案第 27 文档](27_当前核心算法说明与落地方案.md)、[Omni-swarm](https://github.com/HKUST-Aerial-Robotics/Omni-swarm)（重点看其为什么还引入视觉惯性与机间视觉观测）、[GTSAM 教程](https://gtsam.org/tutorials/intro.html)（用因子与未知量分析约束）。研究更大规模测距图时，再专题学习距离几何、刚性矩阵及其秩。

### M11 多平台协同估计与共同坐标系

要回答：为什么不能把三台“上电 yaw=0”的惯导直接合并？

必须学习：

- 各车局部坐标系与公共局部坐标系之间的刚体变换；初始相对位置、相对 yaw、尺度和重力方向分别来自什么约束。
- 共同水平初值、运动激励、外部相对观测和可观测性；无北向并不阻止局部协同，但不能忽略车辆局部轴之间的旋转。
- 联合距离模型 $z_{ij}=\|\mathbf p_i-\mathbf p_j\|+v$，及存在杆臂时的完整标签位置模型。
- 集中式 $15N$ 联合误差状态和跨车协方差；分布式通信带宽、计算量与相关性丢失的代价。
- 本项目“本地惯导状态 → 参考车时间对齐 → UWB 二维协同修正”的职责划分；协同修正不等于已经回写本地惯导所有状态。
- 重复信息、数据关联、延迟/丢包/乱序、观测过期；相同信息多次融合可能造成过度自信。
- 拓展选学：Covariance Intersection、分布式因子图、相对状态估计。先理解问题，不急于增加一套新后端。

练习：让三车初始朝向分别不同但各自报告 yaw=0，解释直接拼接的错误；在已知共同初值的仿真中去掉一条边、冻结一个节点、增加延迟，记录输出变化。

掌握标准：能列出每个融合约束的来源，说明哪些自由度靠观测得到、哪些靠人为固定、哪些仍未知。

参考：[Omni-swarm 官方项目及其论文入口](https://github.com/HKUST-Aerial-Robotics/Omni-swarm)、[工程分布式设计](17_分布式本地惯导与参考车协同融合设计.md)。Omni-swarm 包含特定视觉/UWB 硬件和感知条件，不能把完整结果理解成“纯三标签测距结果”。

### M13 仿真、实包回放与精度评价

要回答：怎样证明改动有帮助，而不是只看到有输出或测试通过？

必须学习：

- 合成数据控制变量；Gazebo 物理真值、仿真 `/clock`；真实 rosbag 的不可控误差。
- 固定随机种子用于复现，换种子/轨迹用于检验稳健性；单组理想输入不能代表以后上车。
- 校准段与验证段分离；静止、转动、平移、转弯、丢包、时间跳变、NLOS、退化几何等测试设计。
- 位置 RMSE、均值/最大误差、百分位、姿态最短角误差、ATE/RPE；测距残差与位置误差不是一回事。
- 时间配对、刚体对齐与尺度对齐的适用边界。只有相对坐标可观时应说明 gauge 对齐；不能用对齐掩盖本应估计的航向/尺度错误。
- 输出频率、有效率、延迟、失效次数；有真值才报告精度，没有真值报告重复性、连续性和一致性。

练习：按第 28 文档运行一次 Gazebo，记录数值精度；再人为增加陀螺偏置或 UWB 噪声，只改变一个因素，比较两次结果。

掌握标准：可以给出“实验条件—输入—版本—统计—结论—局限”的完整证据链，不只说接口通过。

参考：[Gazebo Fortress Tutorials](https://gazebosim.org/docs/fortress/tutorials/)、[evo](https://github.com/MichaelGrupp/evo)（轨迹评价与对齐）、[工程仿真流程](28_Gazebo与算法仿真运行流程.md)。工程当前环境是 ROS 2 Humble/Gazebo Fortress，按已有流程运行，不因官网最新版变化而随意升级。

### M14 可选：激光雷达、视觉与多传感器融合

要回答：新增处理链到底补充了哪一种原来没有的约束？

只在需要固定局部系中的连续运动、机间方位或姿态约束时深入。先区分两条路线：

- 环境里程计：雷达扫描匹配、视觉特征跟踪或 VIO，估计自身相对局部环境的运动；不同车辆的局部地图/轨迹仍需要相互对齐。
- 直接观测其他车辆：点云目标识别/聚类与关联、视觉目标检测和 PnP 等，测得他车在本传感器系中的方向或相对位姿；必须知道目标身份，不能拿任意聚类充当另一台车。

必须学习：

- 点云过滤、体素降采样、去地面、聚类、数据关联、ICP/点到面残差；扫描运动畸变及 IMU 去畸变。
- 相机内参/畸变、投影、特征匹配、双目/单目尺度、PnP、重投影误差；PnP 要有对应的目标三维几何等前提。
- 雷达/相机到机体的外参、时间偏移与标定；目标中心、标签天线和车体原点不是同一点。
- 走廊/平面退化、纹理不足、遮挡、动态物体；观测不确定性和失效检测。
- 松耦合里程计输入与紧耦合原始特征融合；相关信息重复利用的问题。

练习：先做单车局部里程计，验证时间与坐标，再考虑多车对齐；若只需测他车方向，先做“可识别目标 → 方位及其置信度”的最小链路，不先搭完整大 SLAM。

掌握标准：能说明新增模块提供的是自身位移、环境姿态、机间方向还是机间完整位姿；不会声称无地图的 LIO/VIO 自动提供真实北向。

参考：[PCL ICP 教程](https://pointclouds.org/documentation/tutorials/iterative_closest_point.html)、[OpenCV 官方项目](https://github.com/opencv/opencv)（从其文档入口学习 `calib3d`）、[FAST-LIO](https://github.com/hku-mars/FAST_LIO)、[VINS-Mono](https://github.com/HKUST-Aerial-Robotics/VINS-Mono)、[ORB-SLAM3](https://github.com/UZ-SLAMLab/ORB_SLAM3)。只选择与目标匹配的一条路线。

### M15 硬件接口、网络传输与二进制协议

先修：Z1、Z3、Z6；读 C++ 实现前完成 Z7。

必须学习：

- 传感器、驱动和算法的分层；UART 串口、USB、以太网是什么；设备节点 `/dev/ttyS4` 不是网络端口。
- 波特率、数据位/停止位/校验、缓冲区、串口字节流、协议帧；波特率不是 ROS 消息发布频率。
- `/dev/ttyUSB*` 与 `/dev/ttyVUSB*` 的区别，符号链接、伪终端、设备权限、串口占用；不要凭编号猜是哪种硬件，也不要将 UART 电平和 RS232 电气接口混为一谈。

- 帧头、版本、类型、长度、序号、时间戳、载荷、CRC32；CRC 是差错检查，不是身份认证或加密。
- ROS CDR、本工程临时 ZJCL 协议、上交设备协议是三层不同协议。学习 ZJCL 不代表已掌握设备串口协议。

工程入口：[UDP 实现](../src/net/udp_socket.cpp)、[线协议](../src/protocol/wire_protocol.cpp)、[CRC](../src/protocol/crc32.cpp)、[Python 协议](../tools/zjcl_protocol.py)、[协议测试](../tests/test_protocol.cpp)。

练习：把一个节点号、时间戳、距离编码成字节再解码；故意改一个字节，观察校验错误；画出“串口 → ROS 消息 → 算法 → UDP 显示”各层的边界。

掌握标准：能区别连不上、没有发布、解码错误、数据内容异常；不会因看到 `/dev/ttyS6` 缺失就直接指定另一个未知串口代替。

参考：[工程临时协议说明](03_临时在线协议说明.md)、[Python socket 文档](https://docs.python.org/zh-cn/3/library/socket.html)、[Python struct 文档](https://docs.python.org/zh-cn/3/library/struct.html)。设备具体协议必须取得上交对应版本，不用通用教程替代。

## 6. 六个必须独立完成的小实验

### 实验一：原始包到可视化证据

用已有 `joint_time_20260909_171345` 或后续明确场景的新包，完成解码、分流统计、CSV、Foxglove 展示。保留原始包，不改原时间。

交付：文件清单、逐流数量、三张能定位异常的图、每张图对应的原始行/时间。评价的是分析可追溯性，不要求重新采集。

### 实验二：前段估零偏，后段验证

只用确认静止的初始窗口估计陀螺均值与重力方向，冻结偏置，后续分别积分原始陀螺和扣偏陀螺。上交姿态统一坐标与起始方向后参与对照。

交付：初始化/验证区间、偏置与单位、静止判定、时间异常处理、两种姿态差曲线、局限说明。不能把 AHRS 当独立真值。

### 实验三：三角形能估什么

先验证 3–4–5 三角形，再给它整体旋转，最后加入噪声和近共线几何。

交付：三条距离、恢复坐标、内部角、镜像解释，以及“哪些角度无从确定”。不能用输出坐标系的默认方向冒充观测到的方向。

### 实验四：时间故障注入

在分析副本或合成数据中分别加入固定偏移、频率偏差、单次前跳、回退和接收延迟。保留原始数据版本，禁止直接修改唯一实包。

交付：每类故障的差分图和识别方法；说明为什么固定减一个时间常数只适用于其中一类。

### 实验五：共同初值下的融合评价

用已有 Gazebo 流程，明确共同初始坐标与航向来源；比较正常测距、减少一条边、提高噪声的结果。

交付：位置/姿态误差数值、输出有效率、参数和版本。仿真共同初值是给定条件，不是算法从三条距离自动得到的成果。

### 实验六：一个最小改动及回归

选一个已理解的小问题，例如统计漏报一个时间回退、一个坐标测试缺失或一个输出说明含糊。先补最小测试，再改对应模块，重新运行相关实验。

交付：改动前证据、改动位置、测试结果、是否影响旧数据解释。未经需求确认，不顺手重写整个滤波器或加入新传感器。

## 10. 跨专业术语速查

这里用于查不熟悉的工程与专业术语，不代替相应模块的严格定义。已经熟悉的数学/计算机名词可以跳过，机器人专业术语首次出现时仍应解释，不必先背完此表。

### 10.1 电脑、编程与数据

| 名词/缩写 | 中文与最初的理解 | 去哪里学 |
|---|---|---|

| Process / Thread | 进程是运行中的程序实例，线程是进程内的执行路径 | M1、M17 |
| PID | 进程编号，查运行者用，不是车辆编号 | M1 |
| Environment / dependency | 环境是运行所需配置，依赖是程序要调用的软件 | Z1、M19 |
| Source / build / install | 源码、构建、安装是不同步骤 | Z7、M19 |
| API / ABI / SDK | 调用接口、二进制兼容约定、给使用者的开发资料与库 | M12、M19 |

| MCAP / rosbag | 消息记录格式或录包工具/数据；不是一张普通图片 | M3 |
