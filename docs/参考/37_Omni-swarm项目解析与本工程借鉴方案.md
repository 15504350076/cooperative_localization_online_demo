# 37 Omni-swarm 项目解析与本工程借鉴方案

## 1. 参考副本与结论

本工程并列目录已克隆参考副本：

    /home/pdq/Code/cooperative_localization_online_demo/omni-swarm

来源：[HKUST-Aerial-Robotics/Omni-swarm](https://github.com/HKUST-Aerial-Robotics/Omni-swarm)。论文：[Omni-swarm](https://arxiv.org/html/2103.04131v5)。本文件只解析，不把该 ROS1 工程编译进当前 ROS2 工程。

Omni-swarm 不是“三个 UWB 距离直接三角定位”，而是：

    VIO里程计 + 鱼眼/双目视觉 + 多机视觉检测
    + 视觉地图/回环 + UWB距离
    → Ceres滑动窗口图优化 → 相对状态与全局一致性

UWB 只是后端的一类观测；快速初始化和航向可观性主要还依赖 VIO、视觉相对位姿或地图约束。

## 2. 目录和数据流

| 目录 | 中文职责 |

| swarm_loop | 相机、鱼眼处理、VIO前端、视觉特征、无人机检测和回环候选 |
| localization_proxy | UWB、里程计和跨机消息的 ROS 通信适配 |
| swarm_localization | 关键帧、滑动窗口、Ceres 图优化、初始化和异常剔除 |
| DataAnalysis | 轨迹、相对误差和实验结果分析 |

后端的主要入口是 swarm_localization/src/swarm_localization_node.cpp；求解调度在 swarm_localization_solver.cpp；因子在 include/swarm_localization/swarm_localization_factors.hpp；异常处理在 swarm_outlier_rejection 目录。

README 要求额外安装 swarm_msgs 和 inf_uwb_ros，因此仅克隆仓库不能直接运行完整系统。README 的实机后端和 UWB 启动方式使用 ROS1 的 roslaunch，不适合直接复制到本工程。

## 3. 坐标系和状态

每架无人机的 VIO 启动时建立自己的 local frame，原点和水平轴由该机启动时刻决定，不自动等于真实 ENU 或北向。后端在某个参考机的局部系中估计其他机状态。

源码注释明确写着：Pose in this file use only x, y, z, yaw。其跨机主状态可以写为：

$$
\mathbf T_i=(x_i,y_i,z_i,\psi_i),
$$

即三维位置加 yaw 的 4-DoF 表达；roll/pitch 通常由重力或 VIO 前端提供。源码中的 YawRotatePoint、PoseTransformPoint、DeltaPose、PoseMulti 分别完成绕 Z 轴旋转、点变换、相对位姿和位姿复合。

它首先输出的是共享局部系中的相对状态。ATE（Absolute Trajectory Error）是将结果与动捕等真值对齐后计算的误差，不表示在线系统自动知道地理东、北。论文还单独报告 RE position 和 RE rotation，分别表示相对位置和相对旋转误差。

## 4. 观测作用

### 4.1 VIO

VIO 提供单机高频短时位姿变化和速度；长时间会漂移，后端需要其他观测修正。

### 4.2 视觉检测与地图

视觉检测可以提供另一平台的方向、深度或 6-DoF 相对位姿；共同地图特征和回环可以建立跨轨迹相对位姿。这些观测含有单个 UWB 距离没有的方向信息。

### 4.3 UWB

源码 DistanceMeasurementFactor 的残差为：

$$
r_{ij}=\left\|\mathbf p_i-\mathbf p_j\right\|-d_{ij}.
$$

它是标量距离约束，不直接测方向或车辆自身 yaw。距离对尺度和相对位置有帮助，但整体平移、整体旋转、镜像和部分运动会不可观。

### 4.4 异常处理

参数中有距离异常阈值、回环异常阈值、最小距离和 debug_no_rejection。正常运行进行拒绝或降权，关闭拒绝只用于诊断。本工程可借鉴创新检验、鲁棒核、数据新鲜度和 NLOS 处理，但不能照搬无人机参数。

## 5. 初始化方式

论文 V-E 节给出三类初始化：

1. **地图初始化**：已初始化平台和未初始化平台在共同地图中建立相对位姿，一条可靠测量即可把新平台加入共享图。
2. **视觉检测初始化**：通过相对视觉位姿和目标 ID 关联初始化新平台。
3. **UWB–里程计初始化**：使用多帧、足够且非退化的运动优化未初始化状态。论文给出的实践运动包围盒约为

   $$
   [1.5,1.5,0.8]\ \mathrm m.
   $$

源码会给未初始化平台随机位置初值，yaw 使用 VIO yaw，并尝试多组初值。平行运动、静止或只有一台平台运动时，部分 yaw 仍不可观。

所以 Omni-swarm 不能证明“静止三条 UWB 距离自动得到三车航向”。

## 6. 时间和精度指标

论文系统以 UWB 通信时间作为多机时间基准，再把 VIO/相机数据映射到该时间轴。论文实验配置约为 IMU 400 Hz、UWB 100 Hz、相机 16/20 Hz、图优化 1 Hz；本工程不必照搬这些频率。

可借鉴的同步流程：

1. 区分测量时间和接收时间；
2. 选一个跨盒子共同时间基准；
3. 按测量时间近邻匹配或插值；
4. 单独统计延迟、回退、丢包和跨流差值。

指标含义：

| 指标 | 含义 |
|---|---|
| RE position | 两平台相对位置误差，单位 m |
| RE rotation | 两平台相对旋转误差，单位 deg |
| ATE | 与真值对齐后的轨迹误差 |
| 初始化时间/成功率 | 从启动到可用及多次实验正确初始化的统计 |

ATE 中的 Absolute 是误差名称，不是在线绝对坐标。

## 7. 与本工程的比较

| 方面 | Omni-swarm | 本工程 |
|---|---|---|
| 平台 | 多架无人机 | 地面车辆/盒子 |
| ROS | ROS1 | ROS2 Humble |
| 视觉 | 鱼眼立体、VIO、检测、地图 | 视觉/激光作为后续观测 |
| IMU | 与 VIO 联合提供运动约束 | 上交六轴 MEMS，不能静态寻北 |
| UWB | 与 VIO/视觉图优化联合 | 单标签距离，当前主要提供队形约束 |
| 后端 | Ceres 滑动窗口图优化 | 15维惯性状态与协同滤波 |
| 初始化 | 地图、视觉或多帧 UWB–里程计 | 静止 roll/pitch、陀螺零偏；公共 yaw 需初值 |
| 坐标 | 各机 local frame 后跨机一致 | FLU/ENU 约定下的局部公共系 |

相似点是多平台、IMU/UWB、相对状态、时间、异常值和可观测性。关键差异是 Omni-swarm 有独立视觉 6-DoF、VIO 和地图；不能照搬其厘米级指标、无人机运动阈值或初始化成功率。

## 8. 对本工程的参考

### 8.1 现在可采用

1. 先判断可观测性，再允许节点初始化；
2. 统一 IMU/UWB 测量时间轴；
3. 用测距创新、NIS、三角不等式、数据新鲜度和 NLOS 处理异常；
4. 使用多帧滑动窗口，不用一帧距离决定全部状态；
5. 分开报告相对误差 RE 和有真值时的 ATE；
6. 输出注明坐标系、单位、时间基准和 yaw 是否有效。

### 8.2 不能直接移植

- 鱼眼视觉和 TensorRT 前端依赖不同硬件、依赖和 ROS 版本；
- 无人机三维运动阈值不能直接作为车辆测试门限；
- VIO yaw 不能当作上交六轴 IMU 的绝对航向；
- Omni-swarm 消息不能直接替换当前 UwbRange；
- 没有地图时不能使用地图初始化结论；
- 论文真值结果不能当作本工程实测精度。

### 8.3 推荐验证顺序

    已有静止包：时间轴、UWB三边、静止IMU初始化
    仿真数据：公共坐标系、非平行运动下的 IMU/UWB
    视觉/激光：相对方向和相对位姿
    最终验收：RE、初始化时间、异常剔除和长期漂移

当前三车全程静止时，可以验证时间同步、静态 IMU 初始化、测距质量和纯 UWB 三角形；不能声称完成 Omni-swarm 的多帧运动初始化。

## 9. 结论

Omni-swarm 最值得借鉴的是工程方法：先判断观测是否足以使状态可观，再初始化；IMU 负责高频传播，UWB 负责尺度和相对距离，视觉/地图负责方向和跨机对齐，并将相对误差与绝对误差分开。

本工程应保持两级能力边界：

1. 无公共航向：输出三车 UWB 相对队形和质量；
2. 有人工或视觉/激光公共航向：输出公共局部系下的 IMU/UWB 连续相对状态。

两级都不自动等于真实东北天，除非另有地理方向锚定。
