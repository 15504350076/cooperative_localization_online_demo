# 论文相对变换估计扩展库（RTE）

稳定基线：`v1.0.0-sensor-baseline`（提交 `44bb545`，三盒联测与 Livox 可视化回放）。新增库名为 `zju_coop_rte`，公开函数采用 `_rte` 方法后缀。默认构建选项 `ZJU_COOP_BUILD_RTE=OFF`，默认 `zju_coop`、在线/回放程序、ROS 2 节点、配置和 launch 保持基线的行为。

论文依据为仓库内 Nguyen / Xie 的 *Relative Transformation Estimation Based on Fusion of Odometry and UWB Ranging Data*（IEEE TRO 2023）；原文和完整中译本位于 `docs/两篇论文_完整中译本/`。

## 1. 估计对象与论文公式

单句柄估计一对平台的四自由度坐标变换 `T_L1_L2`：

```text
state = [tx, ty, tz, theta]
p_in_L1 = t + Rz(theta) p_in_L2
d_hat = ||t + Rz(theta) p2 - p1||
```

`p1/p2` 是两个 UWB 天线在各自局部里程计坐标系的位置。两个局部系须共享重力方向，允许未知的相对原点和相对航向；输入长度单位为米、时间为统一时间轴纳秒。`translation_m` 是 **L2 原点在 L1 中的位置**，并非每个时刻两车之间的向量。

实现对应关系：

| 论文 | 实现 |
| --- | --- |
| 式 (6)、(7) | NodeState 位置加旋转后的天线杆臂；三维测距模型 |
| 式 (34) | 无偏平方测距 `s_tilde = d_measured² - sigma²` |
| 式 (35) | 独立测距噪声的 `Sii = sigma² (4 d_measured² + 2 sigma²)` |
| 式 (39)、(40) | 九维提升变量 `x` 和每个样本的设计矩阵行 `Ai` |
| 式 (36)、(42)、(43) | 最小化 `0.5 ||S^(-1/2) B x||²` |
| 式 (44) 的前四条约束 | 由 `[tx,ty,tz,theta]` 构造 `x`，精确满足单位圆、交叉项和范数约束 |
| 式 (16)、附录 A | 测距 Jacobian、Fisher 信息矩阵、条件数和线性化协方差 |

求解器采用平方测距 QR 初值及全周航向初值，随后用阻尼 Levenberg–Marquardt 求解消元后的目标。它优化的是论文 QCQP 的同一可行目标，**采用局部数值求解，不是论文使用 Gurobi 的全局 QCQP 实现，也未实现 SDP 松弛或全局最优证书**。可选的原点测距 `d0` 硬约束未启用；论文允许在没有此测量时删除它。本实现不估计里程计误差状态或时钟偏移。

条件数过大返回 `UNOBSERVABLE`；多初值发现近等价而不同的解返回 `AMBIGUOUS`，例如两车都作平面运动时可能出现正负高度镜像。状态 `READY` 表示本次局部求解收敛、FIM 通过门限且未检出等价解，不构成全局唯一性证明。协方差是给定里程计位置时的测距信息逆矩阵，不包含完整里程计/外参/时钟误差。

## 2. 构建与复现

扩展库内部使用 Eigen 3 的 QR/SVD/特征值运算；当前开发机已安装 Eigen 3.4。ROS 2、Gurobi 和 SDP 求解器均不是它的运行依赖。Ubuntu 缺少 Eigen 开发包时可安装 `libeigen3-dev`。

从项目根目录执行，使用新目录避免旧 Windows `build/` 缓存冲突：

```bash
cmake -S . -B build-rte -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=ON -DZJU_COOP_BUILD_RTE=ON
cmake --build build-rte -j2
./build-rte/zju_coop_rte_self_check
ctest --test-dir build-rte --output-on-failure -R rte
```

库文件是 `build-rte/libzju_coop_rte.so`（含 `.so.1` 版本链接），公开头是 `include/zju_coop/relative_transform_api.h`。纯 C 消费者例子为 `tests/c_header_smoke_rte.c`，完整合成轨迹调用例子为 `tests/test_relative_transform.cpp`；两者只链接 RTE 库。

全项目回归含 ROS 录包工具测试，先加载已有消息工作区：

```bash
source /opt/ros/humble/setup.bash
source install/ros2-uwb-online/setup.bash
ctest --test-dir build-rte --output-on-failure
```

安装时沿用工程安装流程，新库和公开头会随启用的扩展一起安装：

```bash
cmake --install build-rte --prefix install-rte
```

Windows 使用同一公开头，在安装好 Eigen 的 CMake 环境中配置本选项并生成 DLL；本次验证平台是 Ubuntu 22.04 x86-64，Windows/RK3588 尚未进行本扩展的实机验证。

## 3. 接口和调用顺序

函数使用与现有库相同的 C ABI 错误码、`struct_size/abi_version`、不透明句柄和调用方拥有的输出缓冲区约定；方法函数加 `_rte` 后缀。

| 原有调用方式 | RTE 调用 |
| --- | --- |
| 初始化配置、创建/销毁独立句柄 | `zju_coop_config_init_rte`、`zju_coop_create_rte`、`zju_coop_destroy_rte` |
| 送入紧凑本地惯导状态 | `zju_coop_push_node_state_rte`，复用 `zju_coop_node_state_t` |
| 送入 UWB 距离并读取处理回执 | `zju_coop_push_range_rte`，复用现有 packet/result 结构 |
| 推进解算 | `zju_coop_step_rte`，输出独立的四自由度估计结构 |
| 查询二维结果快照 | `zju_coop_get_pose2d_v2_rte`，复用现有 Pose2D v2 结构与 stride 规则 |

RTE 估计的状态与原 ESKF 不同，因此配置和四自由度估计使用专用结构；这不是将旧库重命名后直接替换的 ABI。**RTE 输入 NodeState 中名字含 `_enu` 的字段，明确按各节点自身的重力对齐局部里程计系解释。** 对接时要选择正确的里程计坐标，不能把它自动视为公共 ENU。

典型流程：

1. 初始化 `zju_coop_config_rte_t`，设置主机和目标节点号、两个车体 FLU 杆臂及配对容差；创建独立 RTE 句柄。
2. 送入两端 NodeState 历史，保持各端非零且严格递增的统一时间戳。
3. 送入 UWB 包。库在时间容差内插值位置和姿态，或取最近有效状态，并构造天线位置。没有配对状态时回执为 `HELD`；该测距不缓存，调用方补状态后可重送。
4. 送入至少 `minimum_samples` 组后，初始化 `zju_coop_estimate_rte_t` 并调用 `zju_coop_step_rte`。入窗回执的 `filter_updated=false`，因为优化由 step 显式执行。
5. 同时检查返回码和 `estimate.status==ZJU_COOP_RTE_READY`，再使用变换或查询 Pose2D。
6. 销毁句柄。里程计坐标系重置时须重新建句柄。

Pose2D 坐标轴平行主机局部系 L1，原点在本次主机车体位置，frame 为 `coop_rte_<host>_local`。输出的是当前车体间位置与车体在 L1 中的航向，没有公共北向含义。查询只读取最后一次有效解和窗口末时刻的配对姿态，不推进状态，也不预测到现在。

已有离线配对数据也可绕过适配接口：初始化 `zju_coop_sample_rte_t`，填写已完成杆臂补偿的两端天线位置和距离，调用 `zju_coop_push_sample_rte` 后 step。直接样本模式只输出坐标变换，不提供车体 Pose2D。直接样本的 `range_std_m=0` 使用配置默认值；UWB packet 则沿用既有接口，必须显式提供正标准差。

## 4. 边界与验证范围

- 每个句柄只估计一对平台；三车可为 201→202、201→203 分别建句柄，尚未实现多对变换的全网一致性优化。
- 默认窗口 512，范围 8–4096；单轴局部位置绝对值不超过 100000m，测距为 `(0,200000]`m，显式标准差为 `[1e-6,1000]`m。
- 无效、NLOS 标记、NLOS 概率不低于 0.5、非 OK 测距、重复/倒序历元会被拒绝。RTE 没有复刻旧库的全部链路质量状态机，也不在这里做原始点云/视觉里程计或 IMU 积分。
- 自检覆盖多组正负高度与接近 ±pi 航向、独立异方差测距噪声、论文目标值核对、静止退化、平面高度镜像、滑窗淘汰、ABI/非法输入，以及现有 NodeState/UWB/Pose2D 结构、旋转杆臂、时间插值和扩展 stride。
- 本次验证是合成里程计与测距测试及旧程序回归。三盒 Livox 可视化数据没有被当作可信里程计或真值，尚未进行该扩展的实盒精度验证。

2026-10-22 开发机验证记录：Release 构建、全项目 9 项 CTest、RTE 专项自检和纯 C 消费者均通过；四组带噪轨迹的测距残差 RMS 为 0.02737–0.02756m。安装后通过安装目录中的头文件和动态库编译并运行纯 C 消费者成功；同一进程同时加载原库 `0.3.0` 和扩展库 `1.1.0-rte-qcqp-local` 成功。新库仅导出 12 个以 `_rte` 结尾的函数；原在线程序的动态依赖不包含 RTE 库。
