# 三车 IMU＋测距协同定位算法与可观测性说明

## 1. 当前算法解决什么问题

当前默认算法在参考盒集中接收车辆 A、B、C 的标准 IMU 瞬时量和车间测距。每个节点维护位置、速度、姿态、陀螺零偏和加计零偏名义状态，误差状态为：

```text
[δp(3), δv(3), δθ(3), δbg(3), δba(3)]
```

三车联合协方差为 45×45，保留节点间交叉相关性。各节点 IMU 异步到达时只传播对应状态块；任一有效车间测距异步到达后用三维欧氏距离更新完整联合状态。算法核心不依赖 ROS 2，标准消息由上交 wrapper 映射成普通 C 结构体。`config/range_only_demo.ini` 另保留二维恒速兼容路径，但不是默认模式。

## 2. 三车为什么能够确定二维相对位置

三条边 AB、AC、BC 构成非共线三角形时，三条距离可以确定三角形的形状，但仅靠距离仍存在整体平移、整体旋转和镜像歧义：

- 把 A 固定在 `(0,0)`，消除整体平移；
- 使用外部初始二维坐标确定 x/y 朝向和镜像分支；
- 后续测距保持三车相对几何，默认由各节点 IMU 递推位置、速度和姿态。

因此，初版必须由上交在创建算法时提供 A/B/C 的外部初值。初值可来自 GNSS 失锁前位置、人工测量或任务配置。只指定 A 为原点而不提供 B/C 初值，不能唯一确定朝向和镜像分支。

当前 demo 默认：

| 车辆 | node_id | 初始坐标 |
|---|---:|---:|
| A | 1 | `(0,0) m` |
| B | 2 | `(3,0) m` |
| C | 3 | `(0,4) m` |

## 3. 测量模型

节点 i、j 的标量距离模型为：

```text
h_ij(x) = sqrt((x_j-x_i)^2 + (y_j-y_i)^2)
innovation = measured_range - h_ij(x)
NIS = innovation^2 / innovation_variance
```

NIS 超过配置门限时拒绝该次滤波更新，并将残差拒绝计入观测质量窗口。NLOS 或恢复期观测可通过放大测量协方差降权。

## 4. 动态有效边与退化

候选边不是固定有效边。引擎按数据时间、观测状态和 `edge_timeout_ns` 动态生成当前有效图：

- 三边有效且三点非共线：二维相对几何可观；
- 缺少一条边：三车瞬时二维几何一般不刚性，输出标记为不可观；
- 三点近共线：刚度矩阵秩不足，标记几何退化；
- 边持续缺失：置 `LINK_TIMEOUT`，节点可达数和有效边数同步变化；
- 时间偏差超限：拒绝该包并置 `TIME_SYNC_TIMEOUT`。

默认惯性模型可以在短时缺测时连续递推，兼容模式则使用常速度预测；两者都不能把预测结果解释为新的几何约束。

## 5. 观测质量状态机

每条候选边维护配置化滑动窗口。默认窗口为 2 s、测距标称 20 Hz，并统计收到数、有效数、NLOS 数、残差拒绝数和丢弃数。

状态可在 `UNKNOWN → NORMAL/DEGRADED → SUSPENDED → REJECTED → RECOVERING → NORMAL` 之间转换；融合动作分别为正常使用、降权、暂缓、拒绝和试探恢复。所有阈值都在 `config/demo.ini`，未硬编码在算法源文件中。

## 6. 当前输出能力边界

当前有效输出只有：

- `x, y`，单位 m；
- `vx, vy`，单位 m/s；
- 二维位置协方差 `cov_xx, cov_xy, cov_yy`，单位 m²；
- 定位、网络、观测质量和原因位。

内部惯性状态包含三维位置和姿态，但当前 C ABI/GCS Localization 仍只发布二维相对量，没有发布 yaw 或 z 数值；`yaw_valid=false`、`z_valid=false`。结果不是地理绝对坐标。坐标轴方向、手性和正式 frame 名称必须在真实盒端联调前由双方冻结。

## 7. 初版与 V3 完整方案的差距

当前已经实现标准 IMU 瞬时量的 15 维预测和车间测距更新，但尚未实现激光/视觉相对观测前端、分布式每车 EKF、显式主约束链或多跳状态汇总。当前验证的是三车集中式 IMU＋测距最小在线闭环、质量退化、动态有效图、C ABI、协议、日志和回放。

若增加第 4 辆车和冗余测距，可提高几何冗余和单边失效容忍度，但不能替代时间同步和外部初始坐标。
