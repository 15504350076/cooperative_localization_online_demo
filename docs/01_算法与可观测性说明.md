# 三车 IMU 启动初始化＋测距协同定位算法与可观测性说明

## 1. 当前算法解决什么问题

当前仓库并存惯性融合、仅测距滤波和三边几何初始化三部分。首版分布式路径由每车在本机计算 15 维惯导，只发布紧凑 NodeState；参考车按 UWB 测量时刻对齐三车状态，维护不覆盖本地惯导的二维协同修正并发布 GCS 结果。原参考盒集中接收三车 IMU、维护 15N 联合协方差的实现继续保留，作为回归基线。两条惯性路径中每个节点的名义状态都包含位置、速度、姿态、陀螺零偏和加计零偏，误差状态为：

```text
[δp(3), δv(3), δθ(3), δbg(3), δba(3)]
```

集中式基线的三车联合协方差为 45×45，保留节点间交叉相关性；分布式首版则由每车自行维护 15×15 协方差，NodeState 不传输协方差，参考车只估计平面位置修正。算法核心不依赖 ROS 2；已实现的 ROS 2 适配节点先把上交 IMU 的 FRD 量测标准化为 FLU/SI，再将 IMU 和自定义 UWB 消息映射成普通 C 结构体。`config/range_only_demo.ini` 另保留二维恒速兼容路径，供回退和回归使用。

新增的两个无状态算法入口是：

- `initialize_static_imu()`：检查静止窗口，用平均重力确定 roll/pitch，用平均角速度估计启动陀螺零偏；
- `solve_three_node_formation()`：由同一历元的三条距离恢复规范三角形、三个内角和三条连线方向。

二者目前位于 C++ 核心层并有单元测试；ROS 2 在线节点尚未增加“缓存静止窗口后自动配置滤波器”的启动状态机，不能把核心函数已实现误写成盒端已自动使用。

## 2. 静止 IMU 初始化能确定什么

输入必须先统一为本工程内部约定：车体 FLU、角速度 rad/s、比力 m/s²。算法对完整窗口计算均值和逐轴标准差，并用重力模长、平均角速度和两类标准差门限拒绝非静止窗口。

静止时比力均值记为 `f_b=[fx,fy,fz]`，姿态采用 `Rz(yaw)Ry(pitch)Rx(roll)`。初始化为：

```text
roll  = atan2(fy, fz)
pitch = atan2(-fx, sqrt(fy²+fz²))
gyro_bias = mean(angular_velocity)
```

重力只能给出 roll/pitch。`initial_yaw_rad` 只是人为固定不可观的水平旋转自由度，默认可取 0，但不代表北向、地图方向或真实车头航向。一个静止姿态下，加速度计三轴零偏与倾斜误差不可分离，因此本函数不伪造加计零偏估计；需要六面标定、厂家标定或运动/外部观测才能进一步估计。

平均角速度中严格说还包含地球自转，但对当前低精度 MEMS 可一并吸收到启动零偏；这不构成寻北。详细调用和门限见 `docs/26_静止IMU初始化与三车UWB三角形.md`。

## 3. 三车为什么能够确定二维相对位置

同一历元的三条边 AB、AC、BC 构成非共线三角形时，三条距离可以确定三角形的形状，但仅靠距离仍存在整体平移、整体旋转和镜像歧义。新增规范坐标系消除的是数学表达歧义，不是增加了物理观测：

- A 固定在 `(0,0)`；
- B 固定在 `(dAB,0)`，定义人为 `+X`；
- C 固定在 `+Y` 半平面，选择两个镜像解中的一个；
- frame 记为 `formation_<A>_<B>`，例如 `formation_1_2`。

这能输出三个 UWB 标签点的相对位置、三角形三个内角，以及各连线相对人为 `+X` 的方向角。它不能输出三角形相对北向、地图或车头的方向，也不能输出任一车辆自身 yaw；标签有安装杆臂时，标签点也不等于车体中心。

现有在线 `RangeEkf` 仍需要初始二维位置。`solve_three_node_formation()` 的三个点可以直接作为它的规范初值；后续持续测距用于滤波，但纯测距输出仍只处在人为相对坐标系。若需要真实 ENU，则必须另有 GNSS、地图/视觉/激光定位、已知基站或可信航向等外部锚定。

历史理想惯性 demo 默认（不是三边纯测距推导出的航向）：

| 车辆 | node_id | 初始坐标 | 公共 ENU 初始航向 |
|---|---:|---:|---:|
| A | 1 | `(0,0) m` | `0 rad` |
| B | 2 | `(3,0) m` | `π/2 rad` |
| C | 3 | `(0,4) m` | `-3π/4 rad` |

这里的航向表示本车 FLU 前向 `+x` 轴相对 ENU 东向 `+x` 轴的逆时针夹角，规范范围为 `[-π,π)`。UWB 标量测距的量测方程只含节点间位置距离，不直接含姿态或航向；因此测距不能直接校正航向。运动状态和滤波交叉相关可能产生间接耦合，但静止或缺少有效运动激励时不应宣称 UWB 已使航向可观。

## 4. 测量模型

节点 i、j 的标量距离模型为：

```text
h_ij(x) = sqrt((x_j-x_i)^2 + (y_j-y_i)^2)
innovation = measured_range - h_ij(x)
NIS = innovation^2 / innovation_variance
```

NIS 超过配置门限时拒绝该次滤波更新，并将残差拒绝计入观测质量窗口。NLOS 或恢复期观测可通过放大测量协方差降权。

## 5. 动态有效边与退化

候选边不是固定有效边。引擎按数据时间、观测状态和 `edge_timeout_ns` 动态生成当前有效图：

- 三边有效且三点非共线：二维相对几何可观；
- 缺少一条边：三车瞬时二维几何一般不刚性，输出标记为不可观；
- 三点近共线：刚度矩阵秩不足，标记几何退化；
- 边持续缺失：置 `LINK_TIMEOUT`，节点可达数和有效边数同步变化；
- 时间偏差超限：拒绝该包并置 `TIME_SYNC_TIMEOUT`。

默认惯性模型可以在短时缺测时连续递推，兼容模式则使用常速度预测；两者都不能把预测结果解释为新的几何约束。

## 6. 观测质量状态机

每条候选边维护配置化滑动窗口。默认窗口为 2 s、测距标称 20 Hz，并统计收到数、有效数、NLOS 数、残差拒绝数和丢弃数。

状态可在 `UNKNOWN → NORMAL/DEGRADED → SUSPENDED → REJECTED → RECOVERING → NORMAL` 之间转换；融合动作分别为正常使用、降权、暂缓、拒绝和试探恢复。所有阈值都在 `config/demo.ini`，未硬编码在算法源文件中。

## 7. 当前输出能力边界

当前同时保留两条输出语义：

- C ABI v1 `Localization`：`x/y`、`vx/vy`、二维位置协方差、定位状态和原因位；旧结构固定 `yaw_valid=false`、`z_valid=false`；
- Pose2D C ABI v2：公共 `timestamp_ns/reference_node_id/frame_id`，以及每辆车的 `node_id/x_m/y_m/yaw_rad/position_valid/yaw_valid`；
- 临时 UDP 类型 105 和浏览器 GCS：映射 Pose2D v2 的 x/y/yaw，`yaw_valid` 有效时绘制航向箭头；
- Network、Observation、演示层 AlgorithmStatus/Alert：继续提供网络、观测质量和原因位。

Pose2D 的 x/y 表示 `node-reference`。惯性模式沿用公共 ENU，frame 为 `coop_ref_<reference_node_id>_enu`；纯测距模式只沿用人为初始轴，frame 为 `coop_ref_<reference_node_id>_relative`。只有 `yaw_valid=true` 时 yaw 才表示每辆车自身的 ENU 航向；由重力初始化出的任意初始 yaw 不应被上层标成绝对航向有效。z、高度、完整三维姿态和地理绝对坐标仍未输出。

## 8. 初版与 V3 完整方案的差距

当前已经实现静止窗口 roll/pitch/启动陀螺零偏解算、三边规范三角形解算、标准 IMU 瞬时量的 15 维预测、集中式 15N 基线、分布式每车本地惯导与 NodeState、参考车二维 UWB 修正、Pose2D C ABI v2、ROS 2 GCS 发布、临时 UDP/GCS 和 Gazebo 三车闭环。尚未把新增静止/三边初始化自动接入 ROS 2 启动流程，也未实现激光/视觉相对观测前端、协同修正反馈、无中心或显式多跳约束传播。当前桌面构建和单元测试不构成 RK3588、跨盒网络或实车验证证据。

若增加第 4 辆车和冗余测距，可提高几何冗余和单边失效容忍度，但不能替代时间同步和外部初始坐标。
