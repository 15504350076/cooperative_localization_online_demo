# KF-GINS 对协同定位项目的适用性评估

## 1. 评估对象与结论

- 上游项目：`i2Nav-WHU/KF-GINS`
- 本地只读副本：`D:\Users\20411\Desktop\协同定位导航\程序\武汉大学_KF-GINS`
- 评估提交：`8291a93e49de513fe9d21f819500d39082ded611`
- 上游许可：GNU GPL v3
- 评估日期：2026-07-20

结论：**KF-GINS 可以作为“各节点本地 IMU 机械编排和误差状态 EKF 递推”的算法参考，但不能直接作为本项目的协同定位算法库，也不应在未完成许可证评审的情况下复制源代码或链接进拟交付的闭源算法库。**

它实现的是单平台 GNSS/INS 松组合离线解算。仓库中没有 UWB 距离更新、多节点状态、协同拓扑、主参考平台汇总、ROS 2 适配、稳定 C ABI 或 `.so` 库目标。现有三车 Demo 与 KF-GINS 的合理关系是：保留现有 UWB 协同定位、质量评价、拓扑和 C ABI 框架；参考其数学思路，自主实现许可证清晰的本地 IMU ESKF 模块，再通过版本化接口接入。

## 2. 实际代码结构

KF-GINS 的主要数据流为：

```text
IMU 文本：时间、角增量、速度增量
GNSS 文本：时间、经纬高、位置标准差
            │
            ▼
     文件读取与时间对齐
            │
            ▼
 IMU误差补偿 → INS机械编排
            │
            ▼
 21维误差状态EKF协方差预测
            │
            ▼
      GNSS位置松组合更新
            │
            ▼
 误差反馈 → 导航/误差/STD文件
```

21 维误差状态包括：位置误差、速度误差、姿态误差、陀螺零偏、加速度计零偏、陀螺比例因子、加速度计比例因子，各 3 维。IMU 零偏和比例因子采用一阶高斯—马尔可夫模型。

该项目采用**逐历元 IMU 递推预测**，不是因子图中的 IMU 预积分。其 `IMU` 输入为时间、时间间隔、角增量 `dtheta`（rad）和速度增量 `dvel`（m/s）；机械编排包含圆锥/划桨补偿、重力、地球自转、位置、速度和姿态更新；随后对误差状态和协方差做 EKF 预测。

## 3. 与本项目需求的对应关系

| 本项目要求 | KF-GINS 现状 | 适用判断 |
|---|---|---|
| C/C++ 算法核心 | C++14 类实现 | 部分可参考；不满足当前 C++17 和稳定 C ABI 交付形式 |
| 每节点 IMU 递推预测 | 有完整 INS 机械编排、误差补偿和 EKF 预测 | 核心参考价值最高 |
| MEMS-IMU 零偏估计 | 有陀螺/加速度计零偏和比例因子状态 | 可参考；初版建议先用 15 状态，比例因子留作可选扩展 |
| 异步观测时间对齐 | 可把一帧 IMU 增量拆分到 GNSS 观测时刻 | 可参考数学处理；没有 PPS 同步状态或跨节点统一时间轴 |
| UWB 测距更新 | 无 | 不能直接使用，必须新增距离观测模型和质量处理 |
| 多节点本地状态交换 | 无 | 必须新增 `NodeStatePacket` 及邻居状态不确定度处理 |
| 动态协同拓扑/多跳汇总 | 无 | 继续使用并扩展现有 Demo 的拓扑和可观测性模块 |
| 激光/视觉相对观测 | 无 | 必须以后按统一相对观测接口扩展 |
| ROS 2 | 无 | 上交需实现 ROS 2 适配层；浙大核心库继续与 ROS 2 解耦 |
| 可执行程序或 `.so` | 仅构建 `KF-GINS` 可执行程序 | 不能直接交付为本项目算法库 |
| 在线数据流 | 读取整段 IMU/GNSS 文本文件 | 不满足在线调用，需要改为逐包 `push` 接口 |
| ARM64 Ubuntu 22.04 | 源码和依赖原则上可跨平台 | 尚无本次实机证据，必须在 AIBrainBox 重新编译测试 |
| 配置文件管理 | 使用 YAML | 思路可用；现有 Demo 目前使用 INI，不必为此强制引入 YAML |
| 许可证适合闭源交付 | GPL v3 | 高风险；未获许可前不得直接复制或链接进闭源交付库 |

## 4. 对现有 Demo 的具体价值

### 4.1 可以借鉴

1. IMU 原始量到角增量、速度增量的离散化处理。
2. 捷联惯导的位置、速度、姿态机械编排。
3. 圆锥和划桨误差补偿。
4. 陀螺/加速度计零偏补偿及随机过程建模。
5. 误差状态转移矩阵、过程噪声离散化、协方差传播。
6. 异步观测落在两个 IMU 历元之间时的时间对齐思路。
7. 误差状态反馈到名义状态的方式。

### 4.2 不能照搬

1. GNSS 经纬高和北东地坐标更新不能替代主参考车局部坐标系下的 UWB 相对距离更新。
2. 单平台 21 维滤波器不能直接替代当前多节点联合状态或后续分布式本地滤波器。
3. 文件加载器、命令行主程序和结果文本输出不属于在线算法库接口。
4. 代码中没有观测质量降权、暂缓、剔除、动态拓扑或链路状态处理。
5. GPL v3 源码不能在没有法务/许可结论时直接并入拟闭源交付物。

## 5. 推荐的实现方式

### 5.1 架构选择

后续采用“每车本地递推 + 主参考车协同汇总”的混合架构：

```text
每辆车 AIBrainBox
上交时间同步/ROS2驱动
        │ IMU、UWB、同步状态
        ▼
浙大本地15状态ESKF：p、v、q、bg、ba
        │ NodeStatePacket
        ├──────────平台间状态交换──────────┐
        ▼                                  ▼
本车直接相对观测更新               主参考车拓扑与状态汇总
                                           │
                                           ▼
                         Localization/Network/Alert → GCS
```

当前 UWB-only Demo 可继续作为第一条在线闭环；增加 IMU 后，不应把 KF-GINS 整体嵌入现有联合二维 `RangeEkf`。应新建独立的本地惯性状态模块，并由协同引擎决定使用本地状态、邻居状态和 UWB 观测。

初版建议使用 15 状态 ESKF：位置、速度、姿态、陀螺零偏、加速度计零偏。陀螺/加速度计比例因子 6 状态作为配置开关保留到 21 状态版本。这样可以先降低参数可辨识性和标定要求，同时为后续升级保留接口。

### 5.2 IMU 输入接口

AIBrainBox 的最终 IMU 消息尚未冻结。ROS 2 常见 `sensor_msgs/Imu` 给出角速度（rad/s）和线加速度（m/s²），而 KF-GINS 输入的是角增量（rad）和速度增量（m/s）。浙大算法接口应同时预留两种明确模式，禁止靠单位猜测：

- `RATE_SAMPLE`：角速度和比力，由算法库根据相邻时间戳积分；推荐作为 ROS 2 常规输入。
- `INCREMENT_SAMPLE`：传感器或上交预处理后的角增量和速度增量。

包内至少需要：`node_id`、`sequence`、`timestamp_ns`、`receive_timestamp_ns`、测量模式、三轴陀螺量、三轴加速度计量、可选温度、六轴协方差或噪声标识、`frame_id`、`valid`、`status`。上交负责时间同步与时间戳可信性，算法库负责顺序、间隔、迟到、重复和数值有效性检查。

### 5.3 计划修改位置

后续实施 IMU 阶段时，建议修改/新增：

- `include/zju_coop/types.hpp`：增加版本化 `ImuPacket`、`NodeStatePacket` 和能力位。
- `include/zju_coop/c_api.h`：增加版本化 C 结构体与 `push_imu`、`push_node_state` 接口，保持现有 ABI v1 可用。
- `src/core/inertial_eskf.hpp/.cpp`：自主实现 15 状态本地 ESKF，不复制 GPL 源码。
- `src/core/engine.hpp/.cpp`：接入各节点本地状态、UWB 异步更新和主参考汇总。
- `src/config/ini_config.hpp/.cpp`、`config/demo.ini`：增加 IMU 噪声、重力、坐标系、输入模式和超时参数。
- `tests/test_inertial_eskf.cpp`：静止、匀速、偏置、时间戳异常和协方差正定性测试。
- `tests/test_imu_uwb_fusion.cpp`：三车 IMU+UWB 闭环、掉线和恢复测试。
- `tools/imu_uwb_simulator.py`：生成同步的多车 IMU、UWB 和真值数据。
- `docs/02_C_API接口说明.md`、`docs/04_AIBrainBox部署与上交ROS2适配说明.md`：补充上交侧映射和单位约束。
