# 31 三盒IMU/UWB联合录包：离线分析操作步骤

适用于 `record_joint_time.py` 生成的 `joint_time_*` 目录。Windows上交电脑负责SSH录包和下载；下面的分析命令在Ubuntu 22.04、ROS 2 Humble开发电脑终端执行，不需要连接盒子，也不需要启动传感器、Gazebo或算法节点。

## 1. 必要文件

可以继续使用完整工程，也可以解压随附的 `联合录包离线分析工具.tar.gz` 单独使用：

```text
工具目录/
├── tools/
│   ├── analyze_joint_recording.sh       # 一次运行全部基础分析
│   ├── record_joint_time.py            # --analyze检查各流原始时间
│   ├── analyze_joint_time.py           # 时间统计CSV及图
│   ├── analyze_imu_bag.py              # IMU频率、时间、陀螺、加速度、姿态突变
│   ├── export_uwb_bag_readable.py       # UWB逐条CSV、统计和图
│   └── export_imu_bag_csv.py            # 可选：导出IMU全部样本和抽样表
├── ros2/cooperative_interfaces/        # 上交消息定义及构建文件
├── docs/31_联合录包离线分析操作步骤.md
└── data/joint_time_实验编号/            # 自己放入录好的数据
```

工具包不含ROS安装文件、原始数据和定位算法。使用本步骤只需编译消息定义，不需要编译整个定位工程。

## 2. 首次准备环境

以下假定Ubuntu已经安装ROS 2 Humble。在工具目录或完整工程根目录打开终端，执行一次：

```bash
source /opt/ros/humble/setup.bash
sudo apt-get install python3-colcon-common-extensions python3-numpy python3-matplotlib fonts-wqy-microhei ros-humble-rosbag2-py ros-humble-rosidl-default-generators ros-humble-sensor-msgs
colcon build --base-paths ros2/cooperative_interfaces --build-base build/offline-analysis --install-base install/offline-analysis
```

每次新开终端都执行：

```bash
source /opt/ros/humble/setup.bash
source install/offline-analysis/setup.bash
python3 -c 'import rosbag2_py, numpy, matplotlib; from cooperative_interfaces.msg import UwbRange, Identity; print("分析环境可用")'
```

若使用现有完整工程，且已经有 `install/ros2-sjtu-adapter-current/setup.bash`，也可以加载它代替 `install/offline-analysis/setup.bash`，无需重复构建。使用Ubuntu系统的python3，避免在conda环境运行。

离线分析不依赖 `ROS_DOMAIN_ID=107`，无需设置域号或联网发现节点。

## 3. 放入数据

把Windows下载得到的整个实验目录复制到开发电脑的 `data/` 下，保留manifest、备注、日志、压缩包及解压目录。

以这轮为例：

```text
data/joint_time_20260908_153328/
├── joint_time_20260908_153328_imu_rec_v1/metadata.yaml和*.db3
├── joint_time_20260908_153328_imu_rec_v2/metadata.yaml和*.db3
├── joint_time_20260908_153328_imu_rec_v3/metadata.yaml和*.db3
├── joint_time_20260908_153328_uwb_rec_v3/metadata.yaml和*.db3
└── manifest.json、实验备注.txt、采集状态.json、日志及原始压缩包
```

如果只有本脚本录制的可信tar.gz，先解压，已有同名目录会跳过：

```bash
RUN=data/joint_time_20260908_153328
for archive in "$RUN"/*.tar.gz; do
  [ -f "$archive" ] || continue
  [ -d "${archive%.tar.gz}" ] || tar -xzf "$archive" -C "$RUN"
done
```

## 4. 每轮只需运行这一条分析命令

先加载第2节的环境，再执行：

```bash
bash tools/analyze_joint_recording.sh data/joint_time_20260908_153328
```

以后只替换末尾实验目录名。通常需要几分钟，等出现“分析完成”。程序会逐个分析发现的IMU/UWB包，不限制录包盒必须是203。

输出保存在原实验目录及其子目录；重复运行会更新自动生成的报告、CSV和图片，不改原始db3/tar.gz。程序不会生成人工撰写的 `本轮联合测试结论.md`，也不会自动判断所有历史问题是否已修复。

## 5. 按这个顺序看结果

| 文件 | 重点看什么 |
|---|---|
| 实验目录/联合时间初查.md | 是否三路IMU、六方向UWB齐全；原始header是否同一时间范围；零值/回退/重复 |
| 实验目录/联合时间详细统计.csv | receive_hz频率；header_dt_max_ms最大间隔；receive_minus_header_median_s接收减消息时间 |
| 实验目录/联合时间轴对比.png | 时间差随录制是否改变；极端异常会压缩正常部分显示范围，需结合CSV |
| 各IMU目录/imu_analysis.txt | 时间异常帧；静止角速度均值/标准差；加速度模长；四元数突变帧及角度 |
| UWB目录/UWB测距分析.md | 六方向数量、均值、中位数、标准差、范围、时间回退、节点身份 |
| UWB目录/UWB测距数据.csv | 查异常原始序号、src/target、距离与时间，Excel可打开 |
| UWB目录/UWB测距曲线与时间戳.png | 静止测距是否分段变化、是否有尖峰 |

注意以下判读边界：

- 标准差是样本离线统计，未给实际距离时不能把它当成绝对测距精度。正有限距离也可能是448米这样的离群值。
- IMU约1000Hz、相邻header约1ms；UWB应按方向检查，当前通常约10Hz。超过100ms的UWB间隔不都代表严重跳变，要结合其正常周期。
- 三盒接收时间各自来自盒子系统时钟，不能直接当成共同真值。全静止时无法仅凭曲线重合证明采样同步。
- 四元数分析已排除q与−q的等价变号；静止时约180°变化值得核查。
- 三边几何需要相近时刻的距离；长期均值或分段中位数仅用于初查。近距离误差、离群值、非同时采样都需考虑。
- 原始首末时间范围正常并不意味着中途无异常，必须同时看回退和最大间隔。

反馈上交时，把具体异常序号、方向、时间和数值写明，并附对应CSV、报告及该原始包。不要仅发截图。

## 6. 可选：导出IMU逐条数据

仅想看频率、均值和突变时无需执行。需要在Excel中查原始四元数和陀螺时：

```bash
RUN=data/joint_time_20260908_153328
python3 tools/export_imu_bag_csv.py "$RUN"/*_imu_rec_v[123]
```

完整数据在各IMU目录的 `imu_full.csv.gz`，另有易读抽样CSV和时间异常表。默认每100条抽一条用于易读表：原包1000Hz时看起来约10Hz，不是原包只有10Hz。原始包和完整CSV保留全部帧。

## 7. 单独重跑某项

```bash
RUN=data/joint_time_20260908_153328
python3 tools/record_joint_time.py --analyze "$RUN"
python3 tools/analyze_joint_time.py "$RUN"
python3 tools/analyze_imu_bag.py "$RUN/${RUN##*/}_imu_rec_v2" | tee "$RUN/${RUN##*/}_imu_rec_v2/imu_analysis.txt"
python3 tools/export_uwb_bag_readable.py "$RUN/${RUN##*/}_uwb_rec_v3"
```

若UWB在202录制，将最后的 `uwb_rec_v3` 改为 `uwb_rec_v2`。

## 8. 常见报错

| 报错 | 处理 |
|---|---|
| No module named rosbag2_py | 在Ubuntu ROS环境运行，source /opt/ros/humble/setup.bash |
| No module named cooperative_interfaces | 执行第2节消息包构建并source对应install |
| 找不到metadata.yaml | 确认已解压、路径指向实验目录，原包是否完整 |
| 图中中文方框或找不到wqy-microhei.ttc | 安装fonts-wqy-microhei后重新运行，UWB绘图使用该字体文件 |
| 缺少一个盒子或某些UWB方向 | 检查manifest和原包；分析成功不代表采集齐全 |

该流程不需要在Windows额外配置SSH密钥；SSH仅用于采集，与离线分析无关。
