# 上交盒端传感器节点启动与检查（精简执行版）

本页只用于现场直接执行。异常原因和完整通过条件见 [详细判定版](21_上交盒端传感器节点启动与可用性检查.md)。

录包命名已统一：IMU为 `imu_v<车辆号>_<场景>_<时间>`，UWB为 `uwb_v<参与车辆>_obs_v<录包车辆>_<场景>_<时间>`；旧包不改名。

标签：🔷三盒各执行；🟠本轮参与测距盒执行；🟢共享DDS中任选一盒执行；🔴仅车1执行。

当前结论：车1—车2双向 `1↔2` UWB冒烟通过；车2仅GNSS因缺少 `/dev/ttyS6` 失败；车3空口仍出现旧ID `19101`，三车融合暂不启动。

## 1. 🔷 三盒：身份、进程和串口

| 车辆 | IP | `node_id` | `uwb_id` |
|---|---|---:|---:|
| 车1 | `192.168.1.201` | 1 | 18905 |
| 车2 | `192.168.1.202` | 2 | 22165 |
| 车3 | `192.168.1.203` | 3 | 62785（空口仍见旧ID 19101，待上交确认） |

~~~bash
hostname -I
grep -E 'node_id|uwb_id|uart_uwb|uart_gnss' /home/firefly/imu_ws/install/gnss_uwb/share/gnss_uwb/config/params.yaml
pgrep -af '^/home/firefly/imu_ws/install/navcore/lib/navcore/navcore( |$)'
pgrep -af '^/home/firefly/imu_ws/install/gnss_uwb/lib/gnss_uwb/gnss_uwb( |$)'
ls -l /dev/ttyS4 /dev/ttyS5 /dev/ttyS6 2>/dev/null
fuser -v /dev/ttyS4 /dev/ttyS5 /dev/ttyS6
GNSS_UWB_PID=$(pgrep -n -f '^/home/firefly/imu_ws/install/gnss_uwb/lib/gnss_uwb/gnss_uwb( |$)')
test -n "$GNSS_UWB_PID" && tr '\0' '\n' < "/proc/$GNSS_UWB_PID/environ" | grep -E '^(ROS_DOMAIN_ID|RMW_IMPLEMENTATION|ROS_LOCALHOST_ONLY)='
~~~

已有进程或串口占用时不重复启动。已有进程缺少 `ROS_DOMAIN_ID=107` 时，先确认启动人，再由原终端停止并重启。

## 2. 🟠 参与盒：启动UWB/GNSS

每个参与盒各开一个启动终端并保持运行：

~~~bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

ros2 launch gnss_uwb gnss_uwb_launch.py
~~~

继续条件：

- `/dev/ttyS5 460800` 成功打开；
- 连续出现状态 `A`、时间递增的 `Received UWB GNRMC`；
- 仅 `/dev/ttyS6` 失败时继续UWB测试，但记录“本车GNSS失败”；
- `/dev/ttyS5` 失败或节点退出时停止测试。

## 3. 🟢 单盒：观察UWB身份和测距

另开观察终端：

~~~bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

ros2 topic info --no-daemon --verbose /node/id
timeout --signal=INT 5s ros2 topic echo --no-daemon --field node_id /node/id cooperative_interfaces/msg/Identity
ros2 topic info --no-daemon --verbose /uwb/range
timeout --signal=INT 15s ros2 topic hz /uwb/range --window 200
timeout --signal=INT 3s ros2 topic echo --no-daemon --once --qos-profile sensor_data /uwb/range cooperative_interfaces/msg/UwbRange
~~~

双盒车1—车2至少出现一条：

~~~yaml
src_id: 1
target_id: 2
distance: 正数
~~~

或反向 `2→1`。逻辑编号正确、距离为正、时间戳非零即可通过冒烟检查。

启动初期短暂 `Tag ID unknown` 可以等待；随后识别并出现目标边即可。非参与盒的unknown另行记录，不影响当前目标边。

## 4. 🟢 单盒：录制固定距离UWB包

录制前修改 `PARTICIPANTS`、`OBSERVER_ID` 和 `TRUE_DISTANCE_M`。严格双盒精度测试应停止第3盒UWB；约1 m、3 m、5 m各录60秒。

~~~bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

PARTICIPANTS=1-2
OBSERVER_ID=1
TRUE_DISTANCE_M=1.30
mkdir -p /home/firefly/uwb_test
UWB_BAG="/home/firefly/uwb_test/uwb_v${PARTICIPANTS}_obs_v${OBSERVER_ID}_static_$(date +%Y%m%d_%H%M%S)"
timeout --foreground --signal=INT --kill-after=5s 60s ros2 bag record -o "$UWB_BAG" /uwb/range /node/id
if [ -f "$UWB_BAG/metadata.yaml" ]; then
  printf 'participants=%s\nobserver_vehicle=%s\ntrue_distance_m=%s\n' "$PARTICIPANTS" "$OBSERVER_ID" "$TRUE_DISTANCE_M" > "$UWB_BAG/test_info.txt"
  ros2 bag info "$UWB_BAG"
  UWB_ARCHIVE="${UWB_BAG}.tar.gz"
  tar -C "$(dirname "$UWB_BAG")" -czf "$UWB_ARCHIVE" "$(basename "$UWB_BAG")"
  ls -lh "$UWB_ARCHIVE" && sha256sum "$UWB_ARCHIVE"
  printf '下载文件：%s\n' "$UWB_ARCHIVE"
else
  printf '录包失败：未生成 metadata.yaml\n' >&2
fi
~~~

## 7. 🔷 三盒：录制10秒IMU包

命令自动根据有线IP写入车辆号：

~~~bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=1

(
case " $(hostname -I) " in
  *" 192.168.1.201 "*) VEHICLE_ID=1 ;;
  *" 192.168.1.202 "*) VEHICLE_ID=2 ;;
  *" 192.168.1.203 "*) VEHICLE_ID=3 ;;
  *) printf '无法根据IP识别车辆，未录包\n' >&2; exit 1 ;;
esac
mkdir -p /home/firefly/imu_test
IMU_BAG="/home/firefly/imu_test/imu_v${VEHICLE_ID}_static_$(date +%Y%m%d_%H%M%S)"
timeout --foreground --signal=INT --kill-after=5s 10s ros2 bag record -o "$IMU_BAG" /imu/raw
if [ ! -f "$IMU_BAG/metadata.yaml" ]; then
  printf '录包失败：未生成 metadata.yaml，请确认 /imu/raw 持续发布\n' >&2
  exit 1
fi
ros2 bag info "$IMU_BAG"
IMU_ARCHIVE="${IMU_BAG}.tar.gz"
tar -C "$(dirname "$IMU_BAG")" -czf "$IMU_ARCHIVE" "$(basename "$IMU_BAG")"
ls -lh "$IMU_ARCHIVE" && sha256sum "$IMU_ARCHIVE"
printf '下载文件：%s\n' "$IMU_ARCHIVE"
)
~~~

## 8. 三车最短顺序

1. 三盒核对身份、进程、串口和DDS环境。
2. 参与盒启动 `gnss_uwb`，通过UWB RMC。
3. 先录双盒已知距离，再录三盒已知三角形。
4. 三盒分别启动并验收 `navcore`。
5. 三盒分别启动浙大本地惯导，发布三个NodeState。
6. 只有三车身份正确、NodeState齐全、UWB测距图连通后，车1才启动融合。

## 9. 退出

回到自己启动进程的原终端按 `Ctrl+C`。不要使用宽泛的 `pkill`、`killall` 或停止来源不明的进程。
