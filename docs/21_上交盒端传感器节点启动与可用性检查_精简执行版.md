# 上交盒端传感器节点启动与检查（精简执行版）

本页只保留现场必须执行的步骤。默认使用 ROS 2 Humble、Domain 107、Fast DDS。

- UWB/GNSS：跨盒共享，使用 `ROS_LOCALHOST_ONLY=0`。
- IMU：只在本盒可见，使用 `ROS_LOCALHOST_ONLY=1`。
- 201雷达：Domain 0、Cyclone DDS、`ROS_LOCALHOST_ONLY=1`，不要套用IMU/UWB的环境。
- 201、202、203分别是 `192.168.1.201`、`192.168.1.202`、`192.168.1.203`。

详细解释见[22号详细版](22_上交盒端传感器节点启动与可用性检查.md)；联合录包和离线分析见[30号说明](30_record_joint_time_使用说明.md)；在线UWB定位现场命令就在本文件第7节，首次部署和排障见[41号详细版](41_201盒UWB最小在线相对定位部署步骤.md)。

本次要录 **GNSS+IMU 联合包** 时，实际顺序是：`1 → 2 → 3（IMU） → 4（201 GNSS）→ 4.4（联合录包）`。第4节前半部分的GNSS单独测试可以跳过；但联合录包前必须先完成第3节的IMU检查。

## 1. 三盒各检查一次

在每个盒子的SSH终端执行：

```bash
hostname -I
grep -E 'node_id|uwb_id|uart_uwb|uart_gnss' \
  /home/firefly/imu_ws/install/gnss_uwb/share/gnss_uwb/config/params.yaml
pgrep -af '^/home/firefly/imu_ws/install/navcore/lib/navcore/navcore( |$)'
pgrep -af '^/home/firefly/imu_ws/install/gnss_uwb/lib/gnss_uwb/gnss_uwb( |$)'
pgrep -af 'start_livox|livox_ros_driver2'
pgrep -afi 'camera|v4l2|gscam|mipi|image|vision|vins|orb_slam|realsense|usb_cam'
ls -l /dev/ttyS4 /dev/ttyS5 /dev/ttyS6 2>/dev/null
fuser -v /dev/ttyS4 /dev/ttyS5 /dev/ttyS6
```

确认：`ttyS4=IMU`、`ttyS5=UWB`、`ttyS6=GNSS`；已有进程和串口占用时不要重复启动。雷达进程存在不等于点云可用，相机查询无输出不等于已确认视觉。

如果进程已运行但当前终端看不到Topic，才执行[22号详细版的DDS排查](22_上交盒端传感器节点启动与可用性检查.md#找不到原启动终端时)。

## 2. 按需启动UWB/GNSS

下面是**当前室内三盒联测**的操作，在201、202、203各自的SSH终端执行，不是在Windows PowerShell执行。目标是三盒均使用`pps_source: 1`（UWB PPS）；只修改不符合的盒子，已经确认按1运行的盒子不用重启。切换前先结束正在进行的录包和定位测试，避免一包里混入切换前后的时间。

**① 查当前配置**

```bash
hostname -I
grep -n 'pps_source' /home/firefly/imu_ws/install/gnss_uwb/share/gnss_uwb/config/params.yaml
```

输出中的行号不固定，只看`pps_source: 0`或`pps_source: 1`。为0时执行②；已经为1则跳过②。没有该字段、出现多行配置或其他值时先核对文件，不自行添加。

**② 仅配置为0时：备份并改成1**

整块复制，包括最外层括号。命令只修改`pps_source`，不会改`node_id`、`uwb_id`或串口：

```bash
(
set -e
PPS_CONFIG=$(readlink -f /home/firefly/imu_ws/install/gnss_uwb/share/gnss_uwb/config/params.yaml)
test "$(grep -c '^[[:space:]]*pps_source:' "$PPS_CONFIG")" = 1 || { printf 'pps_source字段缺失或不唯一，未修改\n'; exit 1; }
grep -Eq '^[[:space:]]*pps_source:[[:space:]]*0[[:space:]]*(#.*)?$' "$PPS_CONFIG" || { printf '当前值不是0，未修改\n'; exit 1; }
PPS_BACKUP="${PPS_CONFIG}.bak.$(date +%Y%m%d_%H%M%S)"
cp -p "$PPS_CONFIG" "$PPS_BACKUP"
sed -i -E 's/^([[:space:]]*pps_source:)[[:space:]]*0([[:space:]]*(#.*)?)$/\1 1\2/' "$PPS_CONFIG"
grep -n '^[[:space:]]*pps_source:' "$PPS_CONFIG"
printf '备份文件：%s\n' "$PPS_BACKUP"
)
```

应输出`pps_source: 1`和备份文件完整路径；命令报错时不要继续。此时只是改了文件，旧进程还未加载新值。

**③ 停止旧进程，再启动本盒UWB/GNSS**

本次改过配置（或无法确认旧进程使用的配置）时，回到本盒运行`ros2 launch gnss_uwb gnss_uwb_launch.py`的终端按一次 **Ctrl+C**，等出现`process has finished cleanly`。找不到原终端时，按[22号详细版“找不到原启动终端时”](22_上交盒端传感器节点启动与可用性检查.md#找不到原启动终端时)核对并停止精确PID，不按名称批量杀进程。原本未运行的盒子直接检查：

```bash
pgrep -af '^/home/firefly/imu_ws/install/gnss_uwb/lib/gnss_uwb/gnss_uwb( |$)'
fuser -v /dev/ttyS5 /dev/ttyS6
```

两条均无占用输出再启动；仍有PID时先核对，不启动第二份驱动。下面整块在同一盒执行，保持该终端运行：

```bash
(
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0
if pgrep -af '^/home/firefly/imu_ws/install/gnss_uwb/lib/gnss_uwb/gnss_uwb( |$)'; then
  printf '本盒gnss_uwb仍在运行，未重复启动\n'
  exit 1
fi
ros2 launch gnss_uwb gnss_uwb_launch.py
)
```

**④ 核对启动结果，再录新包**

应看到`switch uwb pps source`、UWB串口打开，以及连续两条以上时间递增的`Received UWB GNRMC`。若仍显示`switch gnss pps source`，先核对启动进程的`--params-file`，不要继续录包。三盒都核对后，按第3节检查IMU，再按[30号说明](30_record_joint_time_使用说明.md)录新的联合包；不能只重启`navcore`代替重启`gnss_uwb`。

该参数选择的是PPS源，不等于已验证RMC秒号和IMU/UWB时间戳同步。GNSS若仅作真值，当前三盒仍保持UWB授时，GNSS单独记录；真实UTC与UWB模拟时间的映射另行验证。单盒户外GNSS授时测试不套用本节“三盒统一为1”的步骤。

### 2.1 检查UWB Topic

在任意一台参与盒的共享DDS终端执行：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

ros2 topic list --no-daemon -t | grep -Ei 'uwb|gnss|fix|node/id'
ros2 topic info --no-daemon --verbose /uwb/range
ros2 interface show cooperative_interfaces/msg/UwbRange
timeout --signal=INT 5s ros2 topic echo --no-daemon --once \
  --qos-profile sensor_data /uwb/range cooperative_interfaces/msg/UwbRange
```

三车时应能观察到无向边`1-2`、`1-3`、`2-3`；正反方向最多六条有向流。

## 3. 按需启动和检查IMU（联合录包前必须完成）

只在目标盒没有`navcore`进程时执行；三盒各开一个启动终端：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=1
ros2 launch navcore navcore_launch.py
```

同一盒另开观察终端：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=1

ros2 topic info --no-daemon --verbose /imu/raw
timeout --signal=INT 10s ros2 topic hz /imu/raw --window 100
timeout --signal=INT 3s ros2 topic echo --no-daemon --once \
  --qos-profile sensor_data /imu/raw sensor_msgs/msg/Imu
```

应看到一个发布者、约1000 Hz、非零递增时间戳和有限的角速度/加速度。没有通过这一步，不要执行第4.4节联合录包。

## 4. 201单盒户外GNSS测试（可独立执行）

201已被单独带到室外时，只做本节即可。保持GNSS天线无遮挡、盒子静止；不要求202/203在线，也不要求出现UWB测距或运行浙大融合节点。GNSS和UWB由同一个`gnss_uwb`节点管理，因此该进程仍须运行；未运行时按第2节启动。

### 4.1 检查定位是否有效

在201执行（整块复制，保留括号；检查失败只退出子Shell，不断开SSH）：

```bash
hostname -I
PID=$(pgrep -n -f '^/home/firefly/imu_ws/install/gnss_uwb/lib/gnss_uwb/gnss_uwb( |$)')
printf 'GNSS_UWB_PID=%s\n' "${PID:-未运行}"
test -n "$PID" && ps -o pid,lstart,args -p "$PID"
fuser -v /dev/ttyS5 /dev/ttyS6

source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

(
GNSS_TOPIC=/gnss/fix
GNSS_TYPE=$(ros2 topic type --no-daemon "$GNSS_TOPIC")
printf 'GNSS_TYPE=%s\n' "${GNSS_TYPE:-未发现}"
test -n "$GNSS_TYPE" || { printf '未发现GNSS话题：先确认驱动运行，再检查DDS环境\n'; exit 1; }
ros2 topic info --no-daemon --verbose "$GNSS_TOPIC"
timeout --signal=INT 20s ros2 topic hz "$GNSS_TOPIC" \
  --filter 'm.node_id == 1' --window 20
date -u '+HOST_UTC=%Y-%m-%dT%H:%M:%S.%N%z'
timeout --signal=INT 5s ros2 topic echo --no-daemon --once \
  --filter 'm.node_id == 1' "$GNSS_TOPIC" "$GNSS_TYPE"
)
```

通过条件：能持续收到`node_id=1`；`status`不再持续为`-1`；经纬高为有限的真实数值；`header.stamp`非零并持续递增。`status=0`只能说明已有定位，不能据此认定RTK Fixed；解类型、差分状态和预期频率需要上交确认。

若显示`GNSS_UWB_PID=未运行`，先按第2节启动；若进程在但无Topic，查DDS环境。有消息却持续`status=-1`或经纬度全0，再检查天线和室外搜星情况并把输出发给上交。201离其他盒很远时没有UWB测距消息不作为本项失败依据。

### 4.2 录制3分钟静止数据

确认已有有效定位后，在201执行：

```bash
(
mkdir -p /home/firefly/gnss_test
BAG=/home/firefly/gnss_test/gnss_v1_outdoor_static_$(date +%Y%m%d_%H%M%S)
timeout --foreground --signal=INT --kill-after=5s 180s \
  ros2 bag record -o "$BAG" /gnss/fix /node/id
test -f "$BAG/metadata.yaml" || { printf '录包未正常落盘，请检查上方输出\n'; exit 1; }
ros2 bag info "$BAG"
ARCHIVE="${BAG}.tar.gz"
tar -C "$(dirname "$BAG")" -czf "$ARCHIVE" "$(basename "$BAG")"
ls -lh "$ARCHIVE"
sha256sum "$ARCHIVE"
printf '下载文件：%s\n' "$ARCHIVE"
)
```

把压缩包收回后检查：有效定位比例、单车频率、时间戳单调性、静止经纬度散布和协方差。没有已知坐标或独立RTK真值时，只能评价GNSS是否可用和是否稳定，不能给出绝对定位精度。

### 4.3 GNSS只作真值，不参与相对定位

本轮只想验证GNSS时，不启动`202/203`，不启动浙大融合节点，也不运行GNSS距离后备节点；只保存201的`/gnss/fix`包。以后恢复三车相对定位时，继续使用41号的`uwb_only.launch.py`，GNSS包作为独立评价数据，不能回灌到同一个融合算法。若以后显式使用GNSS后备，才单独打开`use_gnss_range_fallback:=true`，否则保持默认关闭。

### 4.4 同时录制201的GNSS和IMU（必须先完成第3节）

需要同时检查两者时间戳时，把`tools/record_201_gnss_imu.py`上传到201，例如放在`/home/firefly/gnss_test/`，然后在201执行：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
python3 /home/firefly/gnss_test/record_201_gnss_imu.py --duration 180
```

脚本会分别用GNSS的`ROS_LOCALHOST_ONLY=0`和IMU的`ROS_LOCALHOST_ONLY=1`检查Topic，同时启动两路录包、等待3秒后计时，最后自动压缩。它不会启动、停止或修改上交传感器节点。压缩包在`/home/firefly/gnss_test/gnss_imu_v1_static_<时间>.tar.gz`。

## 5. 三盒联合录包

三盒驱动都确认正常后，只在电脑上执行：

```bash

```

Windows PowerShell：

```powershell
python .\tools\record_joint_time.py --duration 180
```

结果在`data/joint_time_<时间>/`，脚本自动回收并压缩三路IMU和一路共享UWB。录制期间保持静止，或只移动指定的一个盒子并记录动作时间。离线分析按31号文档执行。

## 6. 雷达和相机

### 6.1 雷达

雷达与`navcore`可以独立运行；`/livox/imu`是雷达内置IMU，不是`/imu/raw`。第1节查到Livox驱动已运行时，不再启动第二份。

**① 在201另开一个雷达观察终端，设置环境并查话题。** 后面的②也在这个终端执行；新开终端必须重新执行①。

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/livox_ws/install/setup.bash
export ROS_DOMAIN_ID=0
export ROS_LOCALHOST_ONLY=1
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp

ros2 node list --no-daemon
ros2 topic list --no-daemon -t | grep -E '^/livox/'
```

当前应看到`/livox_lidar_publisher`、`/livox/lidar [sensor_msgs/msg/PointCloud2]`和`/livox/imu [sensor_msgs/msg/Imu]`。若上交改了话题名，以下命令相应替换。

**② 各接收一条实际消息。** 点云隐藏数组，避免大量数据刷屏。

```bash
timeout --signal=INT 10s ros2 topic echo --no-daemon --once \
  --qos-profile sensor_data --no-arr \
  /livox/lidar sensor_msgs/msg/PointCloud2
timeout --signal=INT 5s ros2 topic echo --no-daemon --once \
  --qos-profile sensor_data --field header \
  /livox/imu sensor_msgs/msg/Imu
```

- 点云有`header`、`width`、`height`等输出，且`width × height > 0`：收到非空点云消息，再按[22号第4.4节](22_上交盒端传感器节点启动与可用性检查.md)测频率和录短包；这还不代表点云质量或时间同步已通过。
- 话题存在但等待结束仍无消息：记录“测试窗口内未收到数据”，先不录正式雷达包；按22号第4.3节查看启动日志并核对设备连接，不反复运行同样的`hz/echo`。
- `Unknown topic`：先检查本终端环境和驱动进程；不能据此断定雷达损坏。

**本轮201实测：两路话题各有1个RELIABLE发布者，但频率检查和单帧订阅均未收到消息，原因待查。** `lo ... disabling multicast`本身不足以判定故障。本机Humble的`topic hz`不支持`--qos-profile`，该参数只用于上面的`echo`。查完雷达如要在同一终端操作IMU/UWB，须重新执行对应节的环境设置。

### 6.2 相机

目前只做只读检查：

```bash
pgrep -afi 'camera|v4l2|gscam|mipi|image|vision|vins|orb_slam|realsense|usb_cam'
ros2 topic list --no-daemon -t | grep -Ei 'camera|image|rgb|camera_info|vision'
```

## 7. 201在线UWB协同定位

三盒UWB边都正常、且算法已经按[41号部署说明](41_201盒UWB最小在线相对定位部署步骤.md)安装到201后，先在201的融合终端执行：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
source /home/firefly/zju_coop_ws/install/ros2-box/setup.bash
export ROS_DOMAIN_ID=107 RMW_IMPLEMENTATION=rmw_fastrtps_cpp ROS_LOCALHOST_ONLY=0

ros2 launch zju_coop_bringup uwb_only.launch.py \
  reference_node_id:=1 \
  uwb_topic:=/uwb/range \
  poses_topic:=/cooperative_localization/poses_2d
```

保持融合终端运行，另开201观察终端，加载同样的环境后检查：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
source /home/firefly/zju_coop_ws/install/ros2-box/setup.bash
export ROS_DOMAIN_ID=107 RMW_IMPLEMENTATION=rmw_fastrtps_cpp ROS_LOCALHOST_ONLY=0

ros2 node list | grep zju
ros2 topic info --no-daemon --verbose /cooperative_localization/poses_2d
timeout --signal=INT 15s ros2 topic hz /cooperative_localization/poses_2d
timeout --signal=INT 15s ros2 topic echo --no-daemon --once \
  /cooperative_localization/poses_2d \
  cooperative_localization_msgs/msg/CooperativePose2DArray
```

通过现场最小检查的现象：输出频率约10 Hz；`frame_id`为`coop_ref_1_relative`；`reference_node_id: 1`；`vehicles`包含1、2、3；三车`position_valid: true`；纯UWB时`yaw_valid: false`是正常的。车1应为`(0,0)`，车2和车3应有有限的相对坐标。

确认静止输出后，只移动一辆盒子约0.5～1米，另外两辆保持不动，观察被移动盒子的相对坐标是否变化、停止后是否稳定。没有真值时，这一步只判断链路和相对变化，不能给出绝对定位精度。

如需保存输入和输出，在另一个201终端录60秒：

```bash
mkdir -p /home/firefly/uwb_test
ONLINE_BAG=/home/firefly/uwb_test/zju_online_v1_$(TZ=Asia/Shanghai date +%Y%m%d_%H%M%S)
timeout --foreground --signal=INT --kill-after=5s 60s \
  ros2 bag record -o "$ONLINE_BAG" \
  /uwb/range /cooperative_localization/poses_2d
test -f "$ONLINE_BAG/metadata.yaml" && \
  tar -C "$(dirname "$ONLINE_BAG")" -czf "${ONLINE_BAG}.tar.gz" \
  "$(basename "$ONLINE_BAG")"
printf '下载文件：%s.tar.gz\n' "$ONLINE_BAG"
```

录包后把压缩包收回电脑，按[41号详细部署版的在线包分析](41_201盒UWB最小在线相对定位部署步骤.md#在线结果包的离线分析)分析。测试结束只在自己启动融合节点的终端按`Ctrl+C`；不要停止上交的`gnss_uwb`、`navcore`或雷达进程。

## 8. 停止

只在自己启动节点的终端按`Ctrl+C`。不要使用`pkill`、`killall`或停止来源不明的进程。
