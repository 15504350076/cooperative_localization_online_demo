## 3. 🟢 单盒：观察UWB身份和测距

另开观察终端：

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

ros2 topic info --no-daemon --verbose /node/id
timeout --signal=INT 5s ros2 topic echo --no-daemon --field node_id /node/id cooperative_interfaces/msg/Identity
EDGE_COUNTS=$(PYTHONUNBUFFERED=1 timeout --signal=INT 10s ros2 topic echo --no-daemon --qos-profile sensor_data /uwb/range cooperative_interfaces/msg/UwbRange 2>/dev/null | awk '/^[[:space:]]*src_id:/ {src=$2} /^[[:space:]]*target_id:/ && src != "" {dst=$2; if (src < dst) print src "-" dst; else print dst "-" src; src=""}' | sort | uniq -c)
if [ -n "$EDGE_COUNTS" ]; then
  printf '10秒内实际无向测距边及消息数：\n%s\n' "$EDGE_COUNTS"
else
  printf 'UWB测距冒烟失败：10秒内没有测距边\n' >&2
fi
```

双车1—2应输出 `1-2`；三车应同时输出 `1-2`、`1-3`、`2-3`。`/node/id` 中出现 `1/2/3` 只代表三套ROS身份在线，不代表三条UWB边已经出数。

启动初期短暂 `Tag ID unknown` 可以等待；随后识别并出现目标边即可。非参与盒的unknown另行记录，不影响当前目标边。

## 4. 🟢 单盒：录制固定距离UWB包

录制前修改 `EXPECTED_EDGES`、`SCENE` 和 `TRUE_DISTANCE_M`。双车1—2用 `EXPECTED_EDGES="1-2"`；三车用 `EXPECTED_EDGES="1-2 1-3 2-3"`。缺少任一目标边时不开始60秒录包。

```bash
source /opt/ros/humble/setup.bash
source /home/firefly/imu_ws/install/setup.bash
export ROS_DOMAIN_ID=107
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0

(
case " $(hostname -I) " in
  *" 192.168.1.201 "*) RECORDER_ID=1 ;;
  *" 192.168.1.202 "*) RECORDER_ID=2 ;;
  *" 192.168.1.203 "*) RECORDER_ID=3 ;;
  *) printf '无法识别录包车辆\n' >&2; exit 1 ;;
esac
UWB_TYPE=$(ros2 topic type --no-daemon /uwb/range)
test "$UWB_TYPE" = cooperative_interfaces/msg/UwbRange || { printf 'UWB Topic不存在或类型错误\n' >&2; exit 1; }
EXPECTED_EDGES="1-2 1-3 2-3"
SCENE=static_unknown
TRUE_DISTANCE_M=unknown
ONLINE_IDS=$(PYTHONUNBUFFERED=1 timeout --signal=INT 5s ros2 topic echo --no-daemon --field node_id /node/id cooperative_interfaces/msg/Identity 2>/dev/null | awk '/^[[:space:]]*[0-9]+[[:space:]]*$/ {gsub(/[[:space:]]/, ""); print}' | sort -nu | paste -sd-)
test -n "$ONLINE_IDS" || { printf '未收到 /node/id\n' >&2; exit 1; }
OBSERVED_EDGES=$(PYTHONUNBUFFERED=1 timeout --signal=INT 10s ros2 topic echo --no-daemon --qos-profile sensor_data /uwb/range "$UWB_TYPE" 2>/dev/null | awk '/^[[:space:]]*src_id:/ {src=$2} /^[[:space:]]*target_id:/ && src != "" {dst=$2; if (src < dst) print src "-" dst; else print dst "-" src; src=""}' | sort -u | paste -sd' ')
test -n "$OBSERVED_EDGES" || { printf '10秒内没有实际测距，未录包\n' >&2; exit 1; }
MISSING_EDGES=
for EDGE in $EXPECTED_EDGES; do
  case " $OBSERVED_EDGES " in
    *" $EDGE "*) ;;
    *) MISSING_EDGES="${MISSING_EDGES}${MISSING_EDGES:+ }${EDGE}" ;;
  esac
done
printf 'ROS在线车辆：%s\n实际测距边：%s\n录包车辆：%s\n' "$ONLINE_IDS" "$OBSERVED_EDGES" "$RECORDER_ID"
test -z "$MISSING_EDGES" || { printf '缺少目标边：%s，未录包\n' "$MISSING_EDGES" >&2; exit 1; }
EDGE_TAG=$(printf '%s' "$OBSERVED_EDGES" | tr ' ' '_')
mkdir -p /home/firefly/uwb_test
UWB_BAG="/home/firefly/uwb_test/uwb_online_v${ONLINE_IDS}_edges_${EDGE_TAG}_rec_v${RECORDER_ID}_${SCENE}_$(date +%Y%m%d_%H%M%S)"
timeout --foreground --signal=INT --kill-after=5s 60s ros2 bag record -o "$UWB_BAG" /uwb/range /node/id
if [ -f "$UWB_BAG/metadata.yaml" ]; then
  BAG_INFO=$(ros2 bag info "$UWB_BAG")
  printf '%s\n' "$BAG_INFO"
  RANGE_COUNT=$(printf '%s\n' "$BAG_INFO" | sed -n 's/.*Topic: \/uwb\/range .* Count: \([0-9][0-9]*\).*/\1/p')
  test -n "$RANGE_COUNT" || RANGE_COUNT=0
  printf 'online_node_ids=%s\nexpected_edges=%s\nprecheck_observed_edges=%s\nrecorder_vehicle=%s\nscene=%s\ntrue_distance_m=%s\nrange_message_count=%s\n' "$ONLINE_IDS" "$EXPECTED_EDGES" "$OBSERVED_EDGES" "$RECORDER_ID" "$SCENE" "$TRUE_DISTANCE_M" "$RANGE_COUNT" > "$UWB_BAG/test_info.txt"
  UWB_ARCHIVE="${UWB_BAG}.tar.gz"
  tar -C "$(dirname "$UWB_BAG")" -czf "$UWB_ARCHIVE" "$(basename "$UWB_BAG")"
  ls -lh "$UWB_ARCHIVE" && sha256sum "$UWB_ARCHIVE"
  printf '下载文件：%s\n' "$UWB_ARCHIVE"
  test "$RANGE_COUNT" -gt 0 || printf '无效：/uwb/range 为0条\n' >&2
else
  printf '录包失败：未生成 metadata.yaml\n' >&2
fi
)
```

## 7.1 🔷 三盒IMU＋单盒共享UWB：联合时间实验

本实验检查三盒 IMU 与 UWB 的时间域和明显时间错位。先按前面的步骤确认三条UWB边持续出数、每盒只有一份IMU驱动，且UWB RMC有效递增。保持各盒的 `gnss_uwb` 和 `navcore` 启动终端运行。

| 在哪里 | 使用哪个终端 | 做什么 |
|---|---|---|
| **201、202、203三盒各执行一次** | 各盒新增一个IMU录包终端 | 本机 `ROS_LOCALHOST_ONLY=1`，分别录本盒IMU |
| **任选一盒，只执行一次** | 再新增一个UWB录包终端 | `ROS_LOCALHOST_ONLY=0`，录三盒共享UWB和身份 |

一共得到 **3个IMU包＋1个UWB包**。不需要四个终端同时按回车；全部显示 `Subscribed to topic` 和 `Recording` 后再开始动作。不要用各盒系统时间定时启动，盒子系统日期可能不一致。


### 🟢【电脑执行一次】一键联合录包（推荐，替代下面A～D手动录包）

Windows现场操作、SSH免密配置、全静止实验与故障处理见 [record_joint_time.py独立使用说明](record_joint_time_使用说明.md)。

前提：三盒已按前文启动 `gnss_uwb` 和 `navcore`、确认RMC和测距出数。此脚本只管理本轮录包；驱动无需再开新的启动终端。电脑与三盒网络互通，安装 `ssh/scp`、Python 3.9或更高版本（上交电脑3.9.7无需升级）。

Windows上交电脑：把脚本放到 `C:\joint_test\tools\record_joint_time.py`，在PowerShell执行 `cd C:\joint_test` 和 `python tools\record_joint_time.py`。先用 `python --version` 确认解释器；若使用Python启动器则执行 `py -3.9 tools\record_joint_time.py`。录包控制只用Python标准库，不需要安装ROS；分析在已配置ROS的开发电脑执行。下方 `ssh-copy-id` 为Linux配置方式，Windows需另行配置OpenSSH公钥登录。

首次使用，在电脑配置SSH密钥登录（已有密钥则跳过生成；连接时核对主机指纹）：

```bash
test -f "$HOME/.ssh/id_ed25519.pub" || ssh-keygen -t ed25519
ssh-copy-id firefly@192.168.1.201
ssh-copy-id firefly@192.168.1.202
ssh-copy-id firefly@192.168.1.203
```

每轮只在**电脑一个终端**运行：

```bash
cd /home/pdq/Code/cooperative_localization_online_demo/cooperative_localization_online_demo
python3 tools/record_joint_time.py
```

脚本检查SSH及驱动进程，启动三路本机IMU和203共享UWB录包。等待全部订阅就绪后，终端依次提示静止、移动盒1、盒2、盒3。平移时保持姿态和高度基本不变，并让对应距离明显变化。跟随提示完成90秒动作；每路默认录180秒，随后自动压缩、下载和解压到电脑 `data/joint_time_<电脑时间>/`。不要提前关闭电脑终端。四路无需同一时刻启动，动作必须在就绪提示后开始。

失败看该目录的 `.log` 和 `采集状态.json`；未全部就绪则本轮不做动作。录包有时间上限，远端原包保留在 `/home/firefly/time_test/`，下载失败可手动取回。脚本不自动认定“三边齐全”或“同步通过”，回收后仍需分析实际数据。补写 `实验备注.txt` 中的摆放与异常。

增加盒子或更换UWB录包盒，显式指定即可；动作按传入盒号依次提示，时长随盒子数增加：

```bash

```

电脑加载现有ROS消息环境，生成时间初查报告（将目录名换成本次实际目录）：

```bash

python3 tools/record_joint_time.py --analyze data/joint_time_实际编号
```

结果为 `联合时间初查.md` 与 `时间戳统计.json`：按每盒IMU、每条有向UWB列出消息时间范围、零值、重复、回退及共同区间。分析环境需有 `cooperative_interfaces`；缺包不会影响已完成的采集，可加载正确工作空间后重跑分析。

**共同区间存在不代表时钟已同步。** 本轮报告用于识别明显时间域问题；动作对应及同步误差需进一步离线检查或上交PPS诊断。自动启动录包不会校准盒子时钟。

### 🔷【三盒联合操作】C. 全部录包后按一个秒表做动作

把盒子摆成非退化三角形，动作时保持高度和姿态基本不变。由一人用手机秒表统一口令，时间从四路录制就绪后开始计，不是从任何包的首帧开始计。

| 秒表时间 | 动作 |
|---|---|
| 0～15秒 | 三盒静止 |
| 15～25秒 | 只平移盒1约0.5～1米，再停住 |
| 25～35秒 | 三盒静止 |
| 35～45秒 | 只平移盒2约0.5～1米，再停住 |
| 45～55秒 | 三盒静止 |
| 55～65秒 | 只平移盒3约0.5～1米，再停住 |
| 65～90秒 | 三盒静止 |

平移方向应让涉及该盒的距离有明显变化，避免只绕另一盒做等距离运动。**平移主要看加速度，不能期待陀螺一定有明显变化。**

90秒后，依次在四个**录包终端**按 `Ctrl+C`，等待落盘和压缩完成。把实际动作、秒表大致时刻、三盒是否重启及异常情况写成随包备注；本轮不要求启动浙大NodeState或融合程序。

### 🟢【各包所在盒执行】D. 下载和判定

从各盒 `/home/firefly/time_test/` 下载同一 `RUN_ID` 的4个压缩包及实验备注。检查三个IMU包消息数均非零、UWB包含三条测距边，并且四包都覆盖完整动作过程。若未自动压缩，在对应盒上设置实际目录后执行：

```bash
BAG=/home/firefly/time_test/填实际包目录名
ros2 bag info "$BAG"
test -f "$BAG/metadata.yaml" &&
tar -C "$(dirname "$BAG")" -czf "${BAG}.tar.gz" "$(basename "$BAG")"
```

离线检查先比较**原始消息时间戳**的范围和重叠区间，再检查回退、重复、时间尺度及各盒运动与相应UWB变化的对应关系。不能把四个包各自首帧都减到零后，便认为实现了同步。

本实验用于发现时间域不同、秒级错位及明显漂移。IMU加速度和UWB距离是不同物理量，运动起点也会受测距频率、阈值和传输延迟影响，不能直接把两条曲线的峰值差当成时钟误差。**约10Hz的UWB也不意味着本实验能保证100ms或更高的同步精度。** 毫秒级同步需上交提供共同事件时间标记或PPS捕获与消息时间映射的诊断证据；接收时间差均值接近也不能单独证明同步。


## 8. 三车最短顺序

1. 三盒核对身份、进程、串口和DDS环境。
2. 参与盒启动 `gnss_uwb`，通过UWB RMC。
3. 先录双盒已知距离，再录三盒已知三角形。
4. 三盒分别启动并验收 `navcore`，按7.1完成联合时间实验，核对三车IMU/UWB时间域及事件对应。
5. 三盒分别启动浙大本地惯导，发布三个NodeState。
6. 只有三车身份正确、NodeState齐全、UWB测距图连通后，车1才启动融合。
